Learning Checkpoint
What happens when you open a file with mode 'w' and the file already exists?
The file is overwritten
The existing content is completely erased and replaced with new content.
Correct! The 'w' mode stands for 'write' and it completely overwrites any existing file. Think of it as a fresh start - all previous content is deleted. This is why it's called the "DANGER ZONE" in medical applications!
New content is added to the end
The new content is appended after the existing content.
Not quite. You're thinking of 'a' (append) mode. The 'w' mode completely overwrites the file, erasing all existing content. To add to existing content, use 'a' mode instead.
An error is raised
Python prevents you from overwriting existing files.
That's not correct. Python doesn't prevent overwriting by default. The 'w' mode will happily overwrite existing files without warning. Some other modes like 'x' will raise an error if the file exists.
A backup is created automatically
Python saves the old content before writing new content.
Unfortunately, no. Python doesn't create automatic backups. The 'w' mode immediately overwrites the file. Always create manual backups of critical medical data before using write mode!

🔬 Chapter 6: Appending to Medical Records

🔬 Chapter 7: Processing Large Medical Data Files

Big Data, Bigger Impact!

🧬 The Challenge: Genomic Data

Imagine trying to load a 200GB genome file into memory... 💥 Computer says NO!

Instead, we process files line by line - like eating an elephant one bite at a time (please don't eat elephants 🐘).

💪 Power Technique: Line-by-Line Processing

# Analyzing a massive genomic dataset print("🧬 Genome Analyzer 3000") print("="*40) mutation_count = 0 gene_count = 0 # Simulating genome analysis (would be a real file in practice) genome_data = [ ">GENE001 BRCA1\n", "ATCGATCGATCG\n", ">GENE002 TP53 MUTATION\n", "ATCGMUTATIONATCG\n", ">GENE003 EGFR\n" ] # Process without loading entire file for line in genome_data: # In real life: with open('genome.txt') as file: if line.startswith('>'): gene_count += 1 if 'MUTATION' in line: mutation_count += 1 print(f"⚠️ Mutation detected in: {line.strip()}") print(f"\n📊 Analysis Complete:") print(f" Total Genes: {gene_count}") print(f" Mutations Found: {mutation_count}")

Manually split the file into smaller files first, then process each.

This adds unnecessary overhead. For sequential processing of genomic data, direct file iteration is simpler and often faster. Databases are better for random access patterns, not sequential reads.

🛡️ Error Handling for Medical Data

Learning Checkpoint
What will this robust file handling function do if the patient file doesn't exist?
def read_patient_data(filename): try: with open(filename, 'r') as file: return file.read() except FileNotFoundError: print(f"⚠️ Patient file '{filename}' not found!") print("Creating new patient record...") with open(filename, 'w') as file: file.write("New Patient Record\n") return "New Patient Record\n" except PermissionError: print("🔒 Access denied! Check your permissions.") return None # Test the robust function data = read_patient_data('patient_999.txt')
Create a new file and return default content
It will create 'patient_999.txt' with "New Patient Record\n" and return that text.
Excellent! This is a robust error handling pattern. When the file doesn't exist, instead of crashing, the function creates a new patient record file with default content. This ensures the system keeps working even with missing files - crucial for medical applications!
Crash with FileNotFoundError
The program will stop with an error message.
Not with this code! The try-except block catches the FileNotFoundError. Instead of crashing, it handles the error gracefully by creating a new file. This is why error handling is essential in medical software.
Return None silently
It will return None without any messages.
That's not right. The function only returns None for PermissionError. For FileNotFoundError, it prints messages, creates a new file, and returns the default content "New Patient Record\n".
Print warning only
It will print a warning but not create any file.
Look more carefully at the except block. It does print warnings, but it also creates a new file with default content and returns that content. This is proactive error handling - fixing the problem, not just reporting it.
