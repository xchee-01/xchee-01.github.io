Logical Operations and Medical Decision Making in R

This module focuses on R's logical capabilities for medical decision-making. You'll learn comparison operators, logical values, and how to combine conditions for clinical assessments.

🎯 Learning Objectives:

  • Use logical values (TRUE/FALSE) for medical decisions
  • Apply comparison operators for diagnostic criteria
  • Combine conditions for complex medical logic
  • Build clinical decision support tools

6.2.6. Logical Values in Medicine

Medicine involves binary decisions: Is the test positive? Should we treat? R uses TRUE/FALSE for these:

# Simple medical checks fever_threshold <- 100.4 patient_temp <- 101.5 has_fever <- patient_temp > fever_threshold # TRUE
Copied!
Learning Checkpoint
In R, what value is assigned to has_fever when patient_temp is 101.5 and fever_threshold is 100.4?
"TRUE" (as text)
A text string containing the word TRUE.
Not quite. R uses logical values, not text strings, for boolean operations.
TRUE (logical value)
The logical value TRUE.
Correct! R uses logical values TRUE and FALSE (not quoted text) for boolean operations. When 101.5 > 100.4, the result is the logical value TRUE.
1
The numeric value 1.
While TRUE can be coerced to 1 in arithmetic operations, the comparison operator returns a logical value, not a number.
"Yes"
A text string saying "Yes".
R doesn't use "Yes"/"No" for logical operations. It uses TRUE and FALSE.

6.2.7. Comparison Operators

Your Diagnostic Toolkit:

glucose <- 130 is_high <- glucose > 126 # TRUE (diabetic range) is_low <- glucose < 70 # FALSE is_diabetic <- glucose >= 126 # TRUE is_normal <- glucose <= 99 # FALSE is_exactly <- glucose == 130 # TRUE is_different <- glucose != 130 # FALSE
Copied!
Learning Checkpoint
Which operator should you use to check if a patient's glucose level is EXACTLY 126 mg/dL?
glucose = 126
Single equals sign.
Single = is for assignment, not comparison. This would change the value of glucose to 126.
glucose == 126
Double equals sign.
Correct! Use == (double equals) for exact comparison. Single = is for assignment, not comparison!
glucose >= 126
Greater than or equal to.
This checks if glucose is 126 or higher, not exactly 126. It would return TRUE for 127, 128, etc.
glucose != 126
Not equal to.
This checks if glucose is NOT equal to 126. It's the opposite of what we want.

⚠️ Common Mistake: Use == for comparison, not =!

Learning Checkpoint
Given glucose <- 130, which of these expressions returns FALSE?
glucose > 126
Is glucose greater than 126?
This returns TRUE because 130 > 126.
glucose >= 130
Is glucose greater than or equal to 130?
This returns TRUE because 130 >= 130 (equal counts).
glucose != 130
Is glucose not equal to 130?
Correct! glucose != 130 returns FALSE because glucose IS equal to 130. The != operator checks for inequality.
glucose == 130
Is glucose equal to 130?
This returns TRUE because glucose equals 130.

6.2.8. Complex Medical Logic

Combining Conditions with AND (&):

# Blood pressure check (both must be normal) systolic <- 118 diastolic <- 78 bp_normal <- systolic < 120 & diastolic < 80 # TRUE
Copied!
Learning Checkpoint
A patient has systolic BP of 125 and diastolic BP of 75. What is the result of systolic < 120 & diastolic < 80?
TRUE
Both conditions are met.
Not quite. With AND, both conditions must be TRUE. Check the systolic value again.
FALSE
At least one condition is not met.
Correct! With AND (&), BOTH conditions must be TRUE. Since 125 < 120 is FALSE, the entire expression is FALSE even though 75 < 80 is TRUE.
NA
Missing value.
Logical operations with numeric values don't produce NA unless the inputs are NA.
Error
The code produces an error.
This is valid R syntax and will execute without errors.

Using OR (|) Logic:

# COVID screening (any symptom triggers test) has_fever <- TRUE has_cough <- FALSE loss_of_taste <- TRUE needs_test <- has_fever | has_cough | loss_of_taste # TRUE
Copied!
Learning Checkpoint
In COVID screening, if has_fever <- FALSE, has_cough <- FALSE, and loss_of_taste <- TRUE, what is the value of has_fever | has_cough | loss_of_taste?
FALSE
All conditions must be FALSE.
With OR, only one condition needs to be TRUE. Since loss_of_taste is TRUE, the result is TRUE.
TRUE
At least one condition is TRUE.
Correct! With OR (|), only ONE condition needs to be TRUE. Since loss_of_taste is TRUE, the entire expression is TRUE.
NA
Missing value.
Logical operations with TRUE/FALSE values don't produce NA.
"TRUE"
Text string "TRUE".
Logical operations return logical values (TRUE/FALSE), not text strings.

Clinical Trial Eligibility:

age <- 45 has_condition <- TRUE no_pregnancy <- TRUE eligible <- age >= 18 & age <= 65 & has_condition & no_pregnancy

6.2.9. Building Risk Calculators

In precision medicine, we often need to calculate risk scores based on multiple factors. Let's build a cardiovascular risk calculator that combines age, cholesterol, and smoking status to determine a patient's risk level.

Lab Exercise 3: Cardiovascular Risk Score Calculator

As a cardiovascular specialist, you need to create a risk assessment tool that calculates a patient's cardiovascular risk score based on their age, cholesterol level, and smoking status. The calculator should assign weighted scores to each factor and provide appropriate risk recommendations.

# Lab scenario: Complete the cardiovascular risk calculator # Fix the missing parts indicated by ... # Patient information patient_age <- 55 cholesterol_level <- 220 smoking_status <- "yes" # Calculate risk factors age_factor <- patient_age * ... # Age contributes 0.05 points per year cholesterol_factor <- ... > 200 # High cholesterol (TRUE if above 200) smoking_factor <- smoking_status == ... # Check if patient smokes # Calculate total risk score # Note: TRUE = 1, FALSE = 0 in arithmetic total_risk_score <- ... + (cholesterol_factor * ...) + (smoking_factor * ...) # Interpret results if (total_risk_score > ...) { print("HIGH RISK: Immediate intervention needed") } else if (total_risk_score > ...) { print("MODERATE RISK: Monitor closely") } else { print("LOW RISK: Continue preventive care") }

# Complete solution # Patient information patient_age <- 55 cholesterol_level <- 220 smoking_status <- "yes" # Calculate risk factors age_factor <- patient_age * 0.05 # Age contributes 0.05 points per year cholesterol_factor <- cholesterol_level > 200 # High cholesterol (TRUE if above 200) smoking_factor <- smoking_status == "yes" # Check if patient smokes # Calculate total risk score # Note: TRUE = 1, FALSE = 0 in arithmetic total_risk_score <- age_factor + (cholesterol_factor * 10) + (smoking_factor * 15) # Interpret results if (total_risk_score > 20) { print("HIGH RISK: Immediate intervention needed") } else if (total_risk_score > 10) { print("MODERATE RISK: Monitor closely") } else { print("LOW RISK: Continue preventive care") } # The calculation works as follows: # age_factor = 55 * 0.05 = 2.75 # cholesterol_factor = TRUE (220 > 200) = 1 * 10 = 10 # smoking_factor = TRUE ("yes" == "yes") = 1 * 15 = 15 # total_risk_score = 2.75 + 10 + 15 = 27.75 # Since 27.75 > 20, the patient is classified as HIGH RISK

Final Review
Which naming convention is recommended for R variables in medical contexts?
camelCase (e.g., patientTemp)
Common in JavaScript and Java.
While camelCase works, it's not the R convention.
snake_case (e.g., patient_temp)
Standard R convention.
Correct! R convention recommends snake_case for variable names, making them readable and consistent with R style guides.
PascalCase (e.g., PatientTemp)
Common for class names.
PascalCase is typically reserved for function names or classes in some R packages, not variables.
kebab-case (e.g., patient-temp)
Common in URLs and CSS.
Kebab-case doesn't work in R because the hyphen is interpreted as subtraction.
