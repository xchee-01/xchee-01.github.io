Understanding Vectors in Medical Research

The Test Tube Rack Analogy

A vector is an ordered collection of elements of the same data type. In medical practice:

  • Each slot holds the same type of sample
  • Slots are numbered (1, 2, 3...)
  • You can easily access any specific sample

Your First Vector

# Patient temperatures (Celsius) patient_temps <- c(36.5, 37.2, 38.1, 37.8, 36.9) print(patient_temps) # Output: [1] 36.5 37.2 38.1 37.8 36.9
Copied!

Pro Tip: Patient 3 has a mild fever (38.1°C) - vectors make outliers easy to spot!

Quick Check
Which statement best describes a vector in R?
A collection that can hold different data types together
This describes mixed data structures.
Not quite. Vectors must contain elements of the same data type. Lists can hold different data types.
An ordered collection of elements of the same data type
Elements maintain their position and share the same type.
Correct! Vectors in R must contain elements of the same data type and maintain their order.
A two-dimensional table of data
This describes a different data structure.
That's a data frame or matrix. Vectors are one-dimensional.
A single numeric value
This describes a scalar.
That's a scalar. Vectors are collections of values.

Three Types of Medical Data Vectors

R provides three main vector types for medical data:

  1. Numeric - Lab values, vital signs
  2. Character - Patient IDs, gene names
  3. Logical - Test positive/negative
# Numeric: Hemoglobin levels hemoglobin_levels <- c(12.5, 14.2, 11.8, 13.9, 15.1) # Character: Patient IDs patient_ids <- c("PT001", "PT002", "PT003", "PT004", "PT005") # Logical: Treatment response treatment_response <- c(TRUE, TRUE, FALSE, TRUE, FALSE)
Copied!
Data Type Check
Which vector type would be most appropriate for storing gene mutation status (present/absent)?
Numeric
Numbers for quantitative data.
While you could use 0/1, logical values are more explicit for binary data.
Character
Text strings.
Character strings like "present"/"absent" work but logical is more efficient.
Logical
TRUE/FALSE values.
Correct! Logical vectors (TRUE/FALSE) are perfect for binary data like presence/absence.
Integer
Whole numbers.
Integer could work but logical is specifically designed for binary states.

Lab Exercise 2: Oncology Dashboard

Synchronized Vectors
Create three synchronized vectors:
# Patient codes (format: "ONC101") cancer_patients <- c("___", "___", "___", "___") # Tumor sizes in cm tumor_sizes <- c(___, ___, ___, ___) # Remission status in_remission <- c(_____, _____, _____, _____)
Which set of vectors is correctly synchronized and uses appropriate data types?
Option A
cancer_patients <- c(101, 102, 103, 104) tumor_sizes <- c("2.5", "3.1", "1.8", "2.9") in_remission <- c("yes", "no", "yes", "no")
Wrong data types: IDs should be character, sizes numeric, status logical.
Option B
cancer_patients <- c("ONC101", "ONC102", "ONC103", "ONC104") tumor_sizes <- c(2.5, 3.1, 1.8, 2.9) in_remission <- c(TRUE, FALSE, TRUE, FALSE)
Correct! Uses proper data types (character for IDs, numeric for sizes, logical for status) and all vectors have the same length.
Option C
cancer_patients <- c("ONC101", "ONC102", "ONC103") tumor_sizes <- c(2.5, 3.1, 1.8, 2.9) in_remission <- c(TRUE, FALSE, TRUE, FALSE)
Vectors have different lengths (3 vs 4 elements). They must be synchronized.
Option D
cancer_patients <- c("ONC101", "ONC102", "ONC103", "ONC104") tumor_sizes <- c(2.5, 3.1, 1.8, 2.9) in_remission <- c(1, 0, 1, 0)
Use logical (TRUE/FALSE) instead of numeric (1/0) for remission status.

Accessing Vector Elements

R provides three ways to access data:

  1. Single element: vector[3]
  2. Multiple elements: vector[c(1,3,5)]
  3. Range: vector[2:5]
# Glucose monitoring example glucose_levels <- c(95, 110, 125, 88, 102, 145, 99) # Access 3rd reading third_reading <- glucose_levels[3] # 125 # Access multiple readings morning_readings <- glucose_levels[c(1, 3, 5)] # 95, 125, 102 # Access range midmorning_range <- glucose_levels[2:5] # 110, 125, 88, 102
Copied!

Vector Operations for Population Health

Vectorization Magic

R applies operations to ALL elements at once:

# Convert weights to pounds weights <- c(68, 75, 82, 91, 70) weights_lb <- weights * 2.205 # Calculate BMI for all patients heights <- c(1.70, 1.75, 1.80, 1.85, 1.65) bmi <- weights / (heights^2)
Copied!
Vectorization Understanding
If temps_c <- c(37.0, 38.5, 36.8), which code correctly converts all temperatures to Fahrenheit?
temps_f <- temps_c * 9/5 + 32
Standard conversion formula.
This is correct, but option D includes this plus another valid approach.
temps_f <- (temps_c * 9)/5 + 32
Explicit parentheses.
This is also correct, but option D is the most complete answer.
temps_f <- temps_c * (9/5 + 32)
Incorrect parentheses.
This adds 32 to 9/5 before multiplying, giving wrong results.
Both A and B
Multiple correct approaches.
Correct! Both A and B follow correct order of operations and apply the formula to all elements.

Lab Exercise 4: Drug Dosing Calculator

Drug Calculations
patient_weights <- c(55, 70, 85, 62, 78) dose_per_kg <- 5 # Calculate doses individual_doses <- ____________ # Round to nearest 10mg rounded_doses <- round(____________, -1)
Which code correctly calculates and rounds the doses?
Option A
individual_doses <- patient_weights * dose_per_kg rounded_doses <- round(individual_doses, -1)
Correct! Multiply weight by dose per kg, then round to nearest 10 using round(x, -1).
Option B
individual_doses <- patient_weights / dose_per_kg rounded_doses <- round(individual_doses, 10)
Division is wrong (should multiply) and round(x, 10) rounds to 10 decimal places.
Option C
individual_doses <- patient_weights + dose_per_kg rounded_doses <- round(individual_doses, -1)
Addition is wrong - should multiply weight by dose per kg.
Option D
individual_doses <- dose_per_kg * patient_weights rounded_doses <- round(individual_doses, 1)
Multiplication is correct but round(x, 1) rounds to 1 decimal place, not nearest 10.

Statistical Functions for Clinical Insights

Essential functions:

  • mean() - Average
  • median() - Middle value
  • min() & max() - Range
  • sd() - Standard deviation
  • sum() - Total
# WBC analysis wbc_counts <- c(4.5, 8.2, 11.3, 6.7, 9.1, 7.8, 5.2) avg_wbc <- mean(wbc_counts) # 7.5 wbc_range <- c(min(wbc_counts), max(wbc_counts)) # 4.5, 11.3
Copied!
Statistical Function Selection
Which function would you use to find the middle value in a sorted list of cholesterol readings?
mean()
Calculates average.
mean() calculates the average, not the middle value.
median()
Finds middle value.
Correct! The median() function returns the middle value when data is sorted.
mode()
Most frequent value.
mode() shows data type in R, not statistical mode.
middle()
Not a real function.
middle() doesn't exist in R. Use median() instead.

Lab Exercise 5: Cardiovascular Risk Assessment

Risk Assessment
crp_levels <- c(1.2, 4.5, 2.8, 8.3, 0.9, 3.7, 2.1, 5.6, 1.8, 6.2) # Calculate mean CRP mean_crp <- _______(______) # Count high-risk patients (CRP > 3) high_risk_count <- sum(_________ > 3) # Calculate percentage high_risk_percent <- (___________ / length(___________)) * 100
Which code correctly calculates the percentage of high-risk patients?
Option A
mean_crp <- mean(crp_levels) high_risk_count <- sum(crp_levels > 3) high_risk_percent <- (high_risk_count / length(crp_levels)) * 100
Correct! Use mean() for average, sum() to count TRUE values from logical comparison, and divide by length for percentage.
Option B
mean_crp <- median(crp_levels) high_risk_count <- length(crp_levels > 3) high_risk_percent <- (high_risk_count / sum(crp_levels)) * 100
median() gives middle value not mean, length() of logical gives vector length not count.
Option C
mean_crp <- mean(crp_levels) high_risk_count <- count(crp_levels > 3) high_risk_percent <- (high_risk_count / length(crp_levels)) * 100
count() is not a base R function. Use sum() to count TRUE values.
Option D
mean_crp <- mean(crp_levels) high_risk_count <- sum(crp_levels > 3) high_risk_percent := high_risk_count / 10 * 100
Wrong assignment operator (:= should be <-) and hardcoded 10 instead of length().

Real-World Connection: Statistical functions in R are used daily in clinical research to analyze patient populations, identify treatment effects, and monitor disease progression across cohorts.

Comprehensive Vector Challenge

Create a complete patient monitoring system using vectors. Store synchronized data for 8 patients including IDs, glucose levels, and medication compliance.

# Create your patient monitoring system # 1. Create patient IDs (DM001-DM008) # 2. Store glucose readings # 3. Track medication compliance (TRUE/FALSE) # 4. Calculate statistics and identify at-risk patients
Copied!

Solution:

# Patient monitoring system patient_ids <- paste0("DM", sprintf("%03d", 1:8)) glucose_readings <- c(125, 98, 145, 110, 165, 92, 118, 135) medication_compliance <- c(TRUE, TRUE, FALSE, TRUE, FALSE, TRUE, TRUE, FALSE) # Calculate statistics mean_glucose <- mean(glucose_readings) high_glucose_patients <- patient_ids[glucose_readings > 140] non_compliant_high <- patient_ids[glucose_readings > 140 & !medication_compliance] # Summary report cat("Mean glucose:", round(mean_glucose, 1), "mg/dL\n") cat("High glucose patients:", paste(high_glucose_patients, collapse=", "), "\n") cat("Non-compliant with high glucose:", paste(non_compliant_high, collapse=", "))
