10.2.4. Command Chaining with && and ||

🔗 Conditional Execution

While pipes pass data, && and || control when commands run.

The Rules 🛣️

# Run if previous succeeds command1 && command2 # Run if previous fails command1 || command2 # If-then-else logic command1 && command2 || command3
Copied!
Learning Checkpoint
What does the && operator do in command chaining?
A) Runs the second command only if the first command succeeds
Conditional execution based on success.
Correct! The && operator executes the second command only if the first command completes successfully (returns exit code 0).
B) Runs both commands simultaneously
Parallel execution of commands.
Not quite. The && operator runs commands sequentially, not simultaneously. For parallel execution, you would use & at the end of a command.
C) Runs the second command only if the first command fails
Conditional execution based on failure.
That's not right. You're thinking of the || operator, which runs the second command only if the first fails.
D) Passes output from first command to second command
Data flow between commands.
That's what the pipe (|) operator does. The && operator controls execution flow, not data flow.

Real-World Examples

# Safe directory creation $ mkdir project && cd project && echo "Created!" # Update only if connected $ ping -c 1 google.com && sudo apt update
Copied!
Learning Checkpoint
What happens when you run: ping -c 1 google.com && sudo apt update?
A) Both commands run regardless of ping result
Unconditional execution.
Not correct. The && operator makes the second command conditional on the success of the first.
B) apt update runs only if ping succeeds
Conditional update based on connectivity.
Correct! The && operator ensures that sudo apt update only runs if the ping command successfully reaches google.com, preventing updates when offline.
C) apt update runs only if ping fails
Update on failure.
That would require the || operator, not &&. The && operator runs on success, not failure.
D) The commands run in parallel
Simultaneous execution.
No, && runs commands sequentially. The second command waits for the first to complete successfully.

10.2.5. Advanced Pipeline Techniques

Combining Pipes with Redirection

# Find large files and save report $ find /home -size +100M | sort -h > large_files.txt # Extract unique IPs from logs $ cat access.log | awk '{print $1}' | sort | uniq -c > ips.txt
Copied!
Learning Checkpoint
What does the > operator do in: find /home -size +100M | sort -h > large_files.txt?
A) Appends the sorted output to large_files.txt
Adds to existing file content.
That would be the >> operator. The single > overwrites the file.
B) Redirects the sorted output to large_files.txt, overwriting existing content
Creates or overwrites the file.
Correct! The > operator redirects the sorted output from the pipeline to large_files.txt, creating the file if it doesn't exist or overwriting it if it does.
C) Displays output on screen and saves to file
Dual output destinations.
That would require the tee command. The > operator only redirects to the file.
D) Compares output with large_files.txt
File comparison operation.
No, > is for output redirection, not comparison. You would use diff or similar commands for file comparison.

Command Substitution

# Archive today's changes $ tar -czf changes_$(date +%Y%m%d).tar.gz $(find . -mtime -1)
Copied!
Learning Checkpoint
What does $(find . -mtime -1) do in the tar command above?
A) Creates a file named "find . -mtime -1"
Literal filename interpretation.
No, $() is command substitution syntax, not a literal string.
B) Comments out the find command
Disables the command.
Comments in bash use #, not $(). This is command substitution.
C) Executes find and uses its output as arguments to tar
Dynamic argument generation.
Correct! Command substitution $() executes the find command first, which finds files modified in the last day, then passes those filenames as arguments to tar.
D) Searches for files named "-1"
Searches for literal filename.
The -mtime -1 is an option to find, not a filename. It finds files modified within the last day.

Copied!
Learning Checkpoint
Which operator would you use to run a cleanup command only if a build fails?
A) |
Pipe operator.
The pipe operator passes output between commands, it doesn't handle conditional execution.
B) &&
Success operator.
The && operator runs on success, not failure. You need the opposite behavior.
C) ||
Failure operator.
Correct! The || operator executes the second command only if the first command fails, perfect for error handling and cleanup scenarios.
D) >
Redirect operator.
The > operator redirects output to files, it doesn't control conditional execution.

Learning Checkpoint
To find the 5 largest files in a directory listing, which command combination would you use?
A) ls -la | sort -rn | head -5
Basic numeric sort.
Close, but this would sort the entire line numerically, not specifically by file size.
B) ls -la | sort -k5 -rn | head -5
Sort by specific column.
Correct! sort -k5 -rn sorts by the 5th column (file size in ls -la output) in reverse numeric order, then head -5 shows the top 5 results.
C) ls -la | grep -5
Use grep for filtering.
grep is for pattern matching, not sorting. The -5 flag shows context lines, not top results.
D) ls -la | tail -5
Show last 5 lines.
tail shows the last lines, but without sorting you won't get the largest files.

Final Challenge
In the final challenge command, what does -exec du -h {} + do?
A) Deletes files found by find
File deletion operation.
No, du is for disk usage, not deletion. The rm command would be used for deletion.
B) Executes du -h on each file found, batching multiple files
Efficient disk usage calculation.
Correct! The -exec option runs du -h (disk usage, human-readable) on each file found by find. The {} is replaced with filenames, and + batches multiple files for efficiency.
C) Counts the number of files
File counting operation.
du shows disk usage, not file counts. You would use wc -l to count files.
D) Creates hard links to files
Link creation operation.
The ln command creates links. du is for showing disk usage of files.
