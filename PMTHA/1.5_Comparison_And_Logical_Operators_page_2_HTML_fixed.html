1.5.4. Mission Briefing: Logical Operators - OR

The OR operator returns true if AT LEAST ONE condition is true. In medicine, this mirrors situations where any one of several symptoms might indicate a condition, or where multiple risk factors independently increase disease probability.

Think of OR like a medical warning system - if ANY alarm goes off, we need to investigate! 🚨

Understanding OR Logic

# Simple OR demonstration risk_factor1 = False # No smoking risk_factor2 = True # Has diabetes risk_factor3 = False # No hypertension # ANY risk factor matters has_risk = risk_factor1 or risk_factor2 or risk_factor3 print(f"Has cardiovascular risk: {has_risk}") # True
Copied!

Medical Applications of OR

# Stroke risk assessment - any factor increases risk atrial_fibrillation = True previous_stroke = False high_blood_pressure = False # Any of these = increased risk stroke_risk = atrial_fibrillation or previous_stroke or high_blood_pressure print(f"Elevated stroke risk: {stroke_risk}") # True # Did you know? Atrial fibrillation increases stroke risk 5x!

Create a simplified sepsis screening tool. Sepsis is a life-threatening condition - early detection saves lives!

🏥 Medical Context: SIRS (Systemic Inflammatory Response Syndrome) criteria help identify sepsis. You need suspected infection PLUS at least 2 SIRS criteria.

# Complete the sepsis screening logic suspected_infection = True temperature = 38.5 # °C heart_rate = 95 # bpm respiratory_rate = 22 # breaths/min white_blood_cells = 13000 # cells/μL # SIRS criteria (complete the conditions) temp_abnormal = temperature > ... or temperature < ... tachycardia = heart_rate > ... tachypnea = respiratory_rate > ... wbc_abnormal = white_blood_cells > ... or white_blood_cells < ... # Count SIRS criteria met sirs_count = 0 if temp_abnormal: sirs_count += 1 if tachycardia: sirs_count += 1 if tachypnea: sirs_count += 1 if wbc_abnormal: sirs_count += 1 # Sepsis screening (complete the logic) possible_sepsis = suspected_infection and sirs_count >= ... print(f"Possible sepsis: {possible_sepsis}") print(f"SIRS criteria met: {sirs_count}/4")
Copied!

💡 Criteria hints:

  • Temperature is abnormal if >38°C (fever) OR <36°C (hypothermia)
  • Heart rate >90 is tachycardia
  • Respiratory rate >20 is tachypnea
  • WBC is abnormal if >12,000 (high) OR <4,000 (low)

1.5.5. Mission Briefing: Logical Operators - NOT

The NOT operator reverses a boolean value - turning True to False and vice versa. In healthcare, we often need to check for the absence of conditions or contraindications.

Think of NOT as asking "Is this NOT present?" - sometimes what's missing is just as important as what's there! 🔍

Understanding NOT Logic

# Simple NOT demonstration has_allergy = True safe_to_give = not has_allergy print(f"Safe to administer: {safe_to_give}") # False # Double negative (avoid these - confusing!) not_not_allergic = not not has_allergy # This equals True # Better to just use: has_allergy
Copied!

Medical Applications of NOT

# Checking contraindications has_kidney_disease = False safe_for_contrast = not has_kidney_disease print(f"Can receive contrast dye: {safe_for_contrast}") # True # Fun fact: Contrast dye helps visualize organs in CT scans!
Copied!
# Vaccine eligibility is_immunocompromised = True can_receive_live_vaccine = not is_immunocompromised print(f"Live vaccine safe: {can_receive_live_vaccine}") # False # Note: Live vaccines (like MMR) aren't safe for immunocompromised patients
Copied!
# Combining NOT with other operators pregnancy_test = False age = 45 # Some medications need: NOT pregnant AND adult can_prescribe_drug_x = not pregnancy_test and age >= 18 print(f"Can prescribe medication: {can_prescribe_drug_x}") # True
Copied!

Real-World Connection: Medical AI systems use NOT operators to rule out differential diagnoses - if certain key symptoms are NOT present, specific conditions can be excluded from consideration.

Learning Checkpoint
A patient has diabetes=True, heart_disease=False, on_immunosuppressants=False. The study excludes anyone with these conditions. Which expression checks if they're eligible?
Option A
not has_diabetes and not has_heart_disease and not on_immunosuppressants
This would work, but there's a more elegant solution. This patient would not be eligible since diabetes=True.
Option B
has_diabetes or has_heart_disease or on_immunosuppressants
This checks if they have any condition (returns True), not if they're eligible. We need the opposite!
Option C
not (has_diabetes or has_heart_disease or on_immunosuppressants)
This is also correct! It uses De Morgan's law. The patient would not be eligible since diabetes=True.
Option D
Both A and C are equivalent
Correct! Both expressions A and C are logically equivalent due to De Morgan's law: not(A or B or C) = (not A) and (not B) and (not C). Both would correctly identify this patient as ineligible.

1.5.6. Mission Briefing: Complex Logical Expressions

Real medical decisions often involve intricate combinations of AND, OR, and NOT operators. Understanding operator precedence and using parentheses for clarity is crucial for patient safety.

Operator Precedence (like math order of operations):

  1. NOT (highest priority)
  2. AND
  3. OR (lowest priority)

But always use parentheses to make your clinical logic crystal clear! Your future self (and colleagues) will thank you.

The Importance of Parentheses

# Antibiotic selection logic penicillin_allergy = True cephalosporin_allergy = False severe_infection = True # Without parentheses - potentially confusing # This evaluates as: (severe_infection and penicillin_allergy) or cephalosporin_allergy use_azithromycin = severe_infection and penicillin_allergy or cephalosporin_allergy print(f"Use azithromycin (confusing): {use_azithromycin}") # True # With parentheses - clear clinical logic # We want: severe infection AND (allergic to either antibiotic) use_azithromycin_clear = severe_infection and (penicillin_allergy or cephalosporin_allergy) print(f"Use azithromycin (clear): {use_azithromycin_clear}") # True
Copied!

Complex Medical Decision Example

# Complex cardiovascular risk assessment age = 55 male = True smoker = False diabetes = True ldl_cholesterol = 160 # Multiple risk factors with different weights traditional_risk = (age > 45 and male) or (age > 55 and not male) metabolic_risk = diabetes or ldl_cholesterol > 150 lifestyle_risk = smoker # Combined assessment high_risk = (traditional_risk and metabolic_risk) or (lifestyle_risk and diabetes) needs_statin = high_risk and not (age < 40) print(f"High cardiovascular risk: {high_risk}") print(f"Recommend statin therapy: {needs_statin}")
Copied!

Real-World Connection: The Framingham Risk Score and other cardiovascular risk calculators use exactly these types of complex logical expressions to stratify patient risk and guide treatment decisions.

Summary: Mastering Medical Decision Logic

Congratulations, Medical Decision Programmer! 🎉 You've learned how comparison and logical operators form the backbone of clinical decision support systems:

🔑 Key Takeaways:

  • Comparison operators (>, <, ==, !=, >=, <=) let us evaluate medical values against thresholds and reference ranges
  • AND operator ensures multiple clinical criteria are met simultaneously (ALL must be true)
  • OR operator identifies when any one of several risk factors or symptoms is present (ANY can be true)
  • NOT operator helps us check for absence of contraindications
  • Complex expressions mirror real-world medical decision trees and clinical guidelines
  • Parentheses are your friends - use them liberally for clarity!

💻 These operators power real healthcare technology:

  • Automated diagnostic algorithms (like ECG interpretation)
  • Clinical trial matching systems (matching patients to studies)
  • Drug interaction checkers (preventing dangerous combinations)
  • Risk stratification calculators (predicting patient outcomes)
  • Treatment recommendation engines (suggesting evidence-based therapies)

🏥 Remember:

  • Medical decisions often involve multiple criteria
  • Clear code saves lives - use parentheses and meaningful variable names
  • Test edge cases - what if values are exactly at thresholds?
  • Document your logic - future healthcare providers need to understand your code

📊 Quick Reference - Operator Cheat Sheet:

# Comparisons > # Greater than < # Less than == # Equal to != # Not equal to >= # Greater than or equal <= # Less than or equal # Logical and # ALL conditions must be True or # ANY condition can be True not # Reverses True/False # Precedence (use parentheses instead!) # 1. not (highest) # 2. and # 3. or (lowest)
