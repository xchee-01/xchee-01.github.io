The elif Statement

Chain multiple conditions for complex decisions:

if [ condition1 ]; then echo "First condition" elif [ condition2 ]; then echo "Second condition" elif [ condition3 ]; then echo "Third condition" else echo "Default action" fi
Copied!

System Load Management:

load_int=$(uptime | awk '{print $10}' | cut -d. -f1) if [ $load_int -eq 0 ]; then echo "🟢 System idle" elif [ $load_int -le 2 ]; then echo "🟢 Normal load" elif [ $load_int -le 5 ]; then echo "🟡 High load" else echo "🔴 Critical load!" fi
Copied!
Learning Checkpoint
What will be displayed if the system load integer is 3?
🟢 System idle
Displayed when load is 0
Not correct. The system idle message is only shown when load_int equals 0.
🟢 Normal load
Displayed for load 1-2
Not quite. Normal load is displayed when load_int is less than or equal to 2, but 3 is greater than 2.
🟡 High load
Displayed for load 3-5
Correct! When load_int is 3, it's greater than 2 but less than or equal to 5, so the "High load" message is displayed.
🔴 Critical load!
Displayed for load > 5
Not correct. Critical load is only displayed when load_int is greater than 5, but 3 is not greater than 5.

Lab Exercise 3: Backup Reporter

As a system administrator, you need to create a script that checks the age of backup files and reports their status. This script uses elif statements to categorize backups based on their age.

#!/bin/bash # Lab scenario: Complete the code to check backup file age # Fill in the missing parts indicated by ... backup_file="/backup/daily/system-backup.tar.gz" if [ ! -e "$backup_file" ]; then echo "❌ No backup found!" exit 1 fi file_age_hours=$(( ($(date +%s) - $(stat -c %Y "$backup_file")) / 3600 )) # Use the correct comparison operator to check if backup is <= 24 hours old if [ $file_age_hours ... 24 ]; then echo "✅ Backup fresh (${file_age_hours}h old)" # Add the correct keyword to chain another condition ... [ $file_age_hours -le 48 ]; then echo "⚠️ Backup aging (${file_age_hours}h old)" else echo "❌ Backup old - action required!" fi
Copied!

Expected output (for a 30-hour old backup):

⚠️ Backup aging (30h old)

Answer:

#!/bin/bash # Complete solution backup_file="/backup/daily/system-backup.tar.gz" if [ ! -e "$backup_file" ]; then echo "❌ No backup found!" exit 1 fi file_age_hours=$(( ($(date +%s) - $(stat -c %Y "$backup_file")) / 3600 )) if [ $file_age_hours -le 24 ]; then echo "✅ Backup fresh (${file_age_hours}h old)" elif [ $file_age_hours -le 48 ]; then echo "⚠️ Backup aging (${file_age_hours}h old)" else echo "❌ Backup old - action required!" fi
Copied!
Learning Checkpoint
What operator should fill the first blank to check if the backup is less than or equal to 24 hours old?
-eq
equals
Tests if values are equal
Not correct. -eq tests for exact equality, but we need to check if the age is less than or equal to 24.
-le
less or equal
Tests if value is less than or equal
Correct! -le means "less than or equal to", perfect for checking if the backup is 24 hours old or newer.
-gt
greater than
Tests if value is greater than
Not correct. -gt tests for "greater than", which would check for backups older than 24 hours, not fresher ones.
-ne
not equal
Tests if values are not equal
Not correct. -ne tests for inequality, but we need a range comparison here.
Learning Checkpoint
What keyword should fill the second blank to check an additional condition?
if
Starts a new conditional block
Not correct. 'if' starts a new conditional block, but we need to chain conditions within the same block.
else
Default action when all conditions fail
Not correct. 'else' is for the default case, but we have another specific condition to check.
elif
Checks additional condition in chain
Correct! 'elif' (else if) allows you to chain multiple conditions in the same conditional block.
then
Follows condition statement
Not correct. 'then' follows the condition, but doesn't start a new condition check.

File and Directory Tests

Essential file test operators:

Test Meaning
-e exists (any type)
-f regular file
-d directory
-r readable
-w writable
-x executable
-s not empty
Learning Checkpoint
Which test operator would you use to check if a path is a directory?
-e
exists
Checks if path exists (any type)
Not specific enough. -e checks if something exists but doesn't verify it's a directory.
-f
file
Checks if path is a regular file
Not correct. -f checks for regular files, not directories.
-d
directory
Checks if path is a directory
Correct! -d specifically tests whether the path is a directory.
-s
size
Checks if file is not empty
Not correct. -s checks if a file exists and has size greater than zero.

Directory Validator:

config_dir="/etc/myapp" if [ -d "$config_dir" ]; then echo "✅ Config directory exists" if [ -w "$config_dir" ]; then echo "✅ Directory writable" else echo "⚠️ Read-only mode" fi else echo "Creating directory..." sudo mkdir -p "$config_dir" fi
Copied!
Learning Checkpoint
What message will be displayed if the config directory exists but is NOT writable?
✅ Config directory exists
Only this message
Partially correct. This message will appear, but there's another message that follows.
✅ Directory writable
This message appears
Not correct. This message only appears if the directory IS writable.
⚠️ Read-only mode
Along with directory exists message
Correct! First "✅ Config directory exists" is displayed, then "⚠️ Read-only mode" because the directory is not writable.
Creating directory...
Directory creation message
Not correct. This message only appears if the directory doesn't exist at all.

Combining Tests:

log_file="/var/log/app.log" if [ -f "$log_file" ] && [ -s "$log_file" ]; then size=$(du -h "$log_file" | cut -f1) echo "📊 Log file exists (${size})" else echo "📝 Initializing log..." touch "$log_file" fi
Copied!
Learning Checkpoint
Under what conditions will "Initializing log..." be displayed?
When the log file doesn't exist
Only this condition
Partially correct. This is one condition, but there's another.
When the log file exists but is empty
Only this condition
Partially correct. This is one condition, but there's another.
When the log file exists and has content
File has data
Not correct. If the file exists AND has content, the size will be displayed instead.
Both A and B
File doesn't exist OR exists but is empty
Correct! The && operator requires both conditions to be true. If either -f (file exists) or -s (file not empty) is false, the else block executes.

Learning Checkpoint
Which test would you use to check if a variable is empty?
[ -f "$var" ]
File test operator
Not correct. -f tests if a file exists, not if a variable is empty.
[ -z "$var" ]
Zero-length string test
Correct! -z tests if a string has zero length (is empty).
[ "$var" = "" ]
String comparison to empty
This would also work, but [ -z "$var" ] is the more conventional and preferred method.
Both B and C
Multiple valid approaches
While both would work technically, -z is the standard and most commonly used approach.
