2.1. Mission Briefing: Understanding Lists as Medical Data Containers

Imagine you're the head nurse in a busy ICU. You've got 10 patients, each with hourly vital signs to track. Writing each measurement on a separate sticky note would be chaos! Instead, you'd use a chart with organized rows - that's exactly what Python lists do for your data.

Quick Concept: Lists = Your Digital Medical Filing Cabinet

🧩 Breaking It Down: What Makes Lists Special?

Think of lists like a pill organizer:

  • Each compartment (index) holds one item
  • You can see all compartments at once
  • Items stay in order (Monday's pills don't jump to Friday!)
  • You can add or remove pills as needed
# Creating your first medical list - it's that simple! patient_temps = [98.6, 99.1, 99.5, 100.2, 99.8] print("Patient temperature readings:", patient_temps)
Copied!

Pro Tip: Lists can hold ANY data type - like a patient file that contains:

  • Numbers (age, weight, lab values)
  • Text (name, symptoms, medications)
  • True/False values (has_allergies, is_diabetic)
  • Even other lists (test results over time)!

# A tiny fragment of DNA dna_sequence = ["A", "T", "G", "C", "C", "A", "T", "G"] print("DNA fragment:", dna_sequence) print(f"Length: {len(dna_sequence)} base pairs")

This simple list structure helps identify genetic mutations that could affect how patients respond to medications!

Fun Fact: The BRCA1 gene (linked to breast cancer) is about 81,000 base pairs long. Without lists, analyzing it would be like reading a book with 81,000 loose pages scattered on the floor!

2.2. Mission Briefing: Creating and Accessing List Elements

Picture a hospital corridor with numbered rooms. Room 0 (yes, we start at zero - programmers are quirky that way! 🤓) is the first room, Room 1 is the second, and so on. That's exactly how list indexing works!

Quick Concept: Every Item Has an Address (Index)

📍 Understanding Index Positions

# Blood pressure readings for 5 days blood_pressure = [120, 118, 125, 130, 122] # Index: 0 1 2 3 4 # Accessing readings - it's like knocking on a specific room door first_reading = blood_pressure[0] # Room 0 = First reading print(f"Monday's BP: {first_reading}") third_reading = blood_pressure[2] # Room 2 = Third reading print(f"Wednesday's BP: {third_reading}")
Copied!

🎯 The Magic of Negative Indexing

Here's where Python gets clever! Negative numbers count from the end:

# Think of it like entering the hospital from the back entrance blood_pressure = [120, 118, 125, 130, 122] last_reading = blood_pressure[-1] # -1 = Last room second_last = blood_pressure[-2] # -2 = Second to last print(f"Today's BP: {last_reading}") print(f"Yesterday's BP: {second_last}")
Copied!

Memory Trick:

Positive Index: Count from the START (like regular counting)
[0] [1] [2] [3] [4]

Negative Index: Count from the END (like a countdown)
[-5] [-4] [-3] [-2] [-1]

🏥 Real-World Application: Emergency Response

# Critical patient vitals - newest readings matter most! heart_rates = [72, 75, 78, 82, 95, 110, 125] # Quick! What's the current heart rate? current_hr = heart_rates[-1] if current_hr > 100: print(f"⚠️ ALERT: Tachycardia detected! HR: {current_hr}") else: print(f"Heart rate normal: {current_hr} bpm")
Copied!

2.3. Mission Briefing: Modifying Lists for Dynamic Patient Data

Unlike a printed medical chart, digital lists can grow, shrink, and change - just like patient conditions! Let's explore how to keep your data as dynamic as real healthcare.

Quick Concept: Lists Are Living Documents

📝 Adding New Data Points

# Morning glucose readings glucose_levels = [95, 110, 98] print("Morning readings:", glucose_levels) # Lunchtime - patient eats, we test again glucose_levels.append(145) # append = add to the end print("After lunch:", glucose_levels) # Oops! Forgot the 10 AM reading glucose_levels.insert(2, 101) # insert(position, value) print("Complete timeline:", glucose_levels)
Copied!

Tip: append() vs insert()

append(value) → Always adds to the END (like writing on the next line)
insert(position, value) → Adds ANYWHERE (like squeezing a note between lines)

✏️ Updating Existing Values

# Lab made an error - let's fix it! glucose_levels = [95, 110, 98, 145, 101] glucose_levels[1] = 108 # Direct assignment print("Corrected:", glucose_levels) # You can even do math directly glucose_levels[0] = glucose_levels[0] + 2 # Calibration adjustment print("Calibrated:", glucose_levels)
Copied!

🗑️ Removing Data

# Quality control: removing contaminated sample glucose_levels = [95, 108, 98, 145, 101] bad_reading = 145 glucose_levels.remove(bad_reading) # Removes first occurrence print("Clean data:", glucose_levels) # Alternative: Remove by position last_value = glucose_levels.pop() # Removes and returns last item print(f"Removed: {last_value}") print("Remaining:", glucose_levels)
Copied!

🏥 Real-World Scenario: Continuous Monitoring

# Simulating a continuous glucose monitor (CGM) cgm_data = [] # Start empty # Readings every 5 minutes cgm_data.append(95) # 8:00 AM cgm_data.append(97) # 8:05 AM cgm_data.append(102) # 8:10 AM print(f"CGM readings: {cgm_data}") print(f"Trend: {'Rising' if cgm_data[-1] > cgm_data[0] else 'Stable/Falling'}")
Copied!

Fun Fact: Modern CGMs can store up to 90 days of readings - that's about 26,000 data points in a list!

2.4. Mission Briefing: List Slicing for Data Analysis

Imagine you're reviewing a patient's medical history. Sometimes you need all of it, but often you just want "last week's labs" or "morning vitals." That's where slicing shines!

Quick Concept: Slicing = Taking a Snapshot of Your Data

🔪 The Slicing Syntax: [start:stop:step]

Think of it like cutting a delicious medical data sandwich:

  • start: Where to begin cutting (inclusive)
  • stop: Where to stop cutting (exclusive - the knife stops BEFORE this)
  • step: How thick each slice is
# Week of blood pressure readings bp_readings = [118, 120, 125, 119, 122, 128, 124] # Day: 0 1 2 3 4 5 6 # Mon Tue Wed Thu Fri Sat Sun # Get first three days first_half = bp_readings[0:3] # Days 0, 1, 2 (Mon-Wed) print("Early week:", first_half) # Get mid-week readings mid_week = bp_readings[2:5] # Days 2, 3, 4 (Wed-Fri) print("Mid-week:", mid_week)
Copied!

🎯 Advanced Slicing Tricks

# Week of blood pressure readings bp_readings = [118, 120, 125, 119, 122, 128, 124] # Every other day (for trending) alternate_days = bp_readings[::2] # Start at 0, go to end, step by 2 print("Every other day:", alternate_days) # Last 3 readings recent = bp_readings[-3:] # From -3 to end print("Last 3 days:", recent) # Reverse the list (newest first) reversed_bp = bp_readings[::-1] # Step of -1 reverses print("Newest first:", reversed_bp)
Copied!

Pro Tip: Slice Shortcuts

[:3] → First 3 items (start=0 is default)
[2:] → From index 2 to end (stop=end is default)
[:] → Copy entire list
[::2] → Every 2nd item
[::-1] → Reverse the list

🧬 Medical Application: Gene Analysis

# BRCA1 gene fragment (simplified) gene_sequence = ["ATG", "GAA", "TTC", "CAG", "AGC", "TTA", "GGC", "AAT"] # Extract specific codon region for analysis target_region = gene_sequence[2:6] print("Region of interest:", target_region) # Check every 3rd codon for patterns pattern_check = gene_sequence[::3] print("Pattern analysis:", pattern_check)
Copied!

Lab Exercise 4: Analyzing Patient Recovery Patterns

You're helping the orthopedic ward analyze recovery patterns. Use slicing to extract early recovery (first 3 days), mid-recovery (days 4-7), and create an alternate-day report.

Answer:

# Pain tracking analysis pain_scores = [8, 7, 7, 6, 5, 5, 4, 3, 3, 2] # Extract early recovery (first 3 days) early_recovery = pain_scores[0:3] # or just [:3] print("Early recovery scores:", early_recovery) # Extract mid-recovery (days 4-7) = indices 3-6 mid_recovery = pain_scores[3:7] print("Mid-recovery scores:", mid_recovery) # Get scores for every other day alternate_scores = pain_scores[::2] print("Alternate day scores:", alternate_scores) # Calculate improvement improvement = pain_scores[0] - pain_scores[-1] print(f"Pain reduced by: {improvement} points")
