10.5.3. Character Sets with Square Brackets [] - Your Custom Filter

Square brackets let you create your own custom character matcher. It's like having a bouncer at a club who only lets in specific characters!

Power User Box

[abc] = matches a, b, or c [a-z] = matches any lowercase letter [0-9] = matches any digit [a-zA-Z] = matches any letter (upper or lower)
Copied!
Quick Check
Which pattern would match files named 'file1.txt', 'file5.txt', and 'file9.txt'?
file*.txt
Using asterisk wildcard
This would match more files than intended, including file10.txt, file123.txt, etc.
file?.txt
Using question mark wildcard
The ? matches exactly one character, so this would match all file[single-character].txt files.
file[159].txt
Using character set with specific digits
Correct! This matches exactly file1.txt, file5.txt, and file9.txt.
file[0-9].txt
Using character range
Also correct! This is more general and would match any single digit, but would include the three files mentioned.

Building Your Character Set Skills

Start simple, then combine for power:

# Match files starting with vowels user@hostname:~$ ls [aeiou]* # Match numbered reports from days 1-5 user@hostname:~$ ls report-2024-01-0[1-5].log # Combine with other wildcards for ultimate power! user@hostname:~$ ls [A-Z]*-v[0-9].conf # Matches: Apache-v1.conf, Nginx-v5.conf, BUT NOT apache-v1.conf (lowercase!)
Copied!
Pattern Matching
Why doesn't [A-Z]*-v[0-9].conf match apache-v1.conf?
The pattern is incorrect
There's a syntax error in the pattern
The pattern syntax is correct. The issue is with case sensitivity.
[A-Z] only matches uppercase letters
Character ranges are case-sensitive
Correct! [A-Z] matches only uppercase letters, while 'apache' starts with a lowercase 'a'.
The v should be uppercase
Pattern requires uppercase V
The 'v' in the pattern is outside the brackets and matches literally.
The pattern needs quotes
Missing quotation marks
This pattern doesn't require quotes unless it contains spaces or special shell characters.

The Time-Saving Trick: Ranges

Instead of typing [0123456789], just use [0-9]. Your fingers will thank you!

# The hard way: ls file[0123456789].txt # The smart way: ls file[0-9].txt # They do the same thing!
Copied!
Range Knowledge
Which range pattern would match all lowercase letters from 'a' to 'f'?
[a-f]
Range notation
Correct! This is the standard range notation for consecutive characters.
[A-F]
Uppercase range
This matches uppercase letters A-F, not lowercase a-f.
[abcdef]
Explicit listing
Also correct! This explicitly lists each character, which works but is more typing.
Both A and C
Multiple correct answers
Correct! Both [a-f] and [abcdef] will match the same lowercase letters.

Real-World Scenario: Security Audit Emergency!

The security team needs all authentication logs from June through August, FAST!

# Old painful way (don't do this!): user@hostname:~$ ls auth.log.2024-06-* user@hostname:~$ ls auth.log.2024-07-* user@hostname:~$ ls auth.log.2024-08-* # Ninja way with brackets: user@hostname:~$ ls auth.log.2024-0[6-8]-* # Even better - archive them all at once: user@hostname:~$ tar -czf summer-auth-logs.tar.gz auth.log.2024-0[6-8]-*
Copied!
Time-Saver
Which pattern would match logs from April through June (months 04-06)?
auth.log.2024-[4-6]-*
Simple range without leading zero
This misses the leading zero in months 04-06.
auth.log.2024-0[4-6]-*
Range with leading zero
Correct! This matches 04, 05, and 06 with the proper formatting.
auth.log.2024-[04-06]-*
Range with full month numbers
Character ranges work on single characters, not multi-digit numbers.
auth.log.2024-{04..06}-*
Brace expansion syntax
This is brace expansion syntax, not character set syntax. Different concept!

10.5.4. Negation with [!] - The "Everything EXCEPT" Operator

Sometimes knowing what you DON'T want is just as important as knowing what you do want. Enter the negation operator!

Mind-Bender Box

[!a] = any character EXCEPT 'a' [!0-9] = any character EXCEPT digits [!.] = any character EXCEPT a dot (great for skipping hidden files!)
Copied!
Negation Basics
Which pattern matches any file that does NOT start with a digit?
[0-9]*
Character range for digits
This matches files that DO start with a digit, not those that don't.
[!0-9]*
Negated character range
Correct! The ! inside brackets negates the range, matching any character except 0-9.
![0-9]*
Exclamation outside brackets
The ! must be inside the brackets for negation to work.
[^0-9]*
Caret notation
This is regex syntax, not shell wildcard syntax. Use ! in shell patterns.

The Art of Exclusion

Watch how negation flips the script:

# Show all files (including hidden) user@hostname:~$ ls -la # Show only NON-hidden files user@hostname:~$ ls [!.]* # List all log files EXCEPT the ones ending in 7, 8, or 9 user@hostname:~$ ls *[!789].log # Matches: file1.log, file2.log, BUT NOT file7.log
Copied!
Exclusion Logic
To list all .conf files except those starting with 'test' or 'temp', which pattern works?
[!test]*.conf
Negating the word 'test'
Brackets match single characters, not words. This would exclude t, e, s individually.
[!t]*.conf
Exclude files starting with 't'
This only excludes files starting with 't', missing 'temp' files.
[!test|temp]*.conf
Using pipe for alternatives
Pipe doesn't work inside brackets. This excludes t, e, s, |, m, p individually.
Neither A nor C will work correctly
Wildcards can't exclude word patterns
Correct! Shell wildcards work on single characters. To exclude word patterns, you'd need tools like grep -v or find with -not.

Real-World Lifesaver: The Migration Mishap Prevention

You're migrating configs but need to skip all test and backup files:

# See what we're dealing with user@hostname:~$ ls /etc/*.conf # apache2.conf mysql.conf nginx.conf test-nginx.conf nginx.conf.bak # Copy only the REAL config files user@hostname:~$ cp /etc/[!t]*.conf ~/migration/ # Skips: test-nginx.conf # But wait, we still have .bak files! Let's be more clever: user@hostname:~$ ls /etc/*[!k].conf # Now we skip anything ending in 'k' (like .bak renamed to .conf)
Copied!

10.5.4. Brace Expansion {} - The Multiplication Machine

Brace expansion is like a copy machine for your commands. Type once, create many!

Time-Saver Supreme Box

{dev,test,prod} = expands to: dev test prod {1..5} = expands to: 1 2 3 4 5 {a..e} = expands to: a b c d e
Copied!
Expansion Basics
What does mkdir dir{A,B,C} create?
A single directory named 'dir{A,B,C}'
Literal interpretation
Braces are expanded by the shell, not taken literally.
Three directories: dirA, dirB, dirC
Brace expansion result
Correct! The shell expands dir{A,B,C} to dirA dirB dirC.
An error message
Invalid syntax
This is valid brace expansion syntax.
A directory named 'dirABC'
Concatenated result
Brace expansion creates separate items, not concatenations.

The Power of Parallel Creation

Watch how one command becomes many:

# Create a full project structure in ONE command! user@hostname:~$ mkdir -p myproject/{src,docs,tests,config}/{python,java,scripts} # This creates: # myproject/src/python, myproject/src/java, myproject/src/scripts # myproject/docs/python, myproject/docs/java, myproject/docs/scripts # ... and so on!
Copied!
Nested Expansion
How many directories does mkdir -p app/{frontend,backend}/{src,test} create?
2
Just frontend and backend
The nested braces create subdirectories too.
4
All combinations
Correct! frontend/src, frontend/test, backend/src, backend/test = 4 directories.
6
Including parent directories
Parent directories are created automatically, not counted separately.
8
Double counting
There are only 4 leaf directories created.

Numbered Sequences - Because Typing is Overrated

# Create 10 numbered directories the hard way: mkdir dir1 dir2 dir3 dir4 dir5 dir6 dir7 dir8 dir9 dir10 # Create 10 numbered directories the smart way: mkdir dir{1..10} # Create a test environment with multiple file types: touch test.{txt,log,conf,json,xml,yaml} # Creates: test.txt test.log test.conf test.json test.xml test.yaml
Copied!
Sequence Skills
Which command creates files: log01.txt, log02.txt, log03.txt?
touch log{1..3}.txt
Simple sequence
This creates log1.txt, log2.txt, log3.txt without leading zeros.
touch log{01..03}.txt
Zero-padded sequence
Correct! Bash preserves the zero-padding in sequences.
touch log0{1..3}.txt
Manual zero prefix
This works for single digits but is less flexible than {01..03}.
touch log[01-03].txt
Character range
Brackets are for matching existing files, not creating new ones.

Real-World Magic: Multi-Environment Deployment

DevOps engineers love this trick:

# Set up complete environment structure user@hostname:~$ mkdir -p /opt/myapp/{development,staging,production}/{config,logs,data,backups} # Deploy configs to all environments at once user@hostname:~$ cp base.conf /opt/myapp/{development,staging,production}/config/ # Create environment-specific configs user@hostname:~$ touch /opt/myapp/{dev,stage,prod}-database.conf

10.5.5. Combining Powers - Advanced Wildcard Wizardry

Now for the ultimate level - combining different wildcards for maximum power!

The Compound Pattern Technique

# Find Python files that aren't tests user@hostname:~$ ls [!test]*.py # main.py utils.py config.py # but NOT test_main.py # Multi-format log files from summer months user@hostname:~$ ls /var/log/app-202[3-4]-0[6-8]-*.{log,txt,gz} # Version 1-5 configs in multiple formats user@hostname:~$ ls *-v[1-5].{conf,cfg,config}
Copied!
Pattern Mastery
Which files would app-v[2-4].{py,js} match?
app-v2.py, app-v3.py, app-v4.py only
Only Python files
The brace expansion includes both .py and .js extensions.
app-v2.js, app-v3.js, app-v4.js only
Only JavaScript files
The brace expansion includes both .py and .js extensions.
All six files: app-v2.py, app-v2.js, app-v3.py, app-v3.js, app-v4.py, app-v4.js
All combinations
Correct! [2-4] matches 2, 3, 4 and {py,js} expands to both extensions.
Only app-v2.py and app-v4.js
Random subset
The pattern matches all combinations systematically.

The Safety Pattern: Test Before You Destroy!

Golden Rule: Always test with ls before using rm or mv!

# ALWAYS do this first: user@hostname:~$ ls old-backup-202[0-2]-*.{tar,zip,gz} # ONLY after verifying the list, do this: user@hostname:~$ rm old-backup-202[0-2]-*.{tar,zip,gz}
Copied!
Safety First
Why should you always test patterns with ls before using rm?
ls is faster than rm
Performance consideration
Speed isn't the issue - safety is!
To verify which files the pattern matches before deletion
Prevention of accidental data loss
Correct! Always verify what your pattern matches to avoid accidentally deleting the wrong files.
rm requires root permissions
Permission requirement
rm doesn't always require root permissions.
ls creates a backup first
Backup creation
ls only lists files, it doesn't create backups.
