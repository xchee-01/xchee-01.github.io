🔍 Section 1: grep - Your Pattern Detective

Understanding grep Basics

The name "grep" comes from g/re/p (global/regular expression/print). It's your pattern-finding superpower!

# Find a simple word grep "hello" myfile.txt # Case-insensitive search (-i) grep -i "alice" phonebook.txt # Show line numbers (-n) grep -n "555" phonebook.txt # Count matches (-c) grep -c "555" phonebook.txt
Copied!
Learning Checkpoint
What does the grep command name stand for?
general regular expression parser
A common misconception about grep's name.
Not quite right. While this sounds reasonable, grep actually has a more specific origin.
global/regular expression/print
The actual origin from the ed editor command.
Correct! grep stands for g/re/p (global/regular expression/print), originating from the ed editor command.
get/replace/expression/print
An incorrect expansion of grep.
That's not correct. grep doesn't replace text, it searches for patterns.
generic regex processor
A plausible but incorrect name.
While grep does process regular expressions, this isn't what the name stands for.
Learning Checkpoint
Which grep flag allows you to search without case sensitivity?
-c
count
This flag counts matches.
Not correct. The -c flag counts the number of matching lines, not ignore case.
-n
line numbers
This flag shows line numbers.
That's not right. The -n flag displays line numbers with matching lines.
-i
ignore case
This flag ignores case differences.
Correct! The -i flag makes grep ignore case differences when searching.
-v
invert
This flag inverts the match.
Not quite. The -v flag inverts the match (shows non-matching lines), not ignore case.

Advanced grep: Regular Expressions

# Find lines starting with ERROR (^) grep "^ERROR" file.txt # Find lines ending with IP ($) grep "10.0.0.50$" security.log # Multiple patterns (-E) grep -E "ERROR|CRITICAL" log.txt # Invert match (-v) grep -v "INFO" log.txt
Copied!
Learning Checkpoint
Which grep command would find lines that do NOT contain "ERROR"?
grep "ERROR" file.txt
Standard grep search.
This finds lines containing ERROR, not excluding them.
grep -v "ERROR" file.txt
Inverted match with -v flag.
Correct! The -v flag inverts the match, showing lines that do NOT contain the pattern.
grep "^ERROR" file.txt
Lines starting with ERROR.
This finds lines starting with ERROR, not excluding ERROR.
grep -E "ERROR" file.txt
Extended regex for ERROR.
The -E flag enables extended regex but still finds ERROR, not excludes it.
Learning Checkpoint
What is the difference between grep "ERROR" and grep "^ERROR"?
No difference, they find the same lines
Both commands work identically.
Not correct. The ^ symbol has special meaning in regular expressions.
^ERROR finds lines starting with ERROR, ERROR finds it anywhere
The ^ anchor matches beginning of line.
Correct! The ^ anchor matches the beginning of a line, so ^ERROR only finds lines that start with ERROR.
^ERROR is case-sensitive, ERROR is not
Different case sensitivity.
Both are case-sensitive by default. The ^ symbol doesn't affect case sensitivity.
^ERROR counts matches, ERROR displays them
Different output behavior.
Both display matching lines. The ^ is a position anchor, not a behavior modifier.

✂️ Section 2: cut - Your Data Surgeon

Field Extraction Basics

Extract specific columns from structured text:

# Get usernames from /etc/passwd (field 1) cut -d: -f1 /etc/passwd | head -5 # Multiple fields (1 and 6) cut -d: -f1,6 /etc/passwd | head -3 # Field ranges (1-3) cut -d: -f1-3 /etc/passwd | head -3 # Character positions cut -c1-10 data.txt
Copied!
Learning Checkpoint
In the cut command, what does the -d flag specify?
The data to cut
Input data specification.
Not correct. The -d flag doesn't specify the data itself.
The field delimiter
Character that separates fields.
Correct! The -d flag specifies the field delimiter (separator) character.
The display format
Output formatting option.
That's not right. The -d flag is about field separation, not display formatting.
The delete option
Deletion configuration.
Incorrect. cut doesn't delete data, and -d specifies delimiter.
Learning Checkpoint
What would cut -d: -f1,3 extract from the line "john:x:1001:1001:John Doe:/home/john:/bin/bash"?
john:x
Fields 1 and 2.
Not correct. Field 2 is "x", but we're extracting fields 1 and 3.
john:1001
Fields 1 and 3.
Correct! Field 1 is "john" and field 3 is "1001", so the output is "john:1001".
x:1001
Fields 2 and 3.
That would be fields 2 and 3, but we're extracting fields 1 and 3.
john:John Doe
Fields 1 and 5.
"John Doe" is field 5, but we're extracting fields 1 and 3.

🔧 Lab: CSV Processing

# Create sales data cat > /tmp/sales.csv << 'EOF' Date,Product,Quantity,Price,Customer 2024-01-15,Laptop,2,999.99,TechCorp 2024-01-15,Mouse,10,29.99,StartupInc EOF # Extract products cut -d',' -f2 /tmp/sales.csv # Get product and price cut -d',' -f2,4 /tmp/sales.csv
Copied!
Learning Checkpoint
What output would cut -d',' -f2,4 /tmp/sales.csv produce from the sales data above?
Product,Price / Laptop,999.99 / Mouse,29.99
Fields 2 and 4 from all lines.
Correct! Field 2 is Product and field 4 is Price, so it extracts these columns from all lines.
Laptop,2 / Mouse,10
Fields 2 and 3.
That would be fields 2 and 3 (Product and Quantity), not 2 and 4.
2,999.99 / 10,29.99
Fields 3 and 4.
That would be fields 3 and 4 (Quantity and Price), not 2 and 4.
Product,Quantity / Laptop,2 / Mouse,10
Wrong field selection.
We're extracting fields 2 and 4, not 2 and 3.

Quick Reference Card

grep flags:

  • -i: ignore case
  • -n: show line numbers
  • -c: count matches
  • -v: invert match
  • -E: extended regex

cut flags:

  • -d: field delimiter
  • -f: field numbers
  • -c: character positions
Learning Checkpoint
To find lines containing "ERROR" and extract only the timestamp (first field) from those lines, which command combination would work?
grep "ERROR" log.txt | cut -d' ' -f1
Filter then extract.
Correct! First grep finds lines with "ERROR", then cut extracts the first space-delimited field (timestamp).
cut -d' ' -f1 log.txt | grep "ERROR"
Extract then filter.
This would search for "ERROR" in timestamps only, not the full lines.
grep -f1 "ERROR" log.txt
Invalid grep syntax.
grep doesn't have a -f flag for field extraction. That's cut's job.
cut "ERROR" -d' ' -f1 log.txt
Invalid cut syntax.
cut doesn't search for patterns. Use grep for pattern matching.
