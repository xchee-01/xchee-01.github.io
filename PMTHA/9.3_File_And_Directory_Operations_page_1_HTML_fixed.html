9.3.1. Creating Directories with `mkdir`

The `mkdir` (make directory) command is your folder creator extraordinaire!

Basic Directory Creation

# Create a single directory user@hostname:~$ mkdir projects user@hostname:~$ ls projects
Copied!

Try This!

Create a directory for your hobby:

# Photography enthusiast user@hostname:~$ mkdir photo_collection # Music lover user@hostname:~$ mkdir my_playlists
Copied!
Test Your Understanding
What happens when you run `mkdir projects` if a directory named "projects" already exists?
A) It overwrites the existing directory
Not correct. mkdir never overwrites existing directories for safety reasons.
B) It creates a subdirectory inside the existing one
That's not right. It won't create a subdirectory unless you specify a path like projects/subdirectory.
C) It displays an error message
Correct! mkdir will display an error message: "mkdir: cannot create directory 'projects': File exists"
D) It renames the existing directory
Incorrect. mkdir doesn't rename directories. You would use the mv command for renaming.

Creating Nested Directories with -p Flag

# The tedious way (don't do this!) user@hostname:~$ mkdir website user@hostname:~$ cd website user@hostname:~/website$ mkdir images user@hostname:~/website$ mkdir css # The ninja way with -p flag! user@hostname:~$ mkdir -p website/{images,css,js}
Copied!

Pro Tip: The `-p` flag creates parent directories automatically. No more "directory doesn't exist" errors!

Concept Check
Which command will successfully create the directory structure `data/2024/january/reports`?
A) `mkdir data/2024/january/reports`
This will fail if the parent directories don't exist.
B) `mkdir -p data/2024/january/reports`
Correct! The -p flag creates all parent directories as needed.
C) `mkdir data && mkdir 2024 && mkdir january && mkdir reports`
This won't work because you need to cd into each directory before creating the next one.
D) `mkdir --recursive data/2024/january/reports`
There's no --recursive flag for mkdir. Use -p instead.

Real-World Example: Python Project Structure

# Create complete ML project structure user@hostname:~$ mkdir -p my_ml_project/{data/{raw,processed},models,notebooks,src/{features,models,visualization},tests} # Verify structure user@hostname:~$ tree my_ml_project my_ml_project/ ├── data/ │ ├── raw/ │ └── processed/ ├── models/ ├── notebooks/ ├── src/ │ ├── features/ │ ├── models/ │ └── visualization/ └── tests/
Copied!
Advanced Challenge
What does the command `mkdir -p project/{src/{main,test},docs,build/{debug,release}}` create?
A) 3 directories: src, docs, and build
You're missing the subdirectories created by the nested braces.
B) 5 directories: main, test, docs, debug, and release
You're not counting the parent directories src and build.
C) 7 directories including all subdirectories
Close, but you're missing one directory in your count.
D) 8 directories including the parent 'project' directory
Correct! project, src, main, test, docs, build, debug, and release = 8 directories total.

Common Pitfall Alert! ⚠️

# This fails if parent doesn't exist user@hostname:~$ mkdir parent/child mkdir: cannot create directory 'parent/child': No such file or directory # Always use -p for nested directories user@hostname:~$ mkdir -p parent/child # Success!
Copied!
Error Prevention
When will `mkdir subfolder/newdir` succeed WITHOUT the -p flag?
A) Never - it always requires -p for paths with slashes
Not quite. It can work without -p in certain conditions.
B) When 'subfolder' already exists
Correct! If the parent directory 'subfolder' exists, mkdir can create 'newdir' inside it without -p.
C) When running as root user
Being root doesn't change mkdir's behavior regarding non-existent parent directories.
D) When the current directory is writable
Write permissions don't help if the parent directory doesn't exist.

Lab Exercise 1: Hospital Data Organization

As a bioinformatics analyst managing hospital data, you need to create a directory structure to organize patient records, staff information, and inventory data.

Your task is to create this structure:

hospital_data/ ├── patients/ │ ├── records/ │ └── test_results/ ├── staff/ │ ├── doctors/ │ └── nurses/ └── inventory/ ├── medications/ └── equipment/
Copied!

Instructions: Write a single command using mkdir with the -p flag and brace expansion to create the entire structure.

Before You Try
Which command creates the entire hospital_data structure most efficiently?
A) `mkdir -p hospital_data/patients/records hospital_data/patients/test_results ...` (listing all paths)
This works but is unnecessarily verbose. Brace expansion is more efficient.
B) `mkdir -p hospital_data/{patients/{records,test_results},staff/{doctors,nurses},inventory/{medications,equipment}}`
Perfect! This uses brace expansion efficiently to create the entire structure in one command.
C) `mkdir hospital_data && cd hospital_data && mkdir patients staff inventory`
This only creates the top-level directories, missing all the subdirectories.
D) `mkdir -r hospital_data/**/*`
There's no -r flag for mkdir, and ** globbing doesn't work for creating directories.

Answer:

# Complete solution mkdir -p hospital_data/{patients/{records,test_results},staff/{doctors,nurses},inventory/{medications,equipment}} # Verify the structure was created correctly tree hospital_data
Copied!

9.3.2. Creating Files with `touch`

The `touch` command creates files instantly - no need to open an editor!

Basic File Creation

# Create single file user@hostname:~$ touch README.md user@hostname:~$ ls -la README.md -rw-rw-r-- 1 user user 0 Jan 20 10:30 README.md
Copied!
Quick Check
What is the initial size of a file created with `touch newfile.txt`?
A) 1 byte
Not correct. Touch creates completely empty files.
B) 0 bytes
Correct! Touch creates empty files with 0 bytes.
C) 1 kilobyte
That's too large. Touch creates empty files (0 bytes).
D) Depends on the file extension
File extensions don't affect the initial size with touch - it's always 0 bytes.

Multiple File Creation

# Create multiple files user@hostname:~$ touch index.html style.css script.js # Create numbered files user@hostname:~$ touch experiment_{1..5}.py user@hostname:~$ ls experiment_* experiment_1.py experiment_2.py experiment_3.py experiment_4.py experiment_5.py
Copied!
Pattern Recognition
What files does `touch report_{a..c}.txt` create?
A) report_a.txt, report_b.txt, report_c.txt
Correct! The {a..c} expansion creates a, b, and c variants.
B) report_abc.txt
Not right. The .. syntax expands to individual items, not concatenated.
C) report_{a..c}.txt (literal filename)
The shell expands brace patterns before touch sees them.
D) report_a.txt through report_z.txt
{a..c} only expands to a, b, and c, not the entire alphabet.

Advanced Feature: Custom Timestamps

# Create file with specific timestamp user@hostname:~$ touch -t 202001011200 time_travel.txt user@hostname:~$ ls -la time_travel.txt -rw-rw-r-- 1 user user 0 Jan 1 2020 time_travel.txt
Copied!
Time Format
In `touch -t 202401151430`, what does '1430' represent?
A) The year 1430
The year is already specified as 2024 at the beginning.
B) 14 hours and 30 minutes (2:30 PM)
Correct! 1430 is the time in 24-hour format: 14:30 or 2:30 PM.
C) January 4th, 1930
The format is YYYYMMDDhhmm, not a different date arrangement.
D) File size of 1430 bytes
The -t flag sets timestamp, not file size. Touch always creates 0-byte files.

Real-World Example: Flask Application Setup

# Navigate to project user@hostname:~$ cd my_ml_project/src # Create all necessary files user@hostname:~/my_ml_project/src$ touch __init__.py app.py config.py requirements.txt .env .gitignore # Create module files user@hostname:~/my_ml_project/src$ touch models/{__init__.py,train.py,predict.py} user@hostname:~/my_ml_project/src$ touch features/{__init__.py,build_features.py}
Copied!

Lab Exercise 2: Medical Research File Setup

As a medical data analyst, you need to set up files for a new research project analyzing patient outcomes.

Your task is to create these files:

  • `patient_data.csv` - for storing patient information
  • `analysis.py` - for Python analysis script
  • `results_2024.txt` - for storing analysis results
  • `.env` - for environment variables
  • `README.md` - for project documentation

Instructions: Use the touch command to create all five files efficiently.

Best Practice
Which approach is most efficient for creating these 5 files?
A) Run touch 5 times, once for each file
This works but is inefficient. Touch can create multiple files at once.
B) `touch patient_data.csv analysis.py results_2024.txt .env README.md`
Perfect! This creates all files in one efficient command.
C) Create each file by opening and saving in a text editor
This is much slower than using touch from the command line.
D) Use echo to create each file
Echo would add content to files. Touch is better for creating empty files.

Answer:

# Complete solution touch patient_data.csv analysis.py results_2024.txt .env README.md # Alternative using brace expansion: touch {patient_data.csv,analysis.py,results_2024.txt,.env,README.md} # Verify files were created ls -la
Copied!

Lab Exercise 3: Understanding touch vs echo

As a system administrator, you need to understand the difference between different file creation methods to avoid data loss.

Consider this scenario: What's the difference between `touch filename` and `echo > filename`?

Command Comparison
What's the key difference between `touch existing.txt` and `echo > existing.txt` when existing.txt already contains data?
A) Both commands do exactly the same thing
They behave very differently with existing files!
B) touch preserves content, echo overwrites with empty line
Correct! Touch only updates timestamp, echo > replaces all content with just a newline.
C) echo preserves content, touch overwrites it
It's the opposite - touch preserves content, echo > overwrites.
D) Both commands will show an error
Neither command shows an error with existing files.

Answer:

Key differences:

  • `touch filename` creates empty file (0 bytes) if it doesn't exist
  • `echo > filename` creates file with newline (1 byte)
  • Critical: `touch` won't overwrite existing content, `echo >` will!
  • Use `touch` when you want to preserve existing data
  • Use `echo >` only when you intend to replace file contents

Final Check
Which command creates both the directory structure `logs/2024/errors` AND an empty log file inside it?
A) `mkdir -p logs/2024/errors && touch logs/2024/errors/system.log`
Excellent! This creates the directory structure first, then creates the file inside it.
B) `touch -p logs/2024/errors/system.log`
Touch doesn't have a -p flag. It can't create parent directories.
C) `mkdir logs/2024/errors/system.log`
This would try to create system.log as a directory, not a file.
D) `create -path logs/2024/errors/system.log`
There's no 'create' command in Linux. Use mkdir and touch.
