Introduction
Variables and command substitution are fundamental Linux skills. This module covers variable basics, naming rules, and types.

Variable Naming Rules

✅ Good Names:

user_count=42 # Snake case userName="Alice" # Camel case LOG_LEVEL="DEBUG" # Uppercase constants _temp=100 # Underscore start
Copied!

❌ Bad Names:

user-count=42 # No hyphens 2fast="movie" # No number start my var=42 # No spaces my$var="oops" # No special chars
Copied!
Lab Exercise 1: Server Profile
Create a server configuration by filling in the blanks:
SERVER_NAME="web-prod-___" # Add number SERVER_IP="10.0.1.___" # 1-254 ADMIN_EMAIL="___@corp.com" # Your name echo "Server: $SERVER_NAME" echo "IP: $SERVER_IP"
Which of the following is a valid variable name for this server configuration?
web-server-01
Using hyphens in the variable name
Incorrect. Variable names cannot contain hyphens (-). Use underscores (_) instead.
WEB_SERVER_01
Using uppercase with underscores
Correct! This follows the convention for constants in shell scripts - uppercase letters with underscores.
1st_server
Starting with a number
Incorrect. Variable names cannot start with a number. They must begin with a letter or underscore.
server name
Using spaces in the name
Incorrect. Variable names cannot contain spaces. Use underscores or camelCase instead.

Environment vs Shell Variables

Shell Variables (local):

my_var="local" bash # New shell echo $my_var # Empty!
Copied!

Environment Variables (global):

export APP_NAME="MyApp" export DB_PORT="5432" bash -c 'echo $APP_NAME' # Works!
Copied!

System Variables:

echo $HOME # Home directory echo $USER # Username echo $PATH # Command locations echo $PWD # Current directory
Copied!
Lab Exercise 2: App Configuration
Complete the commands to make these environment variables:
# Make these environment variables ___ APP_NAME="SuperApp" ___ APP_VERSION="1.0" # Verify with: env | grep APP
What command should you use in the blanks to create environment variables?
export
Creates environment variables accessible to child processes
Correct! The export command makes variables available to all child processes, creating environment variables.
set
Sets shell options and positional parameters
Incorrect. The set command is used for shell options, not for creating environment variables.
declare
Declares variables with specific attributes
Incorrect. While declare can create variables, it doesn't export them to the environment by default.
env
Displays environment variables
Incorrect. The env command displays environment variables but doesn't create them.

Special Variables

Variable Purpose
$? Last command exit status (0=success)
$$ Current process ID
$0 Script/shell name
$# Argument count
$USER Current username
$RANDOM Random number (0-32767)

Exit Status Example:

ls /etc/passwd echo $? # 0 (success) ls /not/exist 2>/dev/null echo $? # Non-zero (failure)
Copied!
Progress Check
Which special variable would you use to check if the previous command succeeded?
$?
Returns the exit status of the last command
Correct! $? contains the exit status of the most recently executed command. A value of 0 indicates success.
$$
Returns the current process ID
Incorrect. $$ returns the process ID of the current shell, not the exit status.
$#
Returns the number of arguments
Incorrect. $# returns the count of positional parameters passed to a script or function.
$0
Returns the name of the script or shell
Incorrect. $0 contains the name of the currently executing script or shell, not exit status.
