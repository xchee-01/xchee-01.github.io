MODULE 2: Joining Medical Datasets & Advanced Analysis

Real medical data lives in multiple tables - demographics, labs, medications. dplyr's join functions reunite this information like Electronic Health Records.

The Join Family 🔗

Learning Checkpoint
Which join function would you use to keep all patient records and add available lab data, even if some patients don't have lab results?
left_join()
Keep all patients, add available data
This is the most common join in medical data analysis!
Correct! left_join() keeps all records from the first table (patients) and adds matching data from the second table (labs). Missing labs will show as NA values.
inner_join()
Only complete records
Returns only patients who have lab results.
Not quite. inner_join() would exclude patients without lab results. We want to keep all patients, even those missing labs.
anti_join()
Find missing data
Used for quality control to find gaps.
That's not right. anti_join() would only return patients WITHOUT lab results. We want all patients with their lab data added where available.
full_join()
All records, matched or not
Keeps all records from both tables.
Close, but full_join() would also include lab results without matching patients. left_join() is more appropriate when you want to preserve all records from the primary table only.

Multi-Table Medical Data 📊

Let's work with a realistic medical data scenario involving multiple related tables:

# Patient demographics patients <- data.frame( patient_id = paste0("PT", 1001:1006), age = c(45, 52, 38, 61, 55, 49), gender = c("M", "F", "F", "M", "F", "M") ) # Lab results (PT1006 missing) lab_results <- data.frame( patient_id = paste0("PT", 1001:1005), glucose = c(95, 110, 88, 125, 102), creatinine = c(0.9, 1.1, 0.8, 1.3, 1.0) ) # Medications medications <- data.frame( patient_id = paste0("PT", 1001:1005), medication = c("Metformin", "Insulin", "None", "Metformin", "Glipizide"), dose_mg = c(500, 20, 0, 1000, 5) )

Join Operations in Action 🔄

Left Join - Most Common:

Code Understanding Check
After running this left_join code, what will happen to patient PT1006 who doesn't have lab results?
# Add labs to all patients patients_with_labs <- patients %>% left_join(lab_results, by = "patient_id") # Find missing labs missing_labs <- patients_with_labs %>% filter(is.na(glucose))
PT1006 will be included with NA values
The patient record is preserved, but glucose and creatinine will be NA.
Exactly right! left_join() keeps all patients from the first table. PT1006 will have their demographic data (age, gender) but NA values for glucose and creatinine.
PT1006 will be excluded
Only patients with lab results will be kept.
Not correct. That would be the behavior of inner_join(). left_join() keeps ALL records from the left table (patients).
An error will occur
The join will fail due to missing data.
Incorrect. Joins handle missing matches gracefully by inserting NA values. No error will occur.

Inner Join - Complete Records Only:

Join Strategy Check
How many patient records will remain after these inner joins?
complete_records <- patients %>% inner_join(lab_results, by = "patient_id") %>% inner_join(medications, by = "patient_id")
5 patients
Only PT1001-PT1005 have both labs and medications.
Perfect! PT1006 lacks lab results, so they're excluded by the first inner_join. Only PT1001-PT1005 have complete records across all three tables.
6 patients
All original patients will be included.
Not quite. inner_join() only keeps records that exist in BOTH tables. PT1006 has no lab results, so they're excluded.
0 patients
No patients have all data available.
Too pessimistic! Patients PT1001-PT1005 have records in all three tables and will be included.

Anti-Join - Quality Control:

Quality Control Check
What will the anti_join() operation return in this code?
# Who needs lab work? needs_labs <- patients %>% anti_join(lab_results, by = "patient_id")
Only PT1006
The one patient without lab results.
Excellent! anti_join() returns records from the first table that DON'T have matches in the second table. Perfect for finding gaps in data collection.
PT1001-PT1005
Patients who have lab results.
Backwards! anti_join() returns patients WITHOUT matches in lab_results. These patients already have labs.
All patients
Every patient needs new lab work.
Not correct. Only patients without existing lab results (PT1006) will be returned by anti_join().

Emergency Department Integration 🚨

ED Data Analysis
In this ED analysis, what does the waiting_patients dataframe identify?
# ED triage data ed_triage <- data.frame( patient_id = paste0("ED", 5001:5010), arrival_time = seq(as.POSIXct("2024-01-15 08:00"), by = "30 min", length.out = 10), chief_complaint = sample(c("Chest pain", "Shortness of breath", "Abdominal pain"), 10, replace = TRUE), triage_level = sample(1:5, 10, replace = TRUE) ) # ED vitals (some waiting) ed_vitals <- data.frame( patient_id = paste0("ED", 5001:5008), heart_rate = sample(60:120, 8), blood_pressure = sample(110:160, 8) ) # Complete ED analysis ed_analysis <- ed_triage %>% left_join(ed_vitals, by = "patient_id") %>% mutate( waiting_for_vitals = is.na(heart_rate), vitals_concern = heart_rate > 100 | blood_pressure > 140 ) # Patients needing attention waiting_patients <- ed_triage %>% anti_join(ed_vitals, by = "patient_id") %>% arrange(triage_level)
ED5009 and ED5010, sorted by priority
Patients who haven't had vitals taken yet, ordered by triage urgency.
Perfect! The anti_join identifies patients in triage without vitals (ED5009-5010), and arrange() sorts them by triage_level so the most urgent cases appear first.
All ED patients
Every patient currently in the emergency department.
Not right. anti_join() specifically finds patients WITHOUT vital signs recorded. Most patients (ED5001-5008) already have vitals.
Patients with abnormal vitals
Those with concerning heart rate or blood pressure.
That's what vitals_concern identifies in ed_analysis. waiting_patients finds those who haven't had vitals taken at all.

Clinical Impact: Real-time ED dashboards using these techniques help nurses identify patients awaiting assessment, reducing wait times and improving patient safety.

Cardiovascular Risk Assessment 💔

Risk Stratification Analysis
What does the pct_high_risk calculation tell us in this cardiovascular analysis?
# Multi-factor risk analysis set.seed(123) cardio_study <- data.frame( patient_id = paste0("CV", 3001:3030), age = sample(45:75, 30, replace = TRUE), gender = sample(c("Male", "Female"), 30, replace = TRUE), smoker = sample(c(TRUE, FALSE), 30, replace = TRUE, prob = c(0.3, 0.7)), cholesterol = round(rnorm(30, mean = 200, sd = 30)), systolic_bp = round(rnorm(30, mean = 130, sd = 15)) ) # Risk stratification risk_analysis <- cardio_study %>% mutate( risk_score = case_when( cholesterol > 240 & systolic_bp > 140 ~ "High", cholesterol > 200 | systolic_bp > 130 ~ "Moderate", TRUE ~ "Low" ) ) %>% group_by(gender, smoker) %>% summarize( n = n(), avg_cholesterol = mean(cholesterol), pct_high_risk = mean(risk_score == "High") * 100, .groups = 'drop' )
Percentage of high-risk patients by gender and smoking status
Shows risk distribution across demographic subgroups.
Exactly! The code calculates what percentage of patients in each gender-smoking combination have "High" cardiovascular risk, helping identify vulnerable populations.
Individual patient risk percentages
Each patient's personal risk score as a percentage.
Not quite. This is a grouped summary. It shows the percentage of patients classified as "High" risk within each group, not individual risk scores.
Average of all risk factors
Combined average of cholesterol and blood pressure.
Incorrect. pct_high_risk specifically counts the percentage of patients with risk_score == "High" in each group, not an average of values.

Clinical Dashboard Metrics 📊

Dashboard Metrics Check
What type of R object is ed_dashboard, and how would you access the number of critical patients?
# ED performance metrics ed_dashboard <- list( total_patients = nrow(ed_triage), critical_patients = sum(ed_triage$triage_level <= 2), awaiting_vitals = sum(is.na(ed_vitals$heart_rate)), avg_wait_time = mean(difftime(Sys.time(), ed_triage$arrival_time)) )
A list; access with ed_dashboard$critical_patients
Lists store mixed data types with named elements.
Perfect! Lists are ideal for dashboard metrics because they can store different data types (numbers, times) with meaningful names. Access elements using the $ operator.
A data frame; access with ed_dashboard[,"critical_patients"]
Data frames store tabular data.
Not correct. The code creates a list() not data.frame(). Lists are better for storing summary metrics of different types.
A vector; access with ed_dashboard[2]
Vectors store single data types.
Incorrect. Vectors can only store one data type, but this dashboard has numbers and time differences. It's a list with named elements.

dplyr Function Mastery
Match each dplyr function with its medical data analysis purpose:
filter() → Find diabetic patients with HbA1c > 7
Extract specific patient populations based on clinical criteria.
Correct! filter() is perfect for identifying patient subgroups based on clinical thresholds and diagnostic criteria.
select() → Find diabetic patients with HbA1c > 7
Choose which columns to include in analysis.
Not quite. select() chooses columns (variables), not rows (patients). Use filter() to find specific patients.
arrange() → Find diabetic patients with HbA1c > 7
Sort patients by clinical priority or values.
Incorrect. arrange() sorts data but doesn't filter it. You need filter() to identify specific patient groups.
