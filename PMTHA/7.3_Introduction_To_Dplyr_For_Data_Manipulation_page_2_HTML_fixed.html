Introduction to Joining Medical Datasets

In medical data analysis, information about a single patient often resides in multiple tables. Think of it like a patient's medical file - demographics in one section, lab results in another, medications in a third. The dplyr package provides a family of join functions that act like digital paperclips, connecting these separate pieces into a unified view.

The Join Family - Your Data Integration Toolkit

Each join function serves a specific purpose in medical data integration:

  • left_join(): Keeps all patients from your primary table and adds available information from other tables. This is your go-to function for most medical analyses.
  • inner_join(): Returns only patients with complete records across all joined tables. Useful when you need patients with all required data points.
  • anti_join(): Identifies patients missing from the second table. Perfect for quality control and finding data gaps.
  • full_join(): Keeps all records from both tables, whether matched or not. Less common but useful for comprehensive audits.

Left Join - The Clinical Analyst's Best Friend

The left_join() function is the workhorse of medical data analysis. It ensures you never lose a patient from your primary cohort while enriching their records with available additional data.

# Add labs to all patients patients_with_labs <- patients %>% left_join(lab_results, by = "patient_id") # Find missing labs missing_labs <- patients_with_labs %>% filter(is.na(glucose))

Not correct. That would be the behavior of inner_join(). left_join() keeps ALL records from the left table (patients).

Incorrect. Joins handle missing matches gracefully by inserting NA values. No error will occur.

Inner Join - When You Need Complete Records

Sometimes your analysis requires only patients with complete data across all sources. Inner joins are perfect for creating cohorts where all necessary data points are available.

Anti-Join - Your Data Quality Detective

Anti-joins are invaluable for quality control. They help identify missing data patterns, patients who need follow-up tests, or records that failed to merge properly.

Quality Control Check

The one patient without lab results.
Excellent! anti_join() returns records from the first table that DON'T have matches in the second table. Perfect for finding gaps in data collection.
PT1001-PT1005

Backwards! anti_join() returns patients WITHOUT matches in lab_results. These patients already have labs.
All patients

Not correct. Only patients without existing lab results (PT1006) will be returned by anti_join().

Real-World Medical Applications

Now let's apply our join skills to real healthcare scenarios. We'll explore emergency department operations, cardiovascular risk assessment, and clinical dashboard creation - three critical areas where data integration saves lives.

Emergency Department Integration

Emergency departments generate vast amounts of data across multiple systems. Triage information, vital signs, lab results, and treatment orders all need to be connected for effective patient care. Let's see how joins help create a real-time ED dashboard.

ED Data Analysis
In this ED analysis, what does the waiting_patients dataframe identify?
# ED triage data ed_triage <- data.frame( patient_id = paste0("ED", 5001:5010), arrival_time = seq(as.POSIXct("2024-01-15 08:00"), by = "30 min", length.out = 10), chief_complaint = sample(c("Chest pain", "Shortness of breath", "Abdominal pain"), 10, replace = TRUE), triage_level = sample(1:5, 10, replace = TRUE) ) # ED vitals (some waiting) ed_vitals <- data.frame( patient_id = paste0("ED", 5001:5008), heart_rate = sample(60:120, 8), blood_pressure = sample(110:160, 8) ) # Complete ED analysis ed_analysis <- ed_triage %>% left_join(ed_vitals, by = "patient_id") %>% mutate( waiting_for_vitals = is.na(heart_rate), vitals_concern = heart_rate > 100 | blood_pressure > 140 ) # Patients needing attention waiting_patients <- ed_triage %>% anti_join(ed_vitals, by = "patient_id") %>% arrange(triage_level)
ED5009 and ED5010, sorted by priority
Patients who haven't had vitals taken yet, ordered by triage urgency.
Perfect! The anti_join identifies patients in triage without vitals (ED5009-5010), and arrange() sorts them by triage_level so the most urgent cases appear first.
All ED patients
Every patient currently in the emergency department.
Not right. anti_join() specifically finds patients WITHOUT vital signs recorded. Most patients (ED5001-5008) already have vitals.
Patients with abnormal vitals
Those with concerning heart rate or blood pressure.
That's what vitals_concern identifies in ed_analysis. waiting_patients finds those who haven't had vitals taken at all.

Clinical Impact: Real-time ED dashboards using these techniques help nurses identify patients awaiting assessment, reducing wait times and improving patient safety. Studies show that integrated ED data systems can reduce average wait times by 15-20% and improve patient satisfaction scores.

Cardiovascular Risk Assessment

Cardiovascular disease remains the leading cause of death globally. By combining multiple risk factors - demographics, lab values, lifestyle factors, and medications - we can stratify patients and guide preventive interventions.

Risk Stratification Analysis
What does the pct_high_risk calculation tell us in this cardiovascular analysis?
# Multi-factor risk analysis set.seed(123) cardio_study <- data.frame( patient_id = paste0("CV", 3001:3030), age = sample(45:75, 30, replace = TRUE), gender = sample(c("Male", "Female"), 30, replace = TRUE), smoker = sample(c(TRUE, FALSE), 30, replace = TRUE, prob = c(0.3, 0.7)), cholesterol = round(rnorm(30, mean = 200, sd = 30)), systolic_bp = round(rnorm(30, mean = 130, sd = 15)) ) # Risk stratification risk_analysis <- cardio_study %>% mutate( risk_score = case_when( cholesterol > 240 & systolic_bp > 140 ~ "High", cholesterol > 200 | systolic_bp > 130 ~ "Moderate", TRUE ~ "Low" ) ) %>% group_by(gender, smoker) %>% summarize( n = n(), avg_cholesterol = mean(cholesterol), pct_high_risk = mean(risk_score == "High") * 100, .groups = 'drop' )
Percentage of high-risk patients by gender and smoking status
Shows risk distribution across demographic subgroups.
Exactly! The code calculates what percentage of patients in each gender-smoking combination have "High" cardiovascular risk, helping identify vulnerable populations.
Individual patient risk percentages
Each patient's personal risk score as a percentage.
Not quite. This is a grouped summary. It shows the percentage of patients classified as "High" risk within each group, not individual risk scores.
Average of all risk factors
Combined average of cholesterol and blood pressure.
Incorrect. pct_high_risk specifically counts the percentage of patients with risk_score == "High" in each group, not an average of values.

Lab Exercise 3: Complete Emergency Department Dashboard

Create a comprehensive ED analysis that the charge nurse can use to allocate resources effectively. Combine triage data with vitals to identify patients needing immediate attention.

# Lab scenario: Create comprehensive ED dashboard # Replace the ... with appropriate code # Step 1: Join all ED data and calculate metrics ed_complete <- ed_triage %>% ...(ed_vitals, by = "patient_id") %>% mutate( wait_time_min = as.numeric(difftime(..., arrival_time, units = "mins")), urgency_score = case_when( triage_level == 1 & is.na(heart_rate) ~ "...", triage_level <= 2 & (heart_rate > 120 | blood_pressure > 160) ~ "Critical", triage_level <= 3 & is.na(heart_rate) ~ "...", TRUE ~ "Stable" ) ) # Step 2: Create summary dashboard ed_summary <- list( total_patients = nrow(ed_complete), critical_count = sum(ed_complete$urgency_score == "..."), avg_wait_critical = mean(ed_complete$wait_time_min[ed_complete$triage_level <= 2], na.rm = TRUE), patients_without_vitals = ...(ed_complete$heart_rate) ) # Step 3: Priority list for nursing staff priority_list <- ed_complete %>% filter(urgency_score %in% c("...", "...")) %>% arrange(..., wait_time_min) %>% select(patient_id, chief_complaint, triage_level, wait_time_min, urgency_score)
