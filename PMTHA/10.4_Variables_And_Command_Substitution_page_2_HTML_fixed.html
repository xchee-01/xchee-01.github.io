Command Substitution Basics

Capture command output in variables:

# Modern way (preferred) current_date=$(date) file_count=$(ls | wc -l) # Classic way (avoid) current_date=`date`
Copied!
Learning Checkpoint
Which of these correctly creates a variable with a nested command substitution for creating a backup filename?
# Nesting works! backup="backup_$(date +%Y%m%d)_$(hostname).tar"
backup=`backup_`date +%Y%m%d`_`hostname`.tar`
Using backticks with nesting
Incorrect. Backticks don't handle nesting well and this syntax would cause errors. The modern $() syntax is much better for nested substitutions.
backup="backup_$(date +%Y%m%d)_$(hostname).tar"
Using $() for both substitutions
Correct! The $() syntax handles nesting cleanly and is the modern, preferred way to do command substitution in bash.
backup="backup_$date +%Y%m%d_$hostname.tar"
Direct variable substitution without command execution
Incorrect. This would literally insert the text "date +%Y%m%d" instead of executing the date command. You need $() to execute commands.
backup=(backup_$(date +%Y%m%d)_$(hostname).tar)
Using parentheses around the entire value
Incorrect. Parentheses around the value would create an array instead of a simple string variable. For a single string, quotes are sufficient.

Learning Checkpoint
Which command correctly captures the system's IP address into a variable?
# System Information: MEM_USED=$(free -m | grep Mem | awk '{print $3}') CPU_LOAD=$(uptime | awk -F'average:' '{print $2}') MY_IP=$(hostname -I | awk '{print $1}')
MY_IP=hostname -I
Direct assignment without command substitution
Incorrect. This would set MY_IP to the literal string "hostname" and try to execute "-I" as a command, causing an error.
MY_IP=${hostname -I}
Using ${} syntax for command substitution
Incorrect. The ${} syntax is for variable expansion, not command substitution. You need $() to execute commands.
MY_IP=$(hostname -I | awk '{print $1}')
Using command substitution with pipe to extract first IP
Correct! This executes hostname -I to get all IPs, then uses awk to extract just the first one, capturing it in the MY_IP variable.
MY_IP="$(hostname) -I"
Partial command substitution with -I outside
Incorrect. This would get the hostname and append the literal string " -I" to it, not execute hostname -I as a single command.

Lab Exercise 3: System Reporter

Complete the System Reporter Script
Fill in the blanks to complete this system information reporter script:
# Basic info HOSTNAME=$(_____) # Get hostname KERNEL=$(uname -___) # Kernel version UPTIME=$(uptime | awk '{print $3}') # Resource usage MEM_PCT=$(free | grep Mem | awk '{print int($3/$2*100)}') DISK_PCT=$(df -h / | tail -1 | awk '{print $5}') # Generate report cat > report.txt << EOF System: $HOSTNAME Kernel: $KERNEL Memory: ${MEM_PCT}% Disk: $DISK_PCT EOF
hostname and r
hostname for system name, -r for kernel release
Correct! The hostname command gets the system's name, and uname -r displays the kernel release version.
whoami and v
whoami for current user, -v for version
Incorrect. whoami shows the current user, not the hostname. uname -v shows kernel version date, not the release number.
echo $HOSTNAME and a
Use environment variable, -a for all info
Incorrect. While $HOSTNAME might work in some shells, hostname is more portable. uname -a gives all info, but we want just the kernel release.
host and s
host command, -s for system
Incorrect. The host command is for DNS lookups, not getting the local hostname. uname -s shows the kernel name (e.g., Linux), not the version.

Advanced Techniques

Understanding Nested Substitution
What does this nested command substitution do?
# Find busiest user BUSY=$(ps aux | awk '{print $1}' | sort | uniq -c | sort -nr | head -1)
Finds the process using most CPU
Identifies single process with highest CPU usage
Incorrect. This command counts processes per user, not CPU usage. It finds the user with the most processes running.
Finds user with most processes
Identifies which user has the most running processes
Correct! The pipeline extracts usernames, counts occurrences with uniq -c, sorts numerically in reverse order, and takes the top result - showing the user with the most processes.
Finds longest-running process
Identifies process that has been running the longest
Incorrect. This command counts processes by user, not runtime. It doesn't examine how long processes have been running.
Lists all users sorted by name
Shows alphabetically sorted list of users
Incorrect. The sort -nr sorts by count numerically in reverse order (highest first), not alphabetically by username.

# Backup recent configs for config in $(find /etc -name "*.conf" -mtime -1); do cp "$config" "/backup/$(basename "$config").bak" done

Error Handling Best Practices
What's the purpose of the error handling in this code?
# Safe with fallback IP=$(hostname -I 2>/dev/null) if [ -z "$IP" ]; then IP=$(ip addr show | grep "inet " | head -1) fi
Provides fallback if first command fails
Uses alternative method when hostname -I doesn't work
Correct! This pattern tries hostname -I first, suppresses errors with 2>/dev/null, and if the result is empty, falls back to parsing ip addr show output.
Validates IP address format
Checks if the IP address is valid format
Incorrect. The -z test only checks if the variable is empty, not if it contains a valid IP address format.
Prevents duplicate IP addresses
Ensures unique IP address assignment
Incorrect. This code is about retrieving the system's IP address with a fallback method, not preventing duplicates.
Filters out IPv6 addresses
Only captures IPv4 addresses
Incorrect. While grep "inet " might filter IPv6 (inet6), that's not the primary purpose. The main goal is providing a fallback method.

Lab Exercise 4: System Monitor

Understanding System Monitoring
What does this system monitoring script accomplish?
# Find resource hogs CPU_HOG=$(ps aux | sort -k3 -nr | head -1 | awk '{print $11}') MEM_HOG=$(ps aux | sort -k4 -nr | head -1 | awk '{print $11}') # Disk alerts for fs in $(df -h | grep -v Filesystem | awk '{print $6}'); do USAGE=$(df -h "$fs" | tail -1 | awk '{print $5}' | tr -d '%') if [ "$USAGE" -gt 80 ]; then echo "Warning: $fs is ${USAGE}% full" fi done
Identifies top CPU/memory processes and checks disk usage
Finds resource-intensive processes and warns about full disks
Correct! The script finds the processes using the most CPU (sort -k3) and memory (sort -k4), then checks all filesystems and warns if any are over 80% full.
Kills processes using too many resources
Automatically terminates resource-heavy processes
Incorrect. The script only identifies and reports resource usage. It doesn't take any action to kill or stop processes.
Creates backup of system logs
Archives system monitoring data
Incorrect. This script monitors current system state but doesn't create any backups or archives. It only displays warnings.
Optimizes disk space automatically
Cleans up filesystems approaching capacity
Incorrect. The script only reports disk usage over 80%. It doesn't perform any cleanup or optimization actions.

Quick Reference

Special Variables Knowledge Check
Match the special variable with its purpose:
# Variables name="value" # Create echo $name # Use export name="value" # Environment # Special $? # Exit status $$ # Process ID $# # Arg count $@ # All args # Substitution result=$(command) # Modern way timestamp=$(date +%Y%m%d)
$? stores the process ID of the last command
Returns PID of previous process
Incorrect. $? stores the exit status (0 for success, non-zero for failure) of the last command, not its process ID.
$# shows the number of arguments passed to the script
Counts positional parameters
Correct! $# contains the count of arguments passed to the script or function, useful for validating input.
$$ returns all arguments as a single string
Concatenates all parameters
Incorrect. $$ returns the current shell's process ID. $@ returns all arguments (properly separated), while $* returns them as a single string.
$@ counts the number of running processes
Shows process count
Incorrect. $@ expands to all positional parameters passed to the script, properly preserving spaces and special characters.
