Section 3: Copying with `cp` - Your Safety Net

The cp command is your insurance policy against mistakes!

Basic Copy Operations

# Copy a file user@hostname:~$ cp original_data.csv backup_data.csv # Copy to different directory user@hostname:~$ cp analysis.py /tmp/analysis_backup.py
Copied!
Preserving File Attributes with -p
When copying configuration files, which approach preserves permissions and timestamps?
# Bad practice - loses permissions user@hostname:~$ sudo cp /etc/nginx/nginx.conf nginx.backup # Good practice - preserves everything user@hostname:~$ sudo cp -p /etc/nginx/nginx.conf nginx.backup # Check preservation user@hostname:~$ ls -la nginx.backup -rw-r--r-- 1 root root 1482 Jan 20 11:00 nginx.backup
cp without flags
Simple copy command without preservation options.
Without the -p flag, cp creates new files with default permissions and current timestamps, losing important metadata from the original file.
cp -p
Copy with preservation of mode, ownership, and timestamps.
Correct! The -p flag preserves the original file's permissions, ownership, and timestamps - crucial for system configuration files and backups.
sudo alone is enough
Using sudo automatically preserves all attributes.
sudo only gives you permission to read protected files - it doesn't automatically preserve attributes. You still need the -p flag for preservation.

Copying Directories Recursively

# This FAILS for directories user@hostname:~$ cp my_project my_project_backup cp: omitting directory 'my_project' # Use -r flag user@hostname:~$ cp -r my_project my_project_backup # Better - preserve attributes too user@hostname:~$ cp -rp my_project my_project_$(date +%Y%m%d)
Copied!

Pro Tip: $(date +%Y%m%d) adds today's date to backups!

Advanced Copy Features
Which cp flag would you use to avoid accidentally overwriting important files?
# Interactive mode - asks before overwriting user@hostname:~$ cp -i important.txt destination/ cp: overwrite 'destination/important.txt'? y # Verbose mode - shows progress user@hostname:~$ cp -v *.py python_files/ 'analysis.py' -> 'python_files/analysis.py' 'model.py' -> 'python_files/model.py' # Update only if newer user@hostname:~$ cp -u *.conf /etc/myapp/
-i (interactive)
Prompts before overwriting existing files.
Perfect! The -i flag makes cp ask for confirmation before overwriting files, preventing accidental data loss.
-v (verbose)
Shows detailed progress of copying operations.
While -v is useful for seeing what's being copied, it doesn't prevent overwrites. Use -i for safety confirmation prompts.
-u (update)
Only copies when source is newer than destination.
The -u flag only copies newer files, but it still overwrites without asking. Use -i for interactive confirmation.
-f (force)
Forces copy operation without prompts.
Careful! The -f flag removes existing destination files if needed - the opposite of what you want for safety!

Real-World Example: Pre-Update Backup

# Backup before updating user@hostname:~$ sudo cp -rp /etc/myapp /etc/myapp.backup.$(date +%Y%m%d_%H%M%S) # Create backup script user@hostname:~$ cat > backup_configs.sh << 'EOF' #!/bin/bash BACKUP_DIR="/backup/configs/$(date +%Y%m%d)" mkdir -p "$BACKUP_DIR" cp -rp /etc/nginx "$BACKUP_DIR/" cp -rp /etc/mysql "$BACKUP_DIR/" echo "Backup completed to $BACKUP_DIR" EOF
Copied!
Practice Exercise: 3-2-1 Backup Strategy
What is the correct implementation of the 3-2-1 backup rule for genome_analysis_final.dat?
Create timestamped copies on local, USB, and cloud
Use cp -p with timestamps to ./backups, /mnt/usb, and /mnt/cloud directories.
Excellent! This follows the 3-2-1 rule: 3 copies total, 2 different storage media (local + USB), and 1 offsite (cloud). Using timestamps prevents overwriting previous backups.
Make 3 copies in the same directory
Create file_1.dat, file_2.dat, file_3.dat in the current directory.
This violates the 3-2-1 rule! All copies are on the same storage medium. You need different storage types and at least one offsite backup.
Copy to /tmp for temporary backup
Use cp to create backups in /tmp directory.
Never use /tmp for backups! It's cleared on reboot. You need permanent storage locations across different media types.

🔧 Practice Exercise: 3-2-1 Backup Strategy

Implement the 3-2-1 backup rule for genome_analysis_final.dat:

  • 3 copies total
  • 2 different storage media
  • 1 offsite backup

Solution:

# Create directories mkdir -p ./backups /mnt/usb /mnt/cloud # Create timestamped backups TIMESTAMP=$(date +%Y%m%d_%H%M%S) cp -p genome_analysis_final.dat ./backups/genome_analysis_final_${TIMESTAMP}.dat cp -p genome_analysis_final.dat /mnt/usb/genome_analysis_final_${TIMESTAMP}.dat cp -p genome_analysis_final.dat /mnt/cloud/genome_analysis_final_${TIMESTAMP}.dat
Copied!

Section 4: Moving with `mv` - The Transformer

The mv command moves and renames files - no duplicates created!

Basic Move and Rename

# Simple rename user@hostname:~$ mv old_name.txt new_name.txt # Move to directory user@hostname:~$ mv download.zip ~/Documents/software/ # Move AND rename user@hostname:~$ mv draft_v1.txt ~/Documents/final_report_2024.txt
Copied!
Understanding Atomic Operations
What's the difference between moving files on the same filesystem vs. across filesystems?
# On same filesystem - atomic and safe user@hostname:~$ mv large_database.db /var/lib/mysql/production.db # Across filesystems - actually copies then deletes user@hostname:~$ mv /home/user/file.txt /mnt/external/file.txt
Same filesystem is instant, cross-filesystem copies then deletes
Within same filesystem, mv just updates directory entries. Across filesystems, it must copy data then remove original.
Correct! On the same filesystem, mv is atomic and instant - it just updates the file's location in the directory structure. Across filesystems, it performs cp followed by rm, which takes time and isn't atomic.
Both operations are identical
The mv command works the same way regardless of filesystem boundaries.
Not true! Moving within the same filesystem is much faster and atomic. Cross-filesystem moves require copying all data, which can fail partway through.
Cross-filesystem moves are faster
Moving between different filesystems is optimized for speed.
Actually the opposite! Cross-filesystem moves are slower because they must copy all data to the new location before deleting the original.

Batch Operations

# Move all logs user@hostname:~$ mv *.log archive/ # Rename multiple files user@hostname:~$ for file in *.txt; do mv "$file" "${file%.txt}.backup" done
Copied!

Real-World Example: Log Rotation

# Create rotation script user@hostname:~$ cat > rotate_logs.sh << 'EOF' #!/bin/bash LOG_DIR="/var/log/myapp" ARCHIVE_DIR="$LOG_DIR/archive" mkdir -p "$ARCHIVE_DIR" if [ -f "$LOG_DIR/app.log" ]; then mv "$LOG_DIR/app.log" "$ARCHIVE_DIR/app_$(date +%Y%m%d_%H%M%S).log" touch "$LOG_DIR/app.log" echo "Log rotated successfully" fi EOF
Copied!
Interactive Safety
Which mv flag helps prevent accidental overwrites?
# Ask before overwriting user@hostname:~$ mv -i important.doc ~/Documents/ mv: overwrite '/home/user/Documents/important.doc'? n # Verbose mode user@hostname:~$ mv -v *.pdf ~/Documents/PDFs/ 'report1.pdf' -> '/home/user/Documents/PDFs/report1.pdf'
-i (interactive)
Prompts before overwriting existing files.
Perfect! Just like with cp, the -i flag makes mv ask for confirmation before overwriting files.
-v (verbose)
Shows what files are being moved.
The -v flag shows progress but doesn't prevent overwrites. Use -i for safety prompts.
-n (no-clobber)
Never overwrites existing files.
While -n prevents overwrites entirely, -i is more flexible as it lets you choose whether to overwrite on a case-by-case basis.

Section 5: Removing with `rm` - The Precision Tool

The rm command requires respect - there's no Recycle Bin!

Safety Rules First!
Which is the MOST important safety practice when using rm?
# Add to ~/.bashrc user@hostname:~$ echo "alias rm='rm -i'" >> ~/.bashrc user@hostname:~$ source ~/.bashrc
Always ls before rm
Check what you're about to delete by listing files first.
Excellent! Always verify what you're about to delete. This simple habit prevents most rm disasters. The other practices are important too, but this is the foundation.
Use rm -f for efficiency
Force flag speeds up deletion without prompts.
Dangerous advice! The -f flag bypasses all safety checks. Speed should never compromise safety when deleting files.
Only delete as root
Use sudo for all deletions to ensure permission.
This increases risk! Only use sudo when necessary. Running rm as root can delete critical system files.

Safety Rules:

  1. Always ls before rm
  2. Use -i for confirmation
  3. Never rm -rf /
  4. Create safety aliases

Basic Removal

# Remove single file user@hostname:~$ rm unwanted.txt # Remove with confirmation user@hostname:~$ rm -i important.txt rm: remove regular file 'important.txt'? n # Remove pattern user@hostname:~$ rm *.tmp
Copied!
Directory Removal
What's the difference between rmdir and rm -r?
# Empty directory only user@hostname:~$ rmdir empty_folder/ # Directory with contents user@hostname:~$ rm -r project_folder/ # Force removal user@hostname:~$ rm -rf stubborn_folder/ # Verbose removal user@hostname:~$ rm -rv old_project/ removed 'old_project/file1.txt' removed directory 'old_project/'
rmdir only removes empty directories
rmdir fails if directory contains any files, rm -r removes everything.
Correct! rmdir is safer as it only removes empty directories. rm -r recursively deletes everything inside, making it more powerful but also more dangerous.
They work identically
Both commands remove directories the same way.
Not true! rmdir is much more limited - it only removes empty directories, while rm -r removes directories and all their contents.
rm -r is safer
rm -r provides more safety checks than rmdir.
Actually the opposite! rmdir is safer because it refuses to delete non-empty directories, preventing accidental data loss.

Safe Cleanup Techniques

# Find and remove old files user@hostname:~$ find . -name "*.bak" -mtime +30 -exec rm {} \; # Create trash function user@hostname:~$ mkdir -p ~/.trash user@hostname:~$ trash() { mv "$@" ~/.trash/; } user@hostname:~$ trash important.txt # Moved, not deleted!
Copied!
Horror Stories to Avoid!
What's wrong with this command: rm -rf / home/user/temp?
# DON'T: Space in wrong place user@hostname:~$ rm -rf / home/user/temp # DISASTER! # DO: Correct path user@hostname:~$ rm -rf /home/user/temp # DON'T: Unquoted variables FILE="my file.txt" rm $FILE # Tries to remove 'my' and 'file.txt' # DO: Quote variables rm "$FILE" # Correctly removes 'my file.txt'
Space after / creates two arguments
The command tries to delete / (root) and home/user/temp separately!
Exactly! The space makes rm see two separate arguments: "/" (the entire filesystem!) and "home/user/temp". This is why careful typing and checking commands is crucial.
Nothing, it's a valid command
This will correctly remove the temp directory.
This is extremely dangerous! The space creates two arguments, and the first one is "/" - the root of your entire filesystem!
Missing sudo
The command needs sudo to work properly.
The problem isn't permissions - it's the accidental space that turns this into a system-destroying command!
Practice Exercise: Lab Cleanup Protocol
What's the correct order for safely cleaning up after experiments?

Tasks:

  1. Remove .tmp files older than 7 days
  2. Delete empty directories
  3. Keep only critical.log
Backup first, then clean systematically
Create backups, then use find commands to remove files safely.
Perfect! Always backup before cleanup. Then use find with specific criteria to safely remove only what's intended. This methodical approach prevents data loss.
Use rm -rf * then restore critical.log
Delete everything, then copy back what you need.
Very risky! You might not be able to restore files after deletion. Always use targeted removal commands instead of wholesale deletion.
Delete directories first
Remove empty directories before cleaning files.
Wrong order! Remove files first, then empty directories. You can't remove directories that still contain files.

Combined Operations

Real-world scripts combine all commands:

#!/bin/bash # Project reorganization PROJECT="genome_analysis" DATE=$(date +%Y%m%d) # Backup cp -rp "$PROJECT" "${PROJECT}_backup_${DATE}" # Create structure mkdir -p "$PROJECT"/{data/{raw,processed},scripts,docs,logs} # Organize files mv "$PROJECT"/*.py "$PROJECT/scripts/" 2>/dev/null mv "$PROJECT"/*.csv "$PROJECT/data/raw/" 2>/dev/null mv "$PROJECT"/*.log "$PROJECT/logs/" 2>/dev/null # Cleanup find "$PROJECT" -name "*.tmp" -delete echo "Reorganization complete!" tree "$PROJECT"
Copied!
Quick Reference
Which command needs the -r flag to work with directories?
Command Purpose Key Flags Safety Tip
cp Copy files -r, -p, -i Use -p for attributes
mv Move/rename -i, -v No -r needed
rm Remove files -r, -f, -i Alias to rm -i
Both cp and rm need -r for directories
cp -r and rm -r are required for directory operations.
Correct! Both cp and rm need the -r (recursive) flag to work with directories. Interestingly, mv doesn't need -r because it just updates the directory entry.
Only rm needs -r
Just rm requires the recursive flag.
Actually, cp also needs -r to copy directories. Try cp without -r on a directory and it will fail.
All three commands need -r
cp, mv, and rm all require -r for directories.
Not quite! The mv command doesn't need -r because it just updates the filesystem's directory structure rather than recursively processing contents.
