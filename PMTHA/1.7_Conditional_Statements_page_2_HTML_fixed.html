Section 4: Nested Conditionals - Complex Medical Logic

Sometimes medical decisions have layers - like checking if a patient qualifies for a clinical trial. They must meet age requirements AND have specific conditions AND not have exclusion criteria.

Nesting in Action

# Clinical trial eligibility checker # ================================== age = 45 has_diabetes = True has_heart_disease = False on_insulin = True if age >= 18 and age <= 65: print("✅ Age criteria met") if has_diabetes: print("✅ Has target condition") if not has_heart_disease: print("✅ No exclusion criteria") if on_insulin: print("🎯 ELIGIBLE for insulin optimization trial") else: print("❌ Not eligible - must be on insulin") else: print("❌ Not eligible - heart disease excludes participation") else: print("❌ Not eligible - diabetes required") else: print("❌ Not eligible - age outside 18-65 range")
Copied!

💡 Tip Box: Each nested level adds another "layer" of decision-making. Think of it like a medical checklist where you only proceed if each item passes!

Simplifying Nested Logic

Sometimes we can flatten nested conditions:

# Same logic, cleaner approach # ============================ if age < 18 or age > 65: print("❌ Not eligible - age requirement not met") elif not has_diabetes: print("❌ Not eligible - must have diabetes") elif has_heart_disease: print("❌ Not eligible - heart disease is exclusionary") elif not on_insulin: print("❌ Not eligible - must be on insulin") else: print("🎯 ELIGIBLE for clinical trial!")
Copied!

Section 5: Boolean Logic - Combining Medical Conditions

Medical decisions often involve multiple factors. A stroke risk assessment might consider age AND blood pressure AND smoking status. Let's master combining conditions!

Logical Operators in Medicine

# Stroke risk assessment # ====================== age = 65 systolic_bp = 145 is_smoker = True has_diabetes = True # High risk if: age > 60 AND (high BP OR smoker) # ============================================== high_risk = age > 60 and (systolic_bp > 140 or is_smoker) if high_risk: print("⚠️ HIGH STROKE RISK") print("Immediate preventive measures recommended")
Copied!

Boolean Operator Reference

  • and: Both conditions must be True
  • or: At least one condition must be True
  • not: Reverses the truth value

Incremental scoring approach
Initialize score to 0, then add 1 for each met criterion, finally check if score ≥ 2.
Excellent! The correct approach is to start with score = 0, then check each criterion individually and add 1 to the score if the criterion is met. This allows for clear tracking of which criteria contribute to the final score.
Single boolean expression
Use one complex boolean expression to check all conditions at once.
Not the best approach. While you could use boolean logic, you need to count how many criteria are met, not just check if any are true. A scoring system requires tracking individual points.
Nested if statements only
Use nested if statements to check each condition in sequence.
Not ideal. Nested if statements would create unnecessary complexity. Since each criterion contributes independently to the score, they should be checked separately, not in a nested structure.
List comprehension
Use advanced Python list comprehension to calculate the score.

Section 6: Truthiness - Validating Medical Data

In medical programming, we often need to check if data exists before using it. Python's concept of "truthiness" helps us validate medical records elegantly.

Understanding Truthiness

# Empty values are "falsy" # ======================== patient_name = "" patient_id = None test_results = [] vital_signs = {} if patient_name: print("Patient name recorded") else: print("⚠️ Patient name missing") if test_results: print("Test results available") else: print("⚠️ No test results yet")
Copied!

Practical Medical Data Validation

# Checking medical record completeness # ==================================== patient_record = { "name": "Jane Doe", "age": 45, "allergies": ["penicillin"], "medications": [], "emergency_contact": "" } # Check each field # ================ if patient_record.get("name"): print("✅ Name recorded") else: print("❌ Name missing") if patient_record.get("allergies"): print("✅ Allergy information recorded") print(f" Allergies: {', '.join(patient_record['allergies'])}") else: print("⚠️ No allergy information") if patient_record.get("medications"): print("✅ Current medications listed") else: print("📝 No current medications") if patient_record.get("emergency_contact"): print("✅ Emergency contact available") else: print("❌ CRITICAL: No emergency contact!")

🧪 Lab Exercise 6: Lab Result Validator (Difficulty: ⭐⭐)

Create a system that validates lab results before processing:

Lab Result Validation Challenge
Validate lab results before analysis. Check if all required values are present and valid (not None, not 0 for numeric values). Only process if data is complete.
# TODO: Validate lab results before analysis # ========================================== # Check if all required values are present # ======================================== # Only process if data is complete # ================================ lab_results = { "glucose": 95, "cholesterol": 0, # 0 means not measured "blood_pressure": "120/80", "hemoglobin": None } # Your code here: # =============== # Check each result and determine if analysis can proceed # ==================================================
Copied!
Track missing and valid tests separately
Create lists to track which tests are missing and which are valid, then report findings.
Perfect! The best approach is to maintain separate lists for missing and valid tests. This allows you to provide detailed feedback about what's available and what needs to be collected before proceeding with analysis.
Single boolean flag
Use a single boolean variable to track if all tests are complete.
Not ideal. While a boolean flag could tell you if data is complete, it wouldn't provide information about which specific tests are missing, making it harder to guide the user on what needs to be collected.
Exception handling
Use try-except blocks to handle missing or invalid values.
Not the right approach here. Exception handling is for unexpected errors, but checking for None or 0 values is normal validation that should be done with conditional statements, not exceptions.
Direct processing
Process all values directly and let Python handle any issues.
Dangerous approach! Processing invalid or missing lab values could lead to incorrect medical conclusions. Always validate medical data before processing to ensure patient safety.

Solution:

lab_results = { "glucose": 95, "cholesterol": 0, # 0 means not measured "blood_pressure": "120/80", "hemoglobin": None } # Track completeness # ================== missing_tests = [] valid_results = [] # Check each test # =============== if lab_results.get("glucose") and lab_results["glucose"] > 0: valid_results.append("glucose") else: missing_tests.append("glucose") if lab_results.get("cholesterol") and lab_results["cholesterol"] > 0: valid_results.append("cholesterol") else: missing_tests.append("cholesterol") if lab_results.get("blood_pressure"): valid_results.append("blood_pressure") else: missing_tests.append("blood_pressure") if lab_results.get("hemoglobin"): valid_results.append("hemoglobin") else: missing_tests.append("hemoglobin") # Report findings # =============== if not missing_tests: print("✅ All lab results complete - proceeding with analysis") else: print("⚠️ Incomplete lab results") print(f"Missing: {', '.join(missing_tests)}") print(f"Available: {', '.join(valid_results)}") print("\nRecommendation: Request missing tests before full analysis")
Copied!

Excellent work! You've built a data validation system that ensures medical accuracy! 🎯

Congratulations! You've mastered the essential decision-making tools used in medical programming:

🔧 Your New Skills:

💡 Final Tip Box: Remember, every if statement in medical software could impact patient care. Always consider:

  • What happens if the condition is True?
  • What happens if it's False?
  • Are there edge cases to handle?
  • Is the logic clear for other developers (and future you)?
