6.4.6. Lists - Your Digital Medical Folder

While vectors store single data types, real medical records need mixed data. Lists are R's solution for comprehensive patient records.

Creating Electronic Health Records

patient_record <- list( id = "PT2024-001", age = 45, conditions = c("Type 2 Diabetes", "Hypertension"), lab_results = c(glucose = 126, hba1c = 7.2, bp_systolic = 145), medications = c("Metformin 1000mg", "Lisinopril 10mg"), on_medication = TRUE ) # Access with $ operator print(patient_record$age) # 45 print(patient_record$lab_results["hba1c"]) # 7.2
Copied!
Learning Checkpoint
To access the patient's age from the patient_record list, which syntax is correct?
patient_record[age]
Use bracket notation without quotes
Not quite. This syntax would cause an error because 'age' without quotes is treated as an object name, not a list element name.
patient_record$age
Use the dollar sign operator
Correct! The $ operator is the standard way to access named elements in an R list. It's intuitive and widely used in medical data analysis.
patient_record.age
Use dot notation like other languages
Incorrect. R doesn't use dot notation for list access like Python or JavaScript. Use the $ operator instead.
patient_record("age")
Use parentheses with the element name
That's not right. Parentheses are used for function calls, not list element access in R.
Learning Checkpoint
Which statement about lists in R is TRUE?
Lists can only store numeric values
Lists are restricted to numbers
Incorrect. Lists are much more versatile - they can store any type of R object including characters, logicals, and even other lists!
Lists must contain elements of the same data type
All elements must be homogeneous
Not correct. This describes vectors, not lists. Lists can mix different data types, which makes them perfect for patient records.
Lists can store mixed data types including vectors, numbers, and logical values
Lists allow heterogeneous data storage
Correct! This flexibility makes lists ideal for medical records where you need to combine patient IDs (character), ages (numeric), test results (numeric vectors), and treatment status (logical).
Lists cannot contain other lists as elements
Nested lists are not allowed
False. Lists can contain other lists, creating nested structures perfect for organizing complex medical data hierarchies.

Learning Checkpoint
To access the patient's age in the cancer_patient list, which syntax would you use?
cancer_patient$age
Direct access to age
Not quite. Age is nested inside the demographics sub-list, so you need to navigate through that first.
cancer_patient$demographics$age
Navigate through nested structure
Correct! You need to access the demographics list first, then the age element within it. This nested structure helps organize related patient data.
cancer_patient["demographics"]["age"]
Use bracket notation with quotes
This syntax returns a list, not the value. Use [[]] or $ for direct element access in nested lists.
cancer_patient.demographics.age
Use dot notation throughout
R doesn't support dot notation for list access. Use the $ operator for each level of nesting.

Real-World Connection: Major cancer centers use nested list structures in R to manage comprehensive patient profiles, combining demographic data, tumor characteristics, treatment histories, and genomic profiles in a single, organized data structure.

6.4.7. Matrices - Clinical Trial Command Center

Matrices organize 2D data where:

  • Rows = Patients
  • Columns = Measurements
  • All values same type

Clinical Trial Example

# Vital signs for 5 patients vital_signs <- matrix( c(120, 80, 98.6, # Patient 1 135, 85, 99.1, # Patient 2 128, 82, 98.4, # Patient 3 142, 90, 98.8, # Patient 4 118, 75, 97.9), # Patient 5 nrow = 5, ncol = 3, byrow = TRUE, dimnames = list( c("Patient1", "Patient2", "Patient3", "Patient4", "Patient5"), c("BP_Systolic", "BP_Diastolic", "Temperature") ) ) # Access specific data patient3_bp <- vital_signs["Patient3", c("BP_Systolic", "BP_Diastolic")] avg_systolic <- mean(vital_signs[, "BP_Systolic"])
Copied!
Learning Checkpoint
What does the parameter byrow = TRUE do when creating a matrix?
Sorts the data by row names
Orders rows alphabetically
Incorrect. This parameter doesn't sort data; it controls how the input vector fills the matrix structure.
Fills the matrix by rows instead of columns
Changes the filling direction
Correct! By default, R fills matrices by columns. Setting byrow = TRUE fills across rows first, which is more intuitive when entering patient data row by row.
Creates a matrix with only one row
Limits matrix to single row
Not correct. The number of rows is determined by the nrow parameter, not byrow.
Makes all row values TRUE
Sets logical values in rows
That's not right. The parameter controls filling order, not the values themselves.
Learning Checkpoint
To extract all temperature readings from the vital_signs matrix, which syntax is correct?
vital_signs[, 3]
Use column index number
This works but isn't the best option given. Using column names is more readable and maintainable in medical applications.
vital_signs[, "Temperature"]
Use column name
This is correct syntax, but check the other options - there might be a more complete answer!
vital_signs["Temperature", ]
Temperature as row selector
Incorrect. This would look for a row named "Temperature". Remember: rows before comma, columns after comma.
Both A and B are correct
Multiple valid approaches
Correct! Both numeric index [, 3] and column name [, "Temperature"] work. In medical coding, using names is preferred for clarity and reducing errors.

Lab Exercise 7: Diabetes Drug Trial

You're analyzing glucose levels from a 3-month diabetes drug trial. Create a matrix to store baseline, month 1, and month 3 glucose readings for 4 patients, then calculate the improvement metrics.

# Create a matrix for diabetes trial glucose data # Fill in the blanks with appropriate values trial_data <- matrix( c(..., ..., ..., # Patient A: baseline (140-180), month1, month3 (should decrease) ..., ..., ..., # Patient B: similar pattern ..., ..., ..., # Patient C: similar pattern ..., ..., ...), # Patient D: similar pattern nrow = ..., # How many patients? ncol = ..., # How many time points? byrow = ..., # Fill by rows (TRUE) or columns (FALSE)? dimnames = list( c("PatientA", "PatientB", "PatientC", "PatientD"), c("Baseline", "Month1", "Month3") ) ) # Calculate glucose reduction from baseline to month 3 glucose_reduction <- trial_data[, "..."] - trial_data[, "..."] # Calculate percent improvement percent_improvement <- (glucose_reduction / trial_data[, "..."]) * 100 # Display results print("Glucose Reduction (mg/dL):") print(glucose_reduction) print("Percent Improvement:") print(round(percent_improvement, 1))

# Complete solution trial_data <- matrix( c(160, 145, 130, # Patient A 165, 150, 140, # Patient B 170, 150, 135, # Patient C 160, 150, 140), # Patient D nrow = 4, ncol = 3, byrow = TRUE, dimnames = list( c("PatientA", "PatientB", "PatientC", "PatientD"), c("Baseline", "Month1", "Month3") ) ) # Calculate glucose reduction from baseline to month 3 glucose_reduction <- trial_data[, "Baseline"] - trial_data[, "Month3"] # Calculate percent improvement percent_improvement <- (glucose_reduction / trial_data[, "Baseline"]) * 100 # Display results print("Glucose Reduction (mg/dL):") print(glucose_reduction) print("Percent Improvement:") print(round(percent_improvement, 1))

Learning Checkpoint
To calculate the glucose reduction from baseline to month 3, which columns should be used in the subtraction?
trial_data[, "Month3"] - trial_data[, "Baseline"]
Month 3 minus Baseline
This would give negative values for improvement. In medical contexts, we want positive values to represent glucose reduction.
trial_data[, "Baseline"] - trial_data[, "Month3"]
Baseline minus Month 3
Correct! Starting value minus ending value gives the reduction amount. Positive values indicate improvement (glucose went down).
trial_data[, "Month1"] - trial_data[, "Baseline"]
Month 1 minus Baseline
This only measures the change after one month, not the full three-month trial period.
trial_data[, "Month3"] - trial_data[, "Month1"]
Month 3 minus Month 1
This misses the baseline comparison, which is essential for measuring total treatment effect.

Real-World Connection: Clinical researchers use matrices in R to analyze trial data, calculate treatment effects, and generate regulatory submissions. The ability to perform vectorized operations on entire columns makes R particularly efficient for large-scale clinical trials.

Final Assessment
Which data structure would be BEST for storing patient records containing name (character), age (numeric), test results (numeric vector), and diagnosis (character)?
Vector
Simple, homogeneous storage
Vectors can only store one data type. You couldn't mix character names with numeric ages.
Matrix
Two-dimensional structure
Matrices require all elements to be the same type. Mixing characters and numbers would convert everything to characters.
List
Flexible, mixed-type container
Perfect! Lists can store different data types and even nested structures, making them ideal for comprehensive patient records.
Array
Multi-dimensional structure
Arrays, like matrices, require homogeneous data types. They can't mix characters with numbers.
Final Assessment
What is the KEY difference between matrices and lists in R?
Matrices can store more data than lists
Storage capacity differs
Not true. Both can store large amounts of data. The difference is in structure and type flexibility.
Matrices require all elements to be the same data type, lists can mix types
Type homogeneity requirement
Exactly right! This is the fundamental distinction. Matrices are homogeneous (all numeric or all character), while lists are heterogeneous containers.
Lists are faster to access than matrices
Performance difference
Actually, matrices often have faster access for numerical operations due to their homogeneous structure.
Matrices can only have 2 rows
Row limitation
Incorrect. Matrices can have any number of rows and columns, limited only by system memory.
