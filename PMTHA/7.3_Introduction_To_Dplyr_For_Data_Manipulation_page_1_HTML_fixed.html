dplyr Fundamentals for Medical Data

Welcome to modern medical data analysis! 🎉 The dplyr package revolutionizes clinical dataset manipulation in R - your data manipulation Swiss Army knife. Major pharmaceutical companies use dplyr in their clinical trial pipelines, and FDA reviewers often receive dplyr-based analysis code.

Quick Start 🏥

# Install and load dplyr install.packages("dplyr") library(dplyr)
Copied!
Learning Checkpoint
What is the correct command to load the dplyr package in R?
load(dplyr)
Uses the load() function
Not correct. The load() function is used for loading saved R data files, not for loading packages.
library(dplyr)
Uses the library() function
Correct! The library() function is the standard way to load installed packages in R.
import dplyr
Uses Python-style import syntax
Incorrect. This is Python syntax, not R. R uses library() or require() to load packages.
require("dplyr")
Uses the require() function with quotes
While require() can load packages, library() is the preferred method. Also, quotes are optional for both functions.

# Sample hypertension study data clinical_trial <- data.frame( patient_id = paste0("PT", 1001:1010), age = c(45, 52, 38, 61, 55, 49, 42, 58, 47, 53), treatment = rep(c("Drug_A", "Drug_B"), each = 5), baseline_bp = c(145, 152, 138, 160, 148, 142, 155, 149, 144, 158), final_bp = c(125, 138, 128, 142, 130, 135, 140, 132, 129, 141), diabetes = c(TRUE, TRUE, FALSE, TRUE, FALSE, FALSE, TRUE, TRUE, FALSE, TRUE) )

The Five Core Verbs 🔍

1. SELECT: Choose Variables 🎯

# Select specific columns bp_data <- select(clinical_trial, patient_id, age, baseline_bp, final_bp) # Exclude columns with minus no_diabetes <- select(clinical_trial, -diabetes)
Copied!

💡 Helpers: starts_with(), ends_with(), contains()

Learning Checkpoint
Which select() helper function would you use to select all columns that contain "bp" in their name?
starts_with("bp")
Selects columns starting with "bp"
This would only select columns that START with "bp", missing "baseline_bp" and "final_bp".
ends_with("bp")
Selects columns ending with "bp"
This would select "baseline_bp" and "final_bp" but miss any columns with "bp" in the middle.
contains("bp")
Selects columns containing "bp" anywhere
Correct! contains("bp") will select all columns with "bp" anywhere in their name.
matches("bp")
Uses regex pattern matching
While matches() could work with the right pattern, contains() is simpler for this use case.

2. FILTER: Find Patients 🔍

# Diabetic patients over 50 diabetic_seniors <- filter(clinical_trial, diabetes == TRUE, age > 50) # Multiple conditions with OR high_risk <- filter(clinical_trial, baseline_bp > 150 | age > 55)
Copied!
Learning Checkpoint
How many rows would the diabetic_seniors dataset contain based on the clinical_trial data?
2 rows
Two patients meet the criteria
Count again - look for patients with diabetes=TRUE AND age>50.
3 rows
Three patients meet the criteria
Correct! Patients at positions 2 (age 52), 4 (age 61), and 8 (age 58) have diabetes and are over 50.
4 rows
Four patients meet the criteria
Remember both conditions must be true: diabetes=TRUE AND age>50.
5 rows
Five patients meet the criteria
Not all diabetic patients are over 50 years old.

3. MUTATE: Calculate Metrics 🧮

# Add BP reduction calculations trial_results <- mutate(clinical_trial, bp_reduction = baseline_bp - final_bp, percent_reduction = (bp_reduction / baseline_bp) * 100, response = ifelse(percent_reduction > 10, "Good", "Poor") )
Copied!
Learning Checkpoint
If a patient has baseline_bp = 150 and final_bp = 135, what would their response category be?
"Good"
Patient shows good response
Correct! BP reduction = 15, percent = 10%. Since 10% > 10 is FALSE, but the reduction is exactly 10%, the response is "Good".
"Poor"
Patient shows poor response
Calculate the percent reduction: (150-135)/150 * 100 = 10%. This meets the threshold for "Good".
"Moderate"
Patient shows moderate response
"Moderate" is not one of the response categories defined in the ifelse() statement.
NA
Missing value
The calculation produces a valid result, not a missing value.

4. GROUP_BY + SUMMARIZE: Compare Groups 💪

# Treatment comparison treatment_summary <- clinical_trial %>% mutate(bp_reduction = baseline_bp - final_bp) %>% group_by(treatment) %>% summarize( n = n(), avg_reduction = mean(bp_reduction), sd_reduction = sd(bp_reduction) )
Copied!
Learning Checkpoint
What does the n() function return in the summarize() statement?
The total number of rows in the dataset
Counts all rows in clinical_trial
n() counts within groups when used after group_by(), not the total dataset.
The number of rows in each group
Counts rows per treatment group
Correct! n() returns the count of observations in each group created by group_by().
The number of unique values
Counts distinct values
That would be n_distinct(), not n().
The row number
Returns row indices
Row numbers would be generated by row_number(), not n().

5. ARRANGE: Sort Data 📋

# Find best responders best_responders <- clinical_trial %>% mutate(bp_reduction = baseline_bp - final_bp) %>% arrange(desc(bp_reduction))
Copied!

Describes the data
Provides data description
desc() is not a descriptive function - it modifies sorting behavior.
Sorts in descending order
Changes sort from ascending to descending
Correct! desc() reverses the sort order to descending (largest to smallest).
Removes duplicates
Filters out duplicate values
That would be distinct(), not desc().
Calculates descriptive statistics
Computes summary statistics

# Diabetes medication trial data diabetes_trial <- data.frame( patient_id = paste0("DM", 2001:2020), medication = rep(c("Metformin", "New_Drug"), each = 10), initial_a1c = c(8.2, 7.9, 9.1, 8.5, 7.8, 8.9, 9.3, 8.1, 7.7, 8.8, 8.4, 8.0, 9.2, 8.7, 7.9, 9.0, 9.5, 8.3, 7.6, 8.6), final_a1c = c(6.8, 6.9, 7.5, 7.1, 6.7, 7.3, 7.8, 6.9, 6.8, 7.2, 6.5, 6.3, 6.9, 6.6, 6.2, 6.8, 7.1, 6.4, 6.1, 6.7) ) # Analysis pipeline medication_comparison <- diabetes_trial %>% mutate(a1c_reduction = initial_a1c - final_a1c) %>% group_by(medication) %>% summarize( n = n(), mean_reduction = mean(a1c_reduction), pct_achieving_target = mean(final_a1c < 7) * 100 )
Copied!

In the medication_comparison result, what does mean(final_a1c < 7) calculate?
The average final A1C value
Calculates mean A1C level
That would be mean(final_a1c), not mean(final_a1c < 7).
The proportion of patients with final A1C below 7
Calculates proportion achieving target

The number of patients with final A1C below 7
Counts patients at target
That would be sum(final_a1c < 7), not mean().
The difference between initial and final A1C

Advanced Techniques 🚀

case_when() for Clinical Categories:

response_categories <- clinical_trial %>% mutate( bp_reduction = baseline_bp - final_bp, response_category = case_when( bp_reduction >= 20 ~ "Excellent", bp_reduction >= 10 ~ "Good", bp_reduction >= 5 ~ "Moderate", TRUE ~ "Poor" ) )
Copied!
Learning Checkpoint
What does TRUE ~ "Poor" mean in the case_when() statement?
It assigns "Poor" to TRUE values
Maps TRUE to "Poor"
TRUE in case_when() acts as a catch-all condition, not a value to match.
It's the default case for all other conditions
Catches all remaining cases
Correct! TRUE ~ "Poor" is the else/default case that catches all values not matching previous conditions.
It checks if the value is TRUE
Tests for TRUE values
TRUE here is a constant that always evaluates to TRUE, serving as a default.
It creates a logical column named "Poor"
Makes a new logical variable
case_when() creates a character column with the value "Poor", not a logical column.

Drops the grouping structure after summarizing
Returns ungrouped data

Key Takeaways 💡

  • The Pipe (%>%): Chain operations like clinical thinking
  • Start Simple: Master individual verbs before combining
  • Real-World Ready: Same tools used in pharmaceutical research

What does the pipe operator (%>%) do in dplyr?
Performs mathematical division
Divides values
The pipe is not a mathematical operator; it's for chaining functions.
Creates a new variable
Makes new columns
Creating variables is done with mutate(), not the pipe itself.
Passes the result of one function to the next
Chains operations together
Correct! The pipe takes the output of one function and makes it the first argument of the next function.

Removes NA values
Filtering is done with filter() or na.omit(), not the pipe operator.
