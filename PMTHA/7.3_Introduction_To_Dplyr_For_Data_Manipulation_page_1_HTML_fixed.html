dplyr Fundamentals for Medical Data

Welcome to the world of modern medical data analysis! 🎉 The dplyr package is your Swiss Army knife for clinical data manipulation in R. Just as precision medicine requires precise tools, dplyr provides you with surgical precision for data analysis. Major pharmaceutical companies and research institutions worldwide use dplyr in their clinical trial pipelines, and today, you'll master these same professional tools!

Getting Started: Your dplyr Journey Begins! 🚀

Before we dive into analyzing clinical trials and patient data, let's set up our workspace. Think of dplyr as your laboratory assistant - always ready to help you slice, dice, and understand your medical data with elegance and efficiency.

Installing Your Tools

First, we need to install and load dplyr. This is like preparing your lab bench before an experiment:

# Install dplyr (only needed once) install.packages("dplyr") # Load dplyr for use (needed each R session) library(dplyr)
Copied!

Why dplyr Matters in Medical Research

Traditional R code can be cryptic and hard to read. Compare these two approaches to filtering patient data:

# Traditional R (harder to read) patients[patients$age > 50 & patients$diabetes == TRUE, c("id", "age", "treatment")] # dplyr approach (reads like English!) patients %>% filter(age > 50, diabetes == TRUE) %>% select(id, age, treatment)
Copied!

See the difference? The dplyr version reads like a clinical protocol: "Take patients, filter those over 50 with diabetes, then select their ID, age, and treatment." This clarity is crucial when sharing code with colleagues or regulatory agencies.

The Magic Pipe: %>%

The pipe operator (%>%) is dplyr's secret weapon. It takes the output of one function and feeds it as input to the next, creating a data analysis pipeline. Think of it as connecting laboratory instruments in sequence - each step processes the data and passes it to the next.

Meet Your Patient Data: Clinical Trial Insights 📊

Let's work with a realistic clinical trial dataset. Imagine you're analyzing data from a hypertension study comparing two medications. This is exactly the type of data you'll encounter in real medical research!

Creating Our Clinical Trial Dataset

We'll create a dataset representing 10 patients in a blood pressure medication trial. Each patient has baseline measurements, treatment assignment, and follow-up results:

# Create a hypertension study dataset clinical_trial <- data.frame( patient_id = paste0("PT", 1001:1010), age = c(45, 52, 38, 61, 55, 49, 42, 58, 47, 53), treatment = rep(c("Drug_A", "Drug_B"), each = 5), baseline_bp = c(145, 152, 138, 160, 148, 142, 155, 149, 144, 158), final_bp = c(125, 138, 128, 142, 130, 135, 140, 132, 129, 141), diabetes = c(TRUE, TRUE, FALSE, TRUE, FALSE, FALSE, TRUE, TRUE, FALSE, TRUE) ) # View the structure of our data str(clinical_trial)
Copied!

Understanding Your Dataset

This dataset contains:

  • patient_id: Unique identifier for each patient (PT1001-PT1010)
  • age: Patient age in years
  • treatment: Randomized to either Drug_A or Drug_B (5 patients each)
  • baseline_bp: Systolic blood pressure before treatment
  • final_bp: Systolic blood pressure after 3 months of treatment
  • diabetes: Comorbidity status (TRUE/FALSE)

This mimics real clinical trial data where we track patient characteristics, interventions, and outcomes. Let's explore it!

The Magnificent Five (Part 1): SELECT, FILTER & MUTATE 🎯

Just as a physician uses different diagnostic tools for different purposes, dplyr provides five core "verbs" that handle 90% of data manipulation tasks. Let's master the first three!

1. SELECT: Choose Your Variables Wisely 🎯

The select() function lets you pick specific columns from your dataset. It's like choosing which lab tests to order - you want the relevant information without overwhelming detail.

# Select specific columns for BP analysis bp_focus <- clinical_trial %>% select(patient_id, baseline_bp, final_bp) # Select all columns EXCEPT diabetes status main_data <- clinical_trial %>% select(-diabetes) # Use helper functions for pattern matching bp_columns <- clinical_trial %>% select(patient_id, contains("bp")) # Selects all columns with "bp"
Copied!

💡 Pro Tips:

  • starts_with("prefix") - Select columns starting with specific text
  • ends_with("suffix") - Select columns ending with specific text
  • contains("text") - Select columns containing specific text
  • everything() - Select all remaining columns

2. FILTER: Find Your Patients 🔍

The filter() function extracts rows meeting specific criteria. Think of it as identifying patients who qualify for a particular treatment protocol or analysis.

# Find diabetic patients over 50 at_risk_patients <- clinical_trial %>% filter(diabetes == TRUE, age > 50) # Find patients with high baseline BP OR elderly high_priority <- clinical_trial %>% filter(baseline_bp > 150 | age >= 60) # Complex filtering: Drug A patients who responded well good_responders <- clinical_trial %>% filter(treatment == "Drug_A", final_bp < 130, baseline_bp - final_bp > 10)
Copied!
Learning Checkpoint

3. MUTATE: Create New Clinical Insights 🧮

The mutate() function adds new variables or modifies existing ones. This is where you calculate derived measures like BMI, risk scores, or treatment response metrics.

# Calculate BP reduction and response categories trial_analysis <- clinical_trial %>% mutate( bp_reduction = baseline_bp - final_bp, percent_reduction = round((bp_reduction / baseline_bp) * 100, 1), response_category = ifelse(percent_reduction >= 15, "Good", "Moderate"), age_group = case_when( age < 45 ~ "Young", age < 60 ~ "Middle-aged", TRUE ~ "Senior" ) )
Copied!

Key mutate() capabilities:

  • Create multiple new columns at once
  • Reference newly created columns within the same mutate()
  • Use any R function or calculation
  • Modify existing columns by using the same name

The Magnificent Five (Part 2): GROUP_BY, SUMMARIZE & ARRANGE 💊

Now let's explore the remaining verbs that help us compare treatments, summarize outcomes, and organize our findings. These tools are essential for clinical trial analysis!

4. GROUP_BY + SUMMARIZE: The Power Duo 💪

These functions work together like a clinical research team. group_by() divides your data into groups (like treatment arms), and summarize() calculates statistics for each group. This is how we compare treatment effectiveness!

# Compare treatments: Which drug works better? treatment_comparison <- clinical_trial %>% mutate(bp_reduction = baseline_bp - final_bp) %>% group_by(treatment) %>% summarize( n_patients = n(), mean_reduction = round(mean(bp_reduction), 1), sd_reduction = round(sd(bp_reduction), 1), success_rate = mean(final_bp < 140) * 100 ) # Analyze by diabetes status within treatments detailed_analysis <- clinical_trial %>% mutate(bp_reduction = baseline_bp - final_bp) %>% group_by(treatment, diabetes) %>% summarize( mean_age = round(mean(age), 1), mean_reduction = round(mean(bp_reduction), 1), .groups = 'drop' # Removes grouping after summarizing )
Copied!

Common summary functions:

  • n() - Count observations in each group
  • mean(), median() - Central tendency
  • sd(), IQR() - Variability measures
  • min(), max() - Extreme values
  • sum() - Total across group
  • n_distinct() - Count unique values

5. ARRANGE: Sort Your Results 📋

The arrange() function sorts your data by one or more columns. It's like organizing patient files - you might sort by severity, age, or treatment response to identify patterns.

# Find patients with best BP reduction best_responders <- clinical_trial %>% mutate(bp_reduction = baseline_bp - final_bp) %>% arrange(desc(bp_reduction)) # desc() for descending order # Complex sorting: by treatment, then by age organized_data <- clinical_trial %>% arrange(treatment, age) # Sorts by treatment first, then age within each treatment # Identify high-risk patients: high BP and diabetes high_risk_first <- clinical_trial %>% arrange(desc(baseline_bp), desc(diabetes))
Copied!

Clinical Insight: Sorting data often reveals patterns invisible in unsorted data. For instance, arranging by BP reduction might show that older patients respond differently to treatment!

Level Up: Advanced Clinical Data Wrangling 🚀

Ready to take your dplyr skills to the next level? These advanced techniques are what separate casual users from data science professionals. Master these, and you'll handle complex clinical analyses with confidence!

case_when(): The Clinical Decision Tree 🌳

The case_when() function is like a clinical decision algorithm - it evaluates multiple conditions in order and assigns values accordingly. Perfect for creating risk categories or treatment recommendations!

# Create detailed response categories based on multiple criteria response_analysis <- clinical_trial %>% mutate( bp_reduction = baseline_bp - final_bp, pct_reduction = (bp_reduction / baseline_bp) * 100, response_category = case_when( bp_reduction >= 20 & final_bp < 130 ~ "Excellent", bp_reduction >= 15 & final_bp < 140 ~ "Good", bp_reduction >= 10 ~ "Moderate", bp_reduction >= 5 ~ "Minimal", TRUE ~ "Non-responder" # The 'else' condition ), risk_profile = case_when( baseline_bp >= 160 & diabetes == TRUE ~ "Very High Risk", baseline_bp >= 150 | diabetes == TRUE ~ "High Risk", baseline_bp >= 140 ~ "Moderate Risk", TRUE ~ "Low Risk" ) )
Copied!

case_when() tips:

  • Conditions are evaluated in order - put most specific first!
  • TRUE ~ "value" acts as the default/else condition
  • All result values must be the same type
  • Great for creating clinical categories and risk stratification

Multiple Grouping: Deeper Insights 🔬

Sometimes you need to analyze data by multiple factors simultaneously. This reveals interaction effects - crucial for understanding how treatments work differently in various patient subgroups.

# Analyze treatment effect by age group and diabetes status subgroup_analysis <- clinical_trial %>% mutate( bp_reduction = baseline_bp - final_bp, age_group = case_when( age < 50 ~ "Under 50", TRUE ~ "50 and over" ) ) %>% group_by(treatment, age_group, diabetes) %>% summarize( n = n(), mean_reduction = round(mean(bp_reduction), 1), se_reduction = round(sd(bp_reduction) / sqrt(n()), 2), .groups = 'drop' ) %>% arrange(treatment, age_group, diabetes)
Copied!

Joining Data: Connecting Clinical Information 🔗

Real clinical studies often involve multiple data sources. Here's how to combine them:

# Additional lab results for our patients lab_results <- data.frame( patient_id = paste0("PT", c(1001, 1003, 1005, 1007, 1009)), cholesterol = c(210, 185, 195, 220, 175), hdl = c(45, 55, 50, 40, 60) ) # Join lab results with clinical trial data complete_data <- clinical_trial %>% left_join(lab_results, by = "patient_id") %>% mutate( ldl = cholesterol - hdl - 35, # Simplified LDL calculation cardiovascular_risk = case_when( baseline_bp >= 140 & ldl >= 130 ~ "High", baseline_bp >= 130 | ldl >= 100 ~ "Moderate", TRUE ~ "Low" ) )
Copied!
