Why Loops?

Learning Checkpoint
What is the main benefit of using loops in shell scripts?
Makes scripts run slower
Loops add processing overhead to scripts.
That's not correct. Loops actually save time by automating repetitive tasks. While they might add minimal overhead, the time saved from automation far outweighs any processing cost.
Automates repetitive tasks
Loops handle repetitive operations automatically.
Correct! Loops are the automation heroes of shell scripting. They can process hundreds of items in seconds, saving hours of manual work.
Required for all scripts
Every shell script must contain at least one loop.
Not quite. Many scripts work perfectly without loops. Loops are used specifically when you need to repeat operations or process lists of items.
Makes code more complex
Loops always complicate script logic.
That's not accurate. While loops add structure, they actually simplify code by replacing multiple repetitive commands with a single, elegant construct.

for item in apple banana orange do echo "Processing: $item" done

for Loops - Processing Lists Like a Pro

Your First for Loop Adventure

Let's check disk space automatically:

#!/bin/bash # disk_space_hero.sh echo "Disk Space Monitor Activated!" for directory in /home /var/log /tmp do echo -n "Checking $directory... " size=$(du -sh $directory 2>/dev/null | cut -f1) if [ -z "$size" ]; then echo "❌ Access denied" else echo "✅ Size: $size" fi done
Copied!
Learning Checkpoint
In the for loop syntax for item in list, what does 'item' represent?
A fixed keyword
Must always be called 'item'.
Not correct. 'item' is just an example variable name. You can use any valid variable name like 'file', 'user', 'server', etc.
A loop variable
A variable that takes each value from the list.
Exactly right! The loop variable takes on each value from the list, one at a time, allowing you to process each item individually.
The entire list
Contains all list items at once.
That's not right. The loop variable contains only one item at a time, cycling through each value in the list sequentially.
A counter
Counts loop iterations.
Not quite. This isn't a counter - it's the actual value from the list. For counting, you'd use a C-style for loop with ((i=0; i<10; i++)).

Processing Command Output

Check system users:

#!/bin/bash # user_detective.sh echo "🕵️ User Account Detective" for user in $(cut -d: -f1 /etc/passwd) do uid=$(id -u $user 2>/dev/null) if [ "$uid" -lt 1000 ] 2>/dev/null; then echo "🤖 System user: $user" else echo "👤 Human user: $user" fi done
Copied!

🔧 Lab Exercise 1: Service Guardian

Lab Exercise
What will this service monitoring script do?
#!/bin/bash # service_guardian.sh services="ssh nginx mysql" for service in $services do echo -n "🔍 Checking $service... " if systemctl is-active --quiet $service; then echo "✅ Running!" else echo "DOWN!" fi done
Start all services
Automatically starts ssh, nginx, and mysql.
Not correct. The script only checks service status using 'is-active'. It doesn't start or stop any services.
Check service status
Reports whether each service is running or down.
Perfect! The script loops through each service, checks if it's active, and reports its status with appropriate icons.
Stop all services
Stops ssh, nginx, and mysql services.
Incorrect. The script only checks status - it doesn't modify service states at all.
Install services
Installs missing services automatically.
That's not right. The script only monitors existing services - it doesn't install anything.

Create a service monitoring script:

#!/bin/bash # service_guardian.sh services="ssh nginx mysql" for service in $services do echo -n "🔍 Checking $service... " if systemctl is-active --quiet $service; then echo "✅ Running!" else echo "DOWN!" fi done
Copied!

Advanced for Loop Patterns

Learning Checkpoint
What does the wildcard pattern /etc/*.conf match?
All files in /etc
Matches every file in the /etc directory.
Not quite. The pattern only matches files ending with .conf, not all files in /etc.
Files ending with .conf
All files in /etc with .conf extension.
Exactly! The * wildcard matches any characters, so *.conf matches all configuration files ending with .conf.
Only the file *.conf
A literal file named *.conf.
Incorrect. The asterisk is a wildcard that expands to match multiple files, not a literal character in the filename.
Subdirectories of /etc
All subdirectories containing .conf files.
Not right. This pattern only matches files directly in /etc, not in subdirectories. Use /etc/**/*.conf for recursive matching.

Pattern 1: File Processing with Wildcards

#!/bin/bash # smart_backup.sh backup_dir="/backup/$(date +%Y%m%d)" mkdir -p "$backup_dir" for config_file in /etc/*.conf do if [ -f "$config_file" ]; then filename=$(basename "$config_file") echo "📄 Backing up $filename" cp -p "$config_file" "$backup_dir/" fi done
Copied!
Learning Checkpoint
What is the syntax for a C-style for loop in bash?
for (i=0; i<10; i++)
Single parentheses like in C.
Close, but bash requires double parentheses for C-style loops: for ((i=0; i<10; i++))
for ((i=0; i<10; i++))
Double parentheses for arithmetic.
Perfect! Bash uses double parentheses for C-style arithmetic loops. This allows traditional initialization, condition, and increment syntax.
for [i=0; i<10; i++]
Square brackets for conditions.
Incorrect. Square brackets are used for test conditions, not C-style loops. Use double parentheses instead.
for {i=0; i<10; i++}
Curly braces for loop syntax.
Not right. Curly braces are used for brace expansion and code blocks, not C-style loop syntax.

Pattern 2: C-Style for Loops

#!/bin/bash # port_scanner.sh for ((port=1; port<=1024; port++)) do if timeout 1 bash -c "echo >/dev/tcp/localhost/$port" 2>/dev/null; then echo "Port $port: ✅ OPEN" fi done
Copied!
Learning Checkpoint
What does the brace expansion {01..12} generate?
1 2 3...12
Numbers without leading zeros.
Not quite. The leading zero is preserved, so it generates 01 02 03...12 with zero-padding.
01 02 03...12
Zero-padded numbers from 01 to 12.
Exactly! Brace expansion preserves the format, so {01..12} generates zero-padded numbers perfect for months or file naming.
01..12
The literal string "01..12".
Incorrect. The braces trigger expansion, converting the range into individual values.
0112
Concatenated digits.
That's not right. Brace expansion generates separate values (01 02 03...), not a concatenated string.

Pattern 3: Brace Expansion

#!/bin/bash # project_scaffolder.sh # Create monthly directories for year in {2023..2024} do for month in {01..12} do mkdir -p "logs/$year/$month" done done # Create numbered test files for num in {001..010} do touch "tests/test_${num}.sh" done
Copied!
