Section 1: sort - Bringing Order to Chaos

Basic Sorting

# Create test data cat > /tmp/fruits.txt << 'EOF' banana apple Apple EOF # Default sort (ASCII) sort /tmp/fruits.txt # Output: Apple, apple, banana # Case-insensitive (-f) sort -f /tmp/fruits.txt # Reverse order (-r) sort -r /tmp/fruits.txt
Copied!
Learning Checkpoint
When using the default sort command on a file containing "banana", "apple", and "Apple", what will be the order of the output?
apple, Apple, banana
Lowercase 'apple' comes first
Not quite. Remember that in ASCII order, uppercase letters have lower values than lowercase letters.
Apple, apple, banana
Uppercase 'Apple' comes first in ASCII order
Correct! The default sort uses ASCII order, where uppercase letters come before lowercase letters.
banana, apple, Apple
Alphabetical order starting with 'b'
Incorrect. The sort command arranges items in ascending order by default, not descending.
apple, banana, Apple
Mixed case ordering
That's not right. Remember that uppercase letters come before lowercase in ASCII ordering.

Numerical Sorting - Critical!

# Wrong way (alphabetical) sort numbers.txt # 100, 1000, 20, 3 # Right way (-n) sort -n numbers.txt # 3, 20, 100, 1000
Copied!
Learning Checkpoint
Which command will correctly sort a file containing the numbers 100, 1000, 20, and 3 in ascending numerical order?
sort numbers.txt
Default sort command
Without the -n flag, sort treats numbers as strings, resulting in alphabetical ordering (100, 1000, 20, 3).
sort -n numbers.txt
Sort with numerical flag
Correct! The -n flag enables numerical sorting. Without it, sort treats numbers as strings, resulting in alphabetical ordering.
sort -r numbers.txt
Sort in reverse order
The -r flag reverses the order but still uses alphabetical sorting, not numerical.
sort -f numbers.txt
Sort case-insensitively
The -f flag is for case-insensitive sorting of text, not for numerical sorting.

Advanced Field Sorting

# Sort by specific field sort -t',' -k3 -n employees.csv # Multiple sort keys sort -t',' -k2,2 -k3,3n data.csv # Human-readable sizes (-h) sort -k2 -h sizes.txt
Copied!
Learning Checkpoint
What does the command sort -t',' -k2,2 -k3,3n data.csv do?
Sorts by the second field only
Ignores the third field specification
Look more carefully - there are two -k options, which means it sorts by multiple fields.
Sorts by the second field as text, then by the third field numerically
Uses multiple sort keys with different types
Correct! The command uses comma as delimiter (-t','), sorts by field 2 as text (-k2,2), then by field 3 numerically (-k3,3n).
Sorts by fields 2 through 3 numerically
Treats it as a range of fields
The syntax -k2,2 -k3,3n specifies two separate sort keys, not a range. Also, only the second key has the 'n' flag.
Sorts by the third field, then by the second field
Reverses the order of sorting
Sort keys are applied in the order specified. It sorts by field 2 first, then field 3.

Section 2: uniq - Duplicate Management

Basic Usage (ALWAYS sort first!)

# Wrong: uniq without sort uniq visitors.txt # Misses non-adjacent duplicates! # Right: sort then uniq sort visitors.txt | uniq
Copied!
Learning Checkpoint
Why should you always use sort before uniq?
It makes the output prettier
Aesthetic improvement only
The reason is functional, not aesthetic. Uniq has a specific limitation you need to work around.
uniq only removes adjacent duplicate lines
Non-adjacent duplicates are not detected
Correct! The uniq command only detects and removes consecutive duplicate lines, so sorting first ensures all duplicates are adjacent.
sort is faster than uniq
Performance optimization
Speed isn't the issue here. It's about uniq's fundamental behavior with duplicates.
uniq doesn't work without sort
Technical requirement
Uniq works without sort, but it may miss duplicates that aren't adjacent to each other.

Power Features

# Count occurrences (-c) sort data.txt | uniq -c # Show only duplicates (-d) sort data.txt | uniq -d # Show only unique lines (-u) sort data.txt | uniq -u # Frequency analysis sort data.txt | uniq -c | sort -nr
Copied!
Learning Checkpoint
Which command will show you ONLY the lines that appear more than once in a file?
sort data.txt | uniq -u
Show unique lines
The -u flag shows lines that appear only once, not duplicates.
sort data.txt | uniq -d
Show duplicate lines
Correct! The -d flag shows only duplicate lines, while -u shows unique lines, and -c counts all occurrences.
sort data.txt | uniq -c
Count all occurrences
The -c flag counts occurrences but shows all lines, not just duplicates.
sort data.txt | uniq
Remove duplicates
This removes duplicates but shows all unique lines, not just the ones that were duplicated.

Master Lab: Web Traffic Analysis

# Analyze access logs cut -d' ' -f1 access.log | sort | uniq -c | sort -nr # Shows IPs by request count # Find attack patterns grep "ERROR" log | cut -d' ' -f9 | sort | uniq -c | sort -nr # Shows failed usernames by frequency
Copied!
Learning Checkpoint
In the command cut -d' ' -f1 access.log | sort | uniq -c | sort -nr, what does the final sort -nr do?
Sorts numerically in ascending order
Shows lowest counts first
The -r flag reverses the order, so it won't be ascending.
Sorts numerically in descending order by count
Shows highest counts first
Correct! The -n flag enables numerical sorting and -r reverses the order, showing highest counts first.
Removes duplicate counts
Eliminates repeated numbers
Sort doesn't remove duplicates - that's what uniq does. Sort just reorders the lines.
Sorts alphabetically in reverse order
Orders by IP address
The -n flag makes it numerical sorting, not alphabetical. It's sorting by the count values.

Pipeline Mastery

Build complex analysis step by step:

# Step 1: Filter grep "ERROR" log # Step 2: Extract grep "ERROR" log | cut -d' ' -f9 # Step 3: Sort grep "ERROR" log | cut -d' ' -f9 | sort # Step 4: Count grep "ERROR" log | cut -d' ' -f9 | sort | uniq -c # Step 5: Rank grep "ERROR" log | cut -d' ' -f9 | sort | uniq -c | sort -nr
Copied!
Learning Checkpoint
When building a complex pipeline, why is it important to test each stage incrementally?
It uses less memory
Memory optimization technique
Memory usage isn't the primary concern. Think about debugging and verification.
It helps identify errors at each step
Easier debugging and verification
Correct! Testing incrementally allows you to verify each stage produces the expected output before adding complexity.
It makes the command run faster
Performance improvement
Testing incrementally actually takes more time overall. The benefit is in development and debugging.
It's required by the shell
Technical requirement
The shell doesn't require incremental testing. It's a best practice for development.

Performance Tips

  • Filter early with grep
  • Limit data before expensive operations
  • Build pipelines incrementally
  • Test each stage

Final Challenge

Find top 10 404 URLs in web logs:

grep " 404 " access.log | cut -d'"' -f2 | cut -d' ' -f2 | sort | uniq -c | sort -nr | head -10
Copied!
Learning Checkpoint
In the final challenge command, why are there two cut commands in sequence?
It's a mistake - one cut is enough
Redundant command
It's not a mistake. Each cut command extracts different parts of the log entry.
The first extracts the quoted request, the second extracts just the URL path
Two-stage extraction process
Correct! The first cut extracts the entire quoted HTTP request, while the second cut extracts just the URL path from that request.
They both do the same thing for redundancy
Backup processing
Each cut command has different delimiters and field numbers - they perform different extractions.
The second cut reverses the first cut
Undo operation
Cut commands extract data, they don't reverse operations. Each cut refines the extraction.
