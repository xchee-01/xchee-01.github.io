Understanding Coding Variables

Quiz: Variable Concepts

Variables are fundamental building blocks in programming. This quiz will test your understanding of variables, including some tricky edge cases that often confuse programmers. Read each question carefully!

Challenge 1 Variable Scope Confusion
Time: 0s

Consider the following JavaScript code:

function mystery() {
    if (true) {
        var x = 1;
        let y = 2;
        const z = 3;
    }
    console.log(x);
    console.log(y);
    console.log(z);
}

mystery();

What will be the output when this code is executed?

In JavaScript, variables declared with var are function-scoped, while those declared with let and const are block-scoped. Here's what happens:

  • var x = 1 is hoisted to the function level, so it's accessible outside the if block
  • let y = 2 is block-scoped, so it's only accessible within the if block
  • const z = 3 is also block-scoped

So when we try to log y, we get a ReferenceError, and the code execution stops there, never reaching the line that would log z.

Challenge 2 Variable Declaration Dilemma
Time: 0s

What will be the output of the following Python code?

def calculate():
    result = 10
    
    def inner_function():
        nonlocal result
        result += 5
        
    inner_function()
    print(result)
    
    def another_inner():
        result = 2
        print(result)
        
    another_inner()
    print(result)

calculate()

This Python code demonstrates the nonlocal keyword and nested scopes:

  • First, result is set to 10 in the calculate function
  • Inside inner_function, we use nonlocal result to indicate we're modifying the result from the outer scope
  • After calling inner_function(), result becomes 15 (10 + 5)
  • The first print shows 15
  • In another_inner, a new local variable result is created with value 2
  • The second print shows this local value of 2
  • But the outer result is still 15, so the third print shows 15
Challenge 3 Variable Behavior Riddle
Time: 0s

What will be displayed in the console after running this JavaScript code?

let a = { value: 10 };
let b = a;
let c = { value: 10 };

console.log(a === b);
console.log(a === c);
console.log(a.value === c.value);

a.value = 20;

console.log(b.value);
console.log(c.value);

This challenge reveals how JavaScript handles object references versus primitive values:

  • a === b is true because b references the same object as a (they point to the same memory location)
  • a === c is false because c is a different object with the same value (different memory locations)
  • a.value === c.value is true because we're comparing primitive values (10 === 10)
  • When we change a.value to 20, b.value also becomes 20 because b points to the same object
  • But c.value remains 10 because c is a separate object

This demonstrates the difference between pass by reference (objects) and pass by value (primitives) in JavaScript.

Tip: Understanding variable scope, mutation, and reference vs. value is crucial for writing bug-free code. Pay close attention to how variables behave in different contexts.
