Mission Briefing: Data Cleaning - Making Research-Ready Datasets

🧹 The Unsung Hero of Medical Research

Data scientists spend up to 80% of their time cleaning data! In medical research, clean data isn't just nice to have - it's essential for patient safety and research validity.

Learning Checkpoint
Why is data cleaning particularly critical in medical research compared to other fields?
It makes datasets smaller
Data cleaning is primarily about reducing dataset size for faster processing.
Not quite. While data cleaning might reduce size by removing irrelevant data, this isn't the primary reason it's critical in medical research.
Patient safety and research validity
Errors in medical data can directly impact patient treatment decisions and research conclusions.
Correct! In medical research, data errors can lead to incorrect treatment decisions, misdiagnoses, or flawed research conclusions that affect patient lives. This makes data cleaning a critical ethical and safety requirement.
It's required by regulations
Medical regulations specifically mandate data cleaning procedures.
While regulations do require data quality, the fundamental reason for data cleaning in medical research goes beyond compliance - it's about ensuring patient safety and research validity.
It's easier in medical data
Medical data is more standardized, making cleaning simpler.
Actually, medical data is often more complex and varied, coming from different sources, devices, and formats, making cleaning more challenging, not easier.

Removing the Clutter

Sometimes less is more. After calculating BMI, we might not need the raw height and weight anymore:

# Remove unnecessary columns cleaned_data <- patient_data[, -which(names(patient_data) %in% c("height_m", "weight_kg"))] # Check what columns remain print(names(cleaned_data))
Copied!
Learning Checkpoint
What does the -which() function do in the column removal code above?
Selects specified columns
It includes only the columns named in the function.
Not correct. The minus sign (-) before which() reverses the selection, excluding rather than including the specified columns.
Excludes specified columns
It removes the columns that match the given names from the data frame.
Correct! The combination of - (minus) and which() creates a negative index, which excludes the specified columns from the data frame. This is a common pattern for removing unwanted columns in R.
Renames columns
It changes the names of the specified columns.
That's not right. This code removes columns entirely, it doesn't rename them. Column renaming uses different syntax.
Sorts columns
It reorders the columns alphabetically.
Incorrect. This code removes columns from the data frame, it doesn't sort or reorder them.

Renaming for Clarity

Technical column names can confuse clinicians. Let's make them human-friendly:

# Rename columns for clarity names(cleaned_data)[names(cleaned_data) == "systolic_bp"] <- "systolic_pressure" names(cleaned_data)[names(cleaned_data) == "diastolic_bp"] <- "diastolic_pressure" # Verify the changes print(names(cleaned_data))
Copied!

📌 Best Practice Alert: Clear naming conventions save hours of confusion later!

Learning Checkpoint
How does the column renaming code work in R?
Conditional assignment to names()
It finds columns matching the condition and assigns new names to those positions.
Correct! The code uses logical indexing with names() to find columns that match specific names, then assigns new values to those positions. This is a safe way to rename columns that works even if the column doesn't exist.
Creates new columns
It adds new columns with the new names alongside the old ones.
Not correct. This code modifies existing column names in place, it doesn't create new columns.
Copies data to new names
It duplicates the data under new column names.
That's not right. The code only changes the column names, not the data itself or its structure.
Reorders columns
It moves renamed columns to the beginning of the data frame.
Incorrect. Renaming columns doesn't change their position in the data frame, only their names.

Creating Professional Reports

Here's a power move - creating a completely reformatted dataset in one step:

# Create a subset with renamed columns in one step final_report <- data.frame( Patient_ID = patient_data$patient_id, Age_Years = patient_data$age, BMI_Score = patient_data$bmi, Risk_Level = patient_data$risk_score, BP_Status = patient_data$bp_category ) # Display the polished report print(final_report)
Copied!
Learning Checkpoint
What is the advantage of creating a new data frame with renamed columns as shown above?
Uses less memory
Creating a new data frame is more memory efficient than renaming.
Actually, creating a new data frame uses more memory since you're duplicating data. The advantage lies elsewhere.
Clean, selective reorganization
You can select, rename, and reorder columns in a single, clear operation.
Correct! This approach allows you to simultaneously select only the columns you need, rename them for clarity, and arrange them in a logical order - all in one readable operation. It's perfect for creating focused reports from larger datasets.
Faster processing
New data frames process faster than modified ones.
Processing speed isn't significantly different. The main advantage is in code clarity and data organization.
Required by R
R requires new data frames for column renaming.
Not true. R allows in-place renaming. Creating a new data frame is a choice for clarity and organization, not a requirement.

🧪 Lab Exercise 4: Preparing a Clinical Summary Report

Your Challenge: Prepare a report for the Chief Medical Officer that highlights at-risk patients for a new wellness program.

Requirements:

  • Include only essential columns: patient ID, age, BMI (rounded to 1 decimal)
  • Add a "Priority" column:
    • "HIGH" for risk scores ≥ 3
    • "MEDIUM" for scores 1-2
    • "LOW" for score 0

Learning Checkpoint
Which R function structure would correctly create the Priority column based on risk scores?
Single ifelse()
ifelse(risk_score >= 3, "HIGH", "LOW")
This would only handle HIGH and LOW categories, missing the MEDIUM priority for scores 1-2.
Nested ifelse()
ifelse(risk_score >= 3, "HIGH", ifelse(risk_score >= 1, "MEDIUM", "LOW"))
Correct! Nested ifelse() statements allow you to handle multiple conditions. First it checks for HIGH (≥3), then MEDIUM (≥1), and finally defaults to LOW for all other cases.
Multiple separate ifelse()
Three separate ifelse() statements for each category.
Multiple separate ifelse() statements would overwrite each other. You need nested statements to handle all three categories properly.
switch() function
switch(risk_score, "LOW", "MEDIUM", "HIGH")
switch() doesn't work well with numeric ranges. It's designed for exact matches, not for "greater than or equal to" comparisons.

Solution:

# Complete solution with professional formatting summary_report <- data.frame( Patient_ID = patient_data$patient_id, Age_Years = patient_data$age, BMI_Value = round(patient_data$bmi, 1), # One decimal for readability Priority = ifelse(patient_data$risk_score >= 3, "HIGH", ifelse(patient_data$risk_score >= 1, "MEDIUM", "LOW")) ) print(summary_report)
Copied!
