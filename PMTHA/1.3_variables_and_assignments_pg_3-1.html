Variables and Assignments in Python: Part 3

Welcome to the final part of our variables and assignments journey! In Parts 1 and 2, you learned how to create, name, and update variables. Now we'll explore an important concept that becomes crucial as your programs grow more complex - variable scope.

Mission Briefing: Recognizing Variable Scope

In hospitals, some information is meant to be available hospital-wide, while other details might only be relevant within a specific department. Similarly, in Python, variables have something called "scope" - the region of code where they can be accessed.

Let's start with a basic example:

# This is a global variable (available throughout the program) hospital_name = "Mercy General Hospital" # A function creates its own "room" where variables live def admit_patient(): # This is a local variable - only exists inside this function patient_room = "E204" print(f"Admitting patient to {hospital_name}, room {patient_room}") # Let's call our function admit_patient() # This works - hospital_name is a global variable print("Hospital:", hospital_name) # But this would cause an error - patient_room only exists inside the function # Uncomment to see the error: # print("Room:", patient_room)
Copied!
Learning Checkpoint
What happens if you run the commented-out line of code print("Room:", patient_room)? Why?
NameError: name 'patient_room' is not defined
Correct! The variable patient_room only exists inside the admit_patient() function. Once the function finishes running, that variable is no longer accessible, resulting in a NameError.
It prints "Room: E204"
That's not correct. Variables defined inside a function have "local scope," meaning they only exist inside that function and cannot be accessed from outside.
It prints "Room: None"
Incorrect. The variable patient_room doesn't exist at all outside the function, so Python doesn't return None - it raises a NameError.
SyntaxError: invalid syntax
Not correct. The syntax is valid, but there's a runtime error because the variable doesn't exist in the scope where it's being accessed.

Understanding scope helps us organize our code and prevent errors. Let's look at another example with conditionals:

# Example of scope in conditional statements crp_level = 4.2 # C-reactive protein level (mg/L) # Basic conditional for inflammation assessment if crp_level > 3.0: inflammation_status = "Elevated" recommended_action = "Consider anti-inflammatory therapy" else: inflammation_status = "Normal" recommended_action = "No intervention needed" # These variables are still accessible outside the if/else block in Python print("CRP Level:", crp_level, "mg/L") print("Status:", inflammation_status) print("Recommendation:", recommended_action)
Copied!
Learning Checkpoint
In the example above, can we access inflammation_status after the if/else block?
Yes
Correct! In Python, if/else blocks don't create their own variable scope. Variables defined inside these blocks are accessible outside the block, as long as you're in the same function or global scope.
No
That's not correct. Unlike functions, if/else blocks in Python don't create a new scope. Variables defined inside an if/else block remain accessible after the block ends.

A common source of confusion is trying to modify variables from an outer scope:

# Let's try something tricky baseline_dose = 150 # Starting medication dose def adjust_for_weight(weight_kg): # We're trying to create a new local variable with the same name adjusted_dose = baseline_dose * (weight_kg / 70) return adjusted_dose # Call our function weight_adjusted = adjust_for_weight(85) print("Original dose:", baseline_dose, "mg") print("Weight-adjusted dose:", weight_adjusted, "mg")
Copied!

The key thing to understand: functions can read variables from the outer scope, but when they create a new variable with the same name, it's a separate local variable that doesn't affect the outer one.

Health Tech Tip: In medical software, keep patient-specific variables in appropriate scopes. For instance, vital signs calculations should be done in functions that maintain their own scope, preventing one patient's data from accidentally influencing another's.

Variable Scope Quiz
1. A variable created inside a function can be used anywhere in your program.
True
Incorrect. Variables created inside a function have local scope and can only be used within that function.
False
Correct! Variables created inside a function have local scope and can only be used within that function unless they are explicitly returned or declared as global.
2. A variable created in the main program can be accessed inside a function.
True
Correct! Functions can read (but not modify without special declarations) variables from the outer scope.
False
Incorrect. Functions can access variables from the outer scope, which is why global variables can be read (but not modified without special handling) inside functions.
3. Variables created inside an if/else block in Python can be accessed after the block.
True
Correct! In Python, if/else blocks don't create their own scope. Variables defined inside these blocks remain accessible afterward, as long as you're in the same function or global scope.
False
Incorrect. Unlike some other programming languages, Python's if/else blocks don't create new scopes. Variables defined inside these blocks remain accessible afterward.

Lab Exercise: Clinical Trial Data Processing

Lab Exercise: Clinical Trial Data Processing

Your Mission: You're analyzing data for a clinical trial testing a new treatment for hypertension. The code has scope issues that need to be fixed to properly calculate and report treatment effectiveness.

# Lab scenario: Fix the scope issues in this clinical trial analysis # Patient baseline measurements systolic_baseline = 158 # mmHg diastolic_baseline = 94 # mmHg patient_on_medication = True # Function to evaluate blood pressure change after treatment def calculate_treatment_effect(systolic_after, diastolic_after): # Calculate the differences systolic_change = systolic_baseline - systolic_after diastolic_change = diastolic_baseline - diastolic_after # Determine if treatment was effective (>10 point reduction) if systolic_change > 10: systolic_result = "Significant improvement" else: systolic_result = "Minimal change" if diastolic_change > 5: diastolic_result = "Significant improvement" else: diastolic_result = "Minimal change" # Check for normalization (<140/90) if systolic_after < 140 and diastolic_after < 90: bp_normalized = True else: bp_normalized = False # Return the results # Something is missing here! # Get post-treatment readings post_treatment_systolic = 142 post_treatment_diastolic = 86 # Process the results treatment_results = calculate_treatment_effect(post_treatment_systolic, post_treatment_diastolic) # Generate report print("HYPERTENSION CLINICAL TRIAL - PATIENT REPORT") print("Baseline BP:", systolic_baseline, "/", diastolic_baseline, "mmHg") print("Post-treatment BP:", post_treatment_systolic, "/", post_treatment_diastolic, "mmHg") print("Systolic change:", systolic_change, "mmHg -", systolic_result) print("Diastolic change:", diastolic_change, "mmHg -", diastolic_result) print("BP normalized to <140/90:", bp_normalized) print("Patient was on existing medication:", patient_on_medication)
Copied!

The bug: When you run this code, you'll get a NameError because certain variables like systolic_change, systolic_result, etc., are defined inside the function but then accessed outside it.

Your task: Fix the code so it runs correctly by addressing the scope issues.

Hint: Variables defined inside a function are not accessible outside it unless they are explicitly returned from the function.

Solution:

# Complete solution with resolved scope issues # Patient baseline measurements systolic_baseline = 158 # mmHg diastolic_baseline = 94 # mmHg patient_on_medication = True # Function to evaluate blood pressure change after treatment def calculate_treatment_effect(systolic_after, diastolic_after): # Calculate the differences systolic_change = systolic_baseline - systolic_after diastolic_change = diastolic_baseline - diastolic_after # Determine if treatment was effective (>10 point reduction) if systolic_change > 10: systolic_result = "Significant improvement" else: systolic_result = "Minimal change" if diastolic_change > 5: diastolic_result = "Significant improvement" else: diastolic_result = "Minimal change" # Check for normalization (<140/90) if systolic_after < 140 and diastolic_after < 90: bp_normalized = True else: bp_normalized = False # Return the results as a dictionary return { "systolic_change": systolic_change, "diastolic_change": diastolic_change, "systolic_result": systolic_result, "diastolic_result": diastolic_result, "bp_normalized": bp_normalized } # Get post-treatment readings post_treatment_systolic = 142 post_treatment_diastolic = 86 # Process the results treatment_results = calculate_treatment_effect(post_treatment_systolic, post_treatment_diastolic) # Generate report print("HYPERTENSION CLINICAL TRIAL - PATIENT REPORT") print("Baseline BP:", systolic_baseline, "/", diastolic_baseline, "mmHg") print("Post-treatment BP:", post_treatment_systolic, "/", post_treatment_diastolic, "mmHg") print("Systolic change:", treatment_results["systolic_change"], "mmHg -", treatment_results["systolic_result"]) print("Diastolic change:", treatment_results["diastolic_change"], "mmHg -", treatment_results["diastolic_result"]) print("BP normalized to <140/90:", treatment_results["bp_normalized"]) print("Patient was on existing medication:", patient_on_medication)
Copied!

Why this works:

The key fix was to return all the calculated values from the function and then access them through the returned dictionary.

The pattern of returning a dictionary is very common in medical and scientific programming because:

  1. It keeps related values grouped together
  2. It provides clear names for each value
  3. It avoids scope issues by explicitly passing data between different parts of the program

Common bug: A frequent mistake in medical data processing is forgetting that variables created inside functions aren't automatically available outside. This can lead to errors in clinical analysis if not handled properly.

Debugging Challenge
Identify one more potential scope-related issue that might arise if this code were part of a larger program processing multiple patients.
Global baseline variables could be overwritten
Correct! Using global variables for patient-specific data is risky. If these variables get overwritten when processing a new patient, it would affect all subsequent calculations. A better approach would be to pass these baseline values as function parameters rather than accessing them from the global scope.
Return value limitation
This is not correct. While functions technically return one object, we can return multiple values by using compound data types like dictionaries, lists, or tuples, as demonstrated in the solution.
Dictionary keys are not type-safe
While dictionary access could potentially lead to typos, this is not a scope-related issue. It's a general consideration for any code using dictionaries.
Local variables persist between function calls
This is incorrect. Local variables do not persist between function calls - they are created anew each time the function is called and destroyed when the function completes.

Real-World Connection: In bioinformatics pipelines for genomic analysis, proper variable scoping is critical. For example, the Genome Analysis Toolkit (GATK) used at major sequencing centers relies on carefully scoped variables to ensure that patient samples don't cross-contaminate in the code, even when processing thousands of genomes simultaneously.
