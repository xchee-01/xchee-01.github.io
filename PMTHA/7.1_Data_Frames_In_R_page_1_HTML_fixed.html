🎯 What's a Data Frame, Really?

Learning Checkpoint
In precision medicine, we manage patient records, lab results, genomic sequences, and drug response profiles. What best describes a data frame in R?
A simple list of numbers
Data frames are just one-dimensional lists for storing values.
Not quite! Data frames are much more powerful than simple lists. They're two-dimensional structures that can hold multiple types of data in organized columns and rows.
A digital patient chart on steroids
A structured table holding multiple types of information in one organized format.
Exactly right! A data frame is like having a perfectly organized filing cabinet where each row is a patient and each column is a measurement - instant access to medical histories!
A type of Excel file
Data frames are R's version of Excel spreadsheet files.
Not correct. While data frames can read from Excel files, they're R objects that live in memory and offer much more functionality than spreadsheet files.
A database management system
Data frames are full database systems like SQL.
That's not right. Data frames are in-memory data structures in R, not database management systems. They're more like structured tables that R can manipulate easily.

Picture this: Each row is a patient, and each column is a measurement. It's like having a perfectly organized filing cabinet for instant access to medical histories.

🏥 Your First Medical Data Frame

Let's create a mini clinical trial:

# Welcome to Dr. Data's Diabetes Clinic! patient_data <- data.frame( patient_id = c("P001", "P002", "P003"), age = c(45, 52, 38), glucose_mg_dl = c(126, 115, 142), treatment = c("Drug_A", "Placebo", "Drug_A") ) # Display the data frame print(patient_data)

🛠️ Your Data Frame Creation Toolkit

Method 1: Building from Vectors (Lab Results)

# Morning lab rush - four patients need blood work! patient_ids <- c("PT101", "PT102", "PT103", "PT104") hemoglobin_g_dl <- c(14.5, 12.8, 15.2, 11.9) # Normal: 12-17 g/dL platelet_count <- c(250000, 185000, 310000, 168000) # Normal: 150k-400k # Combine into a data frame blood_work <- data.frame( patient_id = patient_ids, hemoglobin = hemoglobin_g_dl, platelets = platelet_count ) # View the structure str(blood_work)

📁 Reading Real-World Medical Data Files

CSV Files: Universal Medical Data Format

Learning Checkpoint
When reading medical CSV files, which parameter is most important for handling missing lab results?
header = TRUE
This tells R that the first row contains column names.
While important, this parameter handles column names, not missing values in lab results.
na.strings
Specifies what text values should be treated as NA (missing).
Perfect! The na.strings parameter lets you specify values like "Not tested", "pending", or empty strings as NA, crucial for medical data integrity.
stringsAsFactors = FALSE
Prevents R from converting text to factors automatically.
This is about data types, not handling missing values. It's still important but not for missing lab results.
fileEncoding = "UTF-8"
Sets the character encoding for the file.
This handles special characters in the file, not missing values in lab results.
# Basic CSV reading lab_data <- read.csv("lab_results.csv") # Medical data needs special handling lab_data <- read.csv("lab_results.csv", header = TRUE, stringsAsFactors = FALSE, na.strings = c("NA", "Not tested", "", "pending"))
Copied!

Excel Files: The Clinician's Choice

Learning Checkpoint
What's the advantage of using read_excel() with the range parameter for lab reports?
It reads files faster
Range selection speeds up the file reading process.
Speed isn't the main benefit. The range parameter is about precision, not performance.
Skip headers and footers
Extract only the data table, avoiding report headers/summaries.
Exactly! Lab reports often have headers, logos, and summary sections. The range parameter lets you extract just the data table (e.g., "B2:F50").
It's required for Excel files
You must specify a range when reading Excel files.
The range parameter is optional. You can read entire sheets without specifying a range.
It converts data types
Range selection automatically formats numbers correctly.
Range selection doesn't affect data type conversion. That's handled by other parameters.
# Install and load readxl (one-time) install.packages("readxl") library(readxl) # Read specific sheet clinical_trial <- read_excel("clinical_trial_data.xlsx", sheet = "Baseline") # Or specific range lab_values <- read_excel("lab_report.xlsx", range = "B2:F50")
Copied!

🔍 Data Exploration Commands

Learning Checkpoint
Match each R command with its medical data exploration purpose:
head() - Deep structural analysis
Shows data types and structure of each column.
Not quite! head() shows the first few rows of data, not the structure. It's for "first impressions" of your data.
str() - Statistical summary
Provides mean, median, and quartiles for numeric data.
That's not right! str() shows structure (data types, dimensions), not statistical summaries.
summary() - Health check for red flags
Shows min/max values, missing data, and distributions.
Perfect! summary() gives you statistical summaries that help identify outliers, missing values, and data ranges - essential for spotting data quality issues.
dim() - Display first rows
Shows the beginning of your dataset.
Incorrect! dim() returns the dimensions (rows and columns), not the data itself.
# The "first date" with your data head(clinical_trial) # First impressions # The "deep dive" str(clinical_trial) # What are we working with? # The "health check" summary(clinical_trial) # Any red flags?
Copied!

🎯 Data Access: Surgical Precision Toolkit

The [Row, Column] Scalpel

Learning Checkpoint
To get Patient P003's glucose reading from patient_data, which is safer in medical practice?
patient_data[3, 3]
Use numeric row and column positions.
This works but is risky! If columns get reordered, you might access the wrong medical data.
patient_data[3, "glucose_mg_dl"]
Use row number with column name.
Excellent choice! Using column names prevents errors if data structure changes - crucial for patient safety!
patient_data[[3]]
Use double brackets with position.
Double brackets extract entire columns, not specific values. This would give you all glucose values.
patient_data$3
Use dollar sign with row number.
This syntax is invalid! Dollar sign works with column names, not row numbers.
# Get third patient's glucose patient_data[3, 3] # Row 3, Column 3 # Named access (safer) patient_data[3, "glucose_mg_dl"]
Copied!

The Dollar Sign Express Lane

Learning Checkpoint
What does patient_data$glucose_mg_dl return?
A single glucose value
Returns one patient's glucose reading.
No, the dollar sign extracts an entire column, not a single value.
A vector of all glucose values
Returns glucose readings for all patients: 126 115 142
Perfect! The $ operator extracts the entire column as a vector, giving you all patients' glucose levels at once.
A data frame subset
Returns a smaller data frame with just glucose.
The $ operator returns a vector, not a data frame. Use [ , "glucose_mg_dl"] to keep data frame structure.
An error message
This syntax is incorrect.
This is valid syntax! The $ operator is a common way to access columns by name.
# Extract entire column glucose_levels <- patient_data$glucose_mg_dl print(glucose_levels) # 126 115 142
Copied!

Clinical Workflow Patterns

Learning Checkpoint
For morning rounds, you need to review the first two patients. Which code gives you their complete records?
patient_data[, 1:2]
Select columns 1 and 2 for all patients.
This selects the first two columns (patient_id and age) for ALL patients, not the first two patients.
patient_data[1:2, ]
Select rows 1 and 2 with all columns.
Correct! This gives you complete records for patients P001 and P002 - perfect for morning rounds!
patient_data$1:2
Use dollar sign with row range.
Invalid syntax! The $ operator doesn't work with row selections.
patient_data[[1:2]]
Use double brackets with row range.
Double brackets are for list extraction, not row selection in data frames.
# Morning rounds (first two patients) patient_data[1:2, ] # Lab report (specific columns) patient_data[, c("patient_id", "glucose_mg_dl")] # Combined selection patient_data[2:3, "glucose_mg_dl"]
Copied!
