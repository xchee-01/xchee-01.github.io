7.1.1. Understanding and Creating Data Frames

What's a Data Frame, Really?

Learning Checkpoint
In precision medicine, we manage patient records, lab results, genomic sequences, and drug response profiles. What best describes a data frame in R?
A simple list of numbers
Data frames are just one-dimensional lists for storing values.
Not quite! Data frames are much more powerful than simple lists. They're two-dimensional structures that can hold multiple types of data in organized columns and rows.
A digital patient chart on steroids
A structured table holding multiple types of information in one organized format.
Exactly right! A data frame is like having a perfectly organized filing cabinet where each row is a patient and each column is a measurement - instant access to medical histories!
A type of Excel file
Data frames are R's version of Excel spreadsheet files.
Not correct. While data frames can read from Excel files, they're R objects that live in memory and offer much more functionality than spreadsheet files.
A database management system
Data frames are full database systems like SQL.
That's not right. Data frames are in-memory data structures in R, not database management systems. They're more like structured tables that R can manipulate easily.

Data Frame Creation Methods

Method 1: Building from Vectors (Lab Results)

Copied!
Learning Checkpoint
When reading medical CSV files, which parameter is most important for handling missing lab results?
header = TRUE
This tells R that the first row contains column names.
While important, this parameter handles column names, not missing values in lab results.
na.strings
Specifies what text values should be treated as NA (missing).
Perfect! The na.strings parameter lets you specify values like "Not tested", "pending", or empty strings as NA, crucial for medical data integrity.
stringsAsFactors = FALSE
Prevents R from converting text to factors automatically.
This is about data types, not handling missing values. It's still important but not for missing lab results.
fileEncoding = "UTF-8"
Sets the character encoding for the file.
This handles special characters in the file, not missing values in lab results.

Surgical Precision Data Access

The [Row, Column] Scalpel

# Get third patient's glucose patient_data[3, 3] # Row 3, Column 3 # Named access (safer for medical data!) patient_data[3, "glucose_mg_dl"] # Multiple rows or columns patient_data[1:3, ] # First three patients, all columns patient_data[, c("patient_id", "glucose_mg_dl")] # All patients, specific columns
Copied!

The Dollar Sign Express Lane

# Extract entire column as vector glucose_levels <- patient_data$glucose_mg_dl print(glucose_levels) # 126 115 142 # Direct calculations on columns mean_glucose <- mean(patient_data$glucose_mg_dl) high_glucose <- patient_data$glucose_mg_dl > 126
Copied!
Learning Checkpoint
To get Patient P003's glucose reading from patient_data, which is safer in medical practice?
patient_data[3, 3]
Use numeric row and column positions.
This works but is risky! If columns get reordered, you might access the wrong medical data.
patient_data[3, "glucose_mg_dl"]
Use row number with column name.
Excellent choice! Using column names prevents errors if data structure changes - crucial for patient safety!
patient_data[[3]]
Use double brackets with position.
Double brackets extract entire columns, not specific values. This would give you all glucose values.
patient_data$3
Use dollar sign with row number.
This syntax is invalid! Dollar sign works with column names, not row numbers.

# Complete solution # Create clinical dataset clinical_data <- data.frame( patient_id = c("CL001", "CL002", "CL003", "CL004", "CL005"), systolic_bp = c(135, 128, 142, 118, 155), diastolic_bp = c(85, 78, 92, 72, 95), cholesterol = c(205, 185, 225, 170, 245), on_medication = c(TRUE, FALSE, TRUE, FALSE, TRUE) ) # 1.
