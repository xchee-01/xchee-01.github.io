6.3.1. Numeric Data Types

Picture monitoring a patient in the ICU. Their heart rate is 72 beats per minute (whole number), but their temperature is 98.6°F (decimal). R provides two numeric types:

# Integer: Whole numbers only (add 'L' to specify) patient_age <- 45L # Can't be 45.5 years old! tablet_count <- 30L # Pills come in whole numbers # Double: Decimal precision for measurements body_temperature <- 98.6 # Every decimal matters drug_dose_mg <- 2.5 # Medications need precision
Copied!
Learning Checkpoint
Which R data type should you use to store a patient's heart rate of 72 beats per minute?
character
Store the value as text
Not quite. Character types are for text data, not numeric values that you'll use in calculations.
integer
Store as a whole number
Correct! Heart rate is a whole number count, making integer the most appropriate type. Use heart_rate <- 72L to explicitly create an integer.
logical
Store as TRUE/FALSE
Incorrect. Logical types only store TRUE or FALSE values, not numeric measurements.
factor
Store as a categorical variable
Not correct. Factors are for categorical data with defined levels, not continuous numeric measurements.

💊 Medical Application: Calculating insulin doses

blood_sugar <- 180.5 # mg/dL target_sugar <- 120.0 correction_factor <- 50.0 insulin_units <- (blood_sugar - target_sugar) / correction_factor print(paste("Administer", round(insulin_units, 1), "units")) # Output: "Administer 1.2 units"
Copied!
Learning Checkpoint
A patient's temperature reading is 101.3°F. Which code correctly stores this value in R?
temp <- "101.3"
Store as text with quotes
This stores the temperature as text, which you can't use in calculations.
temp <- 101.3L
Store as integer with L suffix
The 'L' suffix creates integers and would cause an error with decimal values.
temp <- 101.3
Store as numeric value
Correct! Temperature requires decimal precision, so use a double (numeric) type.
temp <- TRUE
Store as logical value
Logical values (TRUE/FALSE) cannot represent numeric measurements.

Every patient has a story! From names to clinical notes, text data makes up 80% of healthcare information.

# Patient identification patient_id <- "P2024-1847" medical_record_number <- "MRN-789456" # Clinical information chief_complaint <- "Persistent cough for 3 weeks" prescription <- "Lisinopril 10mg PO daily"
Copied!
Learning Checkpoint
How do you correctly store a patient's name "John Smith" in R?
patient_name <- John Smith
Assign without quotes
This will cause an error. Text data must be enclosed in quotes.
patient_name <- "John Smith"
Use double quotes
This is correct, but not the only way. Check if there's a more complete answer.
patient_name <- 'John Smith'
Use single quotes
This is correct, but not the only way. Check if there's a more complete answer.
Both B and C are correct
Either quote type works
Correct! In R, character strings can be enclosed in either double quotes ("") or single quotes (''). Both are valid for storing text data.

doctor_prescription <- "tylenol 500mg" pharmacy_standard <- toupper(doctor_prescription) generic_name <- "ACETAMINOPHEN 500MG" if (grepl("TYLENOL", pharmacy_standard)) { print(paste("Dispensing generic:", generic_name)) }

6.3.3. Logical Data Types

Medical decisions often boil down to yes/no questions. R's TRUE/FALSE is perfect for binary decisions.

# Direct assignment is_diabetic <- TRUE requires_isolation <- FALSE # From comparisons fever_present <- body_temperature > 100.4 normal_heart_rate <- heart_rate >= 60 & heart_rate <= 100
Copied!
Learning Checkpoint
What value will fever_present have if body_temperature is 99.2?
TRUE
Temperature exceeds threshold
99.2 is not greater than 100.4, so the comparison returns FALSE.
FALSE
Temperature below threshold
Correct! Since 99.2 is not greater than 100.4, the comparison returns FALSE. Logical comparisons always return TRUE or FALSE, not strings or numbers.
"FALSE"
Text string "FALSE"
Comparisons return logical values (TRUE/FALSE), not character strings.
99.2
The temperature value
Comparisons return TRUE or FALSE, not the original numeric value.

💊 Medical Application: Sepsis screening

respiratory_rate <- 24L systolic_bp <- 88L altered_mental_status <- TRUE # Calculate warning signs high_resp_rate <- respiratory_rate >= 22 low_blood_pressure <- systolic_bp <= 100 # Determine risk qsofa_score <- sum(high_resp_rate, low_blood_pressure, altered_mental_status) if (qsofa_score >= 2) { print("⚠️ ALERT: High sepsis risk!") }
Copied!
Learning Checkpoint
If heart_rate is 55, what will normal_heart_rate contain after running: normal_heart_rate <- heart_rate >= 60 & heart_rate <= 100
TRUE
Heart rate is normal
55 is less than 60, so the first condition is FALSE. With &, both must be TRUE.
FALSE
Heart rate is not normal
Correct! Since 55 is less than 60, the first condition (heart_rate >= 60) is FALSE. With the & operator, if any condition is FALSE, the entire expression is FALSE.
55
The heart rate value
Logical operations return TRUE or FALSE, not numeric values.
NA
Missing value
The comparison produces a valid logical result (FALSE), not a missing value.
Learning Checkpoint
In the sepsis screening code, if respiratory_rate = 20, systolic_bp = 95, and altered_mental_status = TRUE, what is the qsofa_score?
0
No risk factors present
At least one condition is TRUE (altered mental status), so the score cannot be 0.
1
One risk factor
Check again: low_blood_pressure (95 <= 100) is TRUE, and altered_mental_status is TRUE.
2
Two risk factors
Correct! high_resp_rate = FALSE (20 < 22), low_blood_pressure = TRUE (95 <= 100), altered_mental_status = TRUE. sum(FALSE, TRUE, TRUE) = sum(0, 1, 1) = 2.
3
All risk factors
The respiratory rate (20) is below the threshold (22), so only 2 of 3 conditions are TRUE.

character

double/numeric
