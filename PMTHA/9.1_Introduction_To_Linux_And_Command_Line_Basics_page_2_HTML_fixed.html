9.1.4. The Linux Filesystem Structure

Linux organizes all files and directories in a single tree structure starting from the root directory /. Understanding this hierarchy is crucial for efficient system navigation and file management.

Directory Hierarchy

/ # Root directory - the top of the filesystem tree ├── home # User home directories (personal files) ├── etc # System configuration files ├── var # Variable data (logs, temporary files) ├── usr # User programs and utilities ├── bin # Essential command binaries ├── tmp # Temporary files └── dev # Device files
Copied!

City Analogy: Think of the Linux filesystem like a well-organized city:

  • /home = Residential area (where users live)
  • /etc = City hall (administrative rules and settings)
  • /var = Post office (messages and changing data)
  • /usr = Shopping district (applications and programs)
Learning Checkpoint
Which directory would you look in to find system configuration files?
/home
Not quite. /home contains user personal files, not system configuration.
/etc
Correct! /etc contains system configuration files, like the "city hall" where rules and settings are stored.
/var
Not correct. /var contains variable data like logs and temporary files, not configuration.
/tmp
Incorrect. /tmp is for temporary files that can be deleted between reboots.

Key Directories and Their Purposes

Directory Purpose Example Use
/home/user Personal files Documents, projects, scripts
/etc System settings Configuration files
/var/log System logs Troubleshooting, monitoring
/tmp Temporary files Downloads, processing
/usr/bin User commands Installed programs
Learning Checkpoint
You need to check system logs for errors. Which directory should you navigate to?
/home/user
Not correct. /home/user contains personal files, not system logs.
/usr/bin
Incorrect. /usr/bin contains executable programs, not log files.
/var/log
Correct! /var/log contains system logs used for troubleshooting and monitoring system activities.
/tmp
Not right. /tmp is for temporary files, not system logs.

9.1.5. Working with Linux Commands

Linux commands become powerful when combined. You'll learn how to chain commands, gather system information, and use shortcuts to work efficiently.

Combining Commands with Pipes

The pipe operator | connects commands, sending output from one as input to another:

# Find large directories and sort by size du -sh /* | sort -h # Search command history for specific commands history | grep "ls" # Count files in a directory ls -1 | wc -l
Copied!
Learning Checkpoint
What does the pipe symbol (|) do in Linux commands?
Separates multiple commands
Not quite. Semicolon (;) separates multiple commands, not the pipe.
Sends output of one command as input to another
Correct! The pipe (|) takes the output from the command on its left and uses it as input for the command on its right.
Comments out the rest of the line
Incorrect. The hash symbol (#) is used for comments, not the pipe.
Creates a new file
Not correct. The > symbol redirects output to a file, not the pipe.

Essential System Information Commands

# Display current date and time date # Show current username whoami # Display hostname hostname # Show current directory pwd # Display system information cat /etc/os-release | grep PRETTY_NAME
Copied!
Learning Checkpoint
Which command shows your current username?
hostname
Not correct. hostname shows the system name, not your username.
whoami
Correct! The whoami command displays the username of the current user.
date
Incorrect. date shows the current date and time, not username.
pwd
Not right. pwd shows the current working directory, not username.

Command Reference and Efficiency Tips

# Essential Commands Quick Reference pwd # Print working directory ls -la # List all files with details cat file # Display file content echo text # Print text to screen man command # Show manual for command --help # Show help for most commands
Copied!

Keyboard Shortcuts for Efficiency:

  • Tab = Auto-complete commands and filenames
  • ↑/↓ = Navigate through command history
  • Ctrl+R = Search command history
  • !! = Repeat last command
  • Ctrl+C = Cancel current command
  • Ctrl+D = Exit current shell
Learning Checkpoint
Which keyboard shortcut searches through your command history?
Tab
Not quite. Tab is for auto-completion, not searching history.
Ctrl+C
Incorrect. Ctrl+C cancels the current command.
Ctrl+R
Correct! Ctrl+R opens reverse search, allowing you to find previously typed commands by typing part of them.
Ctrl+D
Not right. Ctrl+D exits the current shell or logs out.

Lab Exercise 2: System Health Check

As a bioinformatics system administrator, you need to create a script that checks system health. This is crucial for ensuring your computational resources are available for genomic analyses.

# Lab scenario: Complete the system health check script # Fill in the missing commands indicated by ... echo "=== System Health Check ===" echo "Date: $(...)" echo "Current User: $(...)" echo "System Name: $(...)" # Show OS information echo "Operating System:" cat /etc/os-release | grep ... # Check disk usage for important directories echo "Disk Usage Summary:" du -sh ... ... ... 2>/dev/null
Copied!

Expected output pattern:

=== System Health Check === Date: Mon Apr 29 10:30:00 UTC 2025 Current User: biouser System Name: precision-med-server Operating System: PRETTY_NAME="Ubuntu 22.04.3 LTS" Disk Usage Summary: 2.3G /var 156M /tmp 45G /home

Answer:

# Complete solution echo "=== System Health Check ===" echo "Date: $(date)" echo "Current User: $(whoami)" echo "System Name: $(hostname)" # Show OS information echo "Operating System:" cat /etc/os-release | grep PRETTY_NAME # Check disk usage for important directories echo "Disk Usage Summary:" du -sh /var /tmp /home 2>/dev/null
Copied!

Learning Checkpoint
Which command would show both username and date in one line?
echo $(whoami) $(date)
Correct! echo $(whoami) $(date) uses command substitution to display both outputs in one line.
whoami | date
Not correct. This pipes whoami output to date, which doesn't work as expected.
ls -la whoami date
Incorrect. This would try to list files named 'whoami' and 'date'.
pwd && hostname
Not right. This shows directory and hostname, not username and date.
