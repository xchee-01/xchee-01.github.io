4.2 DataFrame Creation - Advanced Techniques

Welcome to Module 2 of DataFrame Creation! In this session, you'll master advanced techniques for creating DataFrames, including working with empty DataFrames and handling complex nested structures - essential skills for real-world medical data processing.

Mission Briefing: Creating Empty DataFrames and Adding Data

The Empty Canvas Approach 🎨

Sometimes you need to set up your data structure before the data arrives - like preparing forms before patients arrive at a clinic!

Setting Up a Vaccine Trial Framework

Let's create a system for tracking COVID-19 vaccine responses:

Current size: {vaccine_trial_df.shape}")

# First participant enrolls! vaccine_trial_df.loc[0] = ['VAC001', '2024-01-15', 10.5, 256.8, 'none'] print("\n🎉 First participant enrolled:") print(vaccine_trial_df)

Learning Checkpoint
What does loc[0] do in the code above?
Locates column 0 in the DataFrame
Not quite right. Python doesn't simply display the text inside print(). When an expression like 2 + 3 is encountered, Python calculates the result first.
Creates and accesses row 0 in the DataFrame
Correct! loc[0] creates and accesses row 0 in the DataFrame. It allows you to set values for a specific row by its index label.
Locks the DataFrame at position 0
That's not correct. This is valid Python syntax. The print() function can display the results of calculations without causing errors.
Loads data from file 0
That's not right. The print() function's purpose is to display output to the screen. In this case, it will display the result of the calculation 2 + 3.

What happened?

  • loc[0] creates row 0
  • Values are assigned in column order
  • DataFrame automatically handles data types

Batch Enrollment: Multiple Participants

# Morning clinic - multiple enrollments new_participants = pd.DataFrame({ 'participant_id': ['VAC002', 'VAC003'], 'vaccination_date': ['2024-01-16', '2024-01-16'], 'antibody_titer_day0': [8.2, 12.1], 'antibody_titer_day28': [198.5, 312.4], 'adverse_events': ['mild fever', 'none'] }) # Add to main trial (concatenate DataFrames) vaccine_trial_df = pd.concat([vaccine_trial_df, new_participants], ignore_index=True) print("\n📊 Updated trial roster:") print(vaccine_trial_df) # Quick analysis print(f"\nAverage antibody increase: {(vaccine_trial_df['antibody_titer_day28'].mean() / vaccine_trial_df['antibody_titer_day0'].mean()):.1f}x")
Copied!

💡 Pro Tip: Use ignore_index=True to maintain clean row numbering when concatenating!

Learning Checkpoint
Why do we use ignore_index=True when concatenating DataFrames?
To ignore any errors in the index
Not quite. ignore_index=True doesn't ignore errors, it has a different purpose.
To reset the index and create continuous row numbers
Correct! ignore_index=True resets the index to create continuous row numbers (0, 1, 2...) when concatenating DataFrames, preventing duplicate or non-sequential indices.
To remove the index column entirely
Not correct. The index column is still present, it's just reset to sequential numbers.
To ignore duplicate index values
That's not its purpose. It resets the entire index rather than ignoring duplicates.

Learning Checkpoint
In PCR testing, a Ct (Cycle threshold) value of 18.2 compared to 35.8 indicates:
Less viral material in the sample
Not correct. Lower Ct values actually indicate more viral material, not less.
More viral material in the sample
Correct! In PCR testing, lower Ct values indicate more viral material. A Ct of 18.2 means the virus was detected earlier in the amplification process compared to 35.8, indicating higher viral load.
No difference in viral load
Incorrect. The difference between 18.2 and 35.8 is significant and indicates a substantial difference in viral load.
An invalid test result
Not right. Both values are within normal ranges for PCR testing and are valid results.
  • What does Ct value mean? (Lower = more virus!)
  • How would you flag urgent results?

Expected Output:

test_id patient_id pathogen ct_value result 0 PCR001 P1234 SARS-CoV-2 25.3 positive 1 PCR002 P1235 Influenza A 35.8 negative 2 PCR003 P1236 SARS-CoV-2 18.2 positive

Solution:

# Create empty PCR results DataFrame pcr_results_df = pd.DataFrame(columns=[ 'test_id', 'patient_id', 'pathogen', 'ct_value', 'result' ]) # Add first test result pcr_results_df.loc[0] = ['PCR001', 'P1234', 'SARS-CoV-2', 25.3, 'positive'] # Create batch of new results new_results = pd.DataFrame({ 'test_id': ['PCR002', 'PCR003'], 'patient_id': ['P1235', 'P1236'], 'pathogen': ['Influenza A', 'SARS-CoV-2'], 'ct_value': [35.8, 18.2], 'result': ['negative', 'positive'] }) # Combine results pcr_results_df = pd.concat([pcr_results_df, new_results], ignore_index=True) print("PCR Test Results:") print(pcr_results_df) # Bonus: Flag high viral load cases (Ct < 20) high_viral_load = pcr_results_df[pcr_results_df['ct_value'] < 20] if not high_viral_load.empty: print("\n🚨 ALERT: High viral load detected!") print(high_viral_load[['patient_id', 'pathogen', 'ct_value']])

Mission Briefing: Creating DataFrames from Nested Structures

Dealing with Complex Medical Data 🏥

Real-world medical data is rarely flat - it's nested like Russian dolls! EHR systems and genomic databases love their hierarchies.

Understanding Nested Data: The EHR Challenge

Electronic Health Records often look like this:

# Nested patient data (like from Epic or Cerner EHR systems) patient_records = [ { 'patient_id': 'MRN001', 'demographics': {'age': 45, 'gender': 'F'}, 'vitals': {'heart_rate': 72, 'temp_celsius': 37.1}, 'diagnosis': 'hypertension' }, { 'patient_id': 'MRN002', 'demographics': {'age': 67, 'gender': 'M'}, 'vitals': {'heart_rate': 88, 'temp_celsius': 37.8}, 'diagnosis': 'diabetes_type2' } ] print("Raw nested data structure:") print(patient_records[0]) # Peek at first patient
Copied!

Method 1: Manual Flattening (The Craftsman Approach) 🔨

# Flatten nested structure manually flattened_records = [] for record in patient_records: flat_record = { 'patient_id': record['patient_id'], 'age': record['demographics']['age'], 'gender': record['demographics']['gender'], 'heart_rate': record['vitals']['heart_rate'], 'temp_celsius': record['vitals']['temp_celsius'], 'diagnosis': record['diagnosis'] } flattened_records.append(flat_record) ehr_df = pd.DataFrame(flattened_records) print("\n📋 Flattened EHR DataFrame:") print(ehr_df) # Quick clinical check print("\nPatients with elevated heart rate (>80 bpm):") print(ehr_df[ehr_df['heart_rate'] > 80][['patient_id', 'heart_rate', 'diagnosis']])
Copied!
Learning Checkpoint
To access the age of the first patient in the nested structure patient_records[0], which syntax is correct?
patient_records[0]['age']
Not correct. 'age' is nested inside 'demographics', not at the top level.
patient_records[0]['demographics']['age']
Correct! To access nested dictionary values, you need to specify each level: first ['demographics'], then ['age']. This navigates through the nested structure correctly.
patient_records[0].demographics.age
Incorrect. This dot notation doesn't work with dictionaries in Python, you need to use square brackets.
patient_records['demographics']['age'][0]
Wrong. The index [0] should come first to select the patient, then navigate through the nested structure.

Method 2: The Power Tool - json_normalize! 🚀

For more complex structures, pandas has a secret weapon:

# Import the heavy machinery from pandas import json_normalize # Complex lab results with multiple nesting levels complex_patient_data = [ { 'patient_id': 'LAB001', 'test_date': '2024-03-15', 'blood_work': { 'cbc': {'wbc': 7.2, 'rbc': 4.8, 'platelets': 250}, 'chemistry': {'glucose': 95, 'creatinine': 0.9} } }, { 'patient_id': 'LAB002', 'test_date': '2024-03-16', 'blood_work': { 'cbc': {'wbc': 9.1, 'rbc': 4.2, 'platelets': 180}, 'chemistry': {'glucose': 125, 'creatinine': 1.2} } } ] # Magic happens here! ✨ lab_results_df = json_normalize(complex_patient_data, sep='_') print("\n🔬 Auto-flattened lab results:") print(lab_results_df) # Check for abnormal values print("\n⚠️ Flagging abnormal results:") if (lab_results_df['blood_work_chemistry_glucose'] > 100).any(): print("- Elevated glucose detected!") if (lab_results_df['blood_work_chemistry_creatinine'] > 1.1).any(): print("- Kidney function may need monitoring!")
Copied!

💡 Pro Tip: The sep='_' parameter creates column names like 'blood_work_cbc_wbc' - much cleaner than 'blood_work.cbc.wbc'!

Learning Checkpoint
After using json_normalize(complex_patient_data, sep='_'), how would you access the glucose value for patient LAB001?
lab_results_df['glucose'][0]
Not correct. The column name would include the full path from the nested structure.
lab_results_df['blood_work']['chemistry']['glucose'][0]
Incorrect. json_normalize flattens the structure, so you don't use nested access anymore.
lab_results_df['blood_work_chemistry_glucose'][0]
Correct! json_normalize with sep='_' creates flattened column names like 'blood_work_chemistry_glucose'. You access values using standard DataFrame indexing with these new column names.
lab_results_df.loc[0, 'chemistry.glucose']
Wrong. The column name would use underscores (_) not dots (.) as specified by sep='_'.

🌟 Real-World Connection: Epic and Cerner, the two largest EHR providers, export data in nested JSON formats. Hospitals use json_normalize daily to create analytics dashboards!

Clinical Context 🏥

Learning Checkpoint
A patient with TMB score of 12.3 compared to 8.5 would likely:
Have worse prognosis overall
Not necessarily. Higher TMB doesn't directly correlate with worse prognosis.
Be a better candidate for immunotherapy
Correct! Higher TMB (Tumor Mutational Burden) indicates more mutations, which often correlates with better response to immunotherapy treatments like checkpoint inhibitors.
Require lower doses of chemotherapy
Incorrect. TMB doesn't determine chemotherapy dosing.
Have fewer genetic mutations
Wrong. A higher TMB score indicates more mutations, not fewer.
  • VAF (Variant Allele Frequency): How much of the tumor has this mutation
  • TMB (Tumor Mutational Burden): Higher = better immunotherapy response
  • Driver mutations: The genetic changes causing cancer

Expected Output:

sample_id age cancer_type driver_mutation vaf tmb_score 0 NGS001 52 breast BRCA1_c.5266dup 0.42 8.5 1 NGS002 61 lung EGFR_L858R 0.38 12.3

Solution:

# Flatten the nested genomic data flattened_genomic = [] for profile in genomic_profiles: flat_profile = { 'sample_id': profile['sample_id'], 'age': profile['patient_info']['age'], 'cancer_type': profile['patient_info']['cancer_type'], 'driver_mutation': profile['mutations']['driver'], 'vaf': profile['mutations']['vaf'], 'tmb_score': profile['tmb_score'] } flattened_genomic.append(flat_profile) genomic_df = pd.DataFrame(flattened_genomic) print("Genomic Profile Report:") print(genomic_df) # Clinical interpretation print("\n🎯 Treatment Recommendations:") for idx, patient in genomic_df.iterrows(): if 'EGFR' in patient['driver_mutation']: print(f"Sample {patient['sample_id']}: Consider EGFR inhibitors (e.g., osimertinib)") elif 'BRCA' in patient['driver_mutation']: print(f"Sample {patient['sample_id']}: Consider PARP inhibitors (e.g., olaparib)") if patient['tmb_score'] > 10: print(f"Sample {patient['sample_id']}: High TMB - good candidate for immunotherapy!")

Learning Checkpoint
Which DataFrame creation method is BEST for combining data from multiple laboratory instruments?
Dictionary method with nested keys
Not ideal. This would create complex nested structures rather than combining data cleanly.
Creating an empty DataFrame and adding rows
While possible, this is less efficient for combining multiple sources simultaneously.
List of dictionaries from separate sources
Correct! List of dictionaries is ideal for combining data from multiple sources, as each instrument can provide its data as a dictionary, which are then combined into a list and converted to a DataFrame.
Using json_normalize on flat data
json_normalize is for nested data, not for combining flat data from multiple sources.
  1. Always validate your data - Use .info() and .describe() liberally
  2. Choose the right method - Dictionaries for structured data, lists for separate sources

  4. Master nesting - Real medical data is rarely flat!
