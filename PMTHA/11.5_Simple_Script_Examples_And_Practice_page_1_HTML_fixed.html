Learning Checkpoint
Which of the following is NOT a professional element of a production-ready shell script?
A) Clear shebang line (#!/bin/bash)
The shebang line tells the system which interpreter to use.
Incorrect. The shebang line is essential for production scripts as it ensures the correct interpreter is used.
B) Using single-letter variable names for brevity
Short variable names save typing time.
Correct! Single-letter variable names make scripts hard to understand and maintain. Professional scripts use descriptive variable names like 'user_count' instead of 'c'.
C) Descriptive header comments
Comments explaining the script's purpose and usage.
Incorrect. Descriptive header comments are crucial for documentation and help others understand your script's purpose.
D) Error handling
Code to handle unexpected situations gracefully.
Incorrect. Error handling is vital for production scripts to ensure they fail gracefully and provide useful feedback.

#!/bin/bash # Script: system_info_report.sh # Purpose: Your friendly neighborhood system monitor echo "=================================" echo "🏥 System Health Report 🏥" echo "Generated: $(date)" echo "Hostname: $(hostname)" echo "================================="
Copied!

Checking CPU Performance

# Check CPU usage echo -e "\n--- 🧠 CPU Information ---" cpu_count=$(nproc) cpu_load=$(uptime | awk -F'load average:' '{print $2}') echo "CPU Cores: $cpu_count" echo "Load Average: $cpu_load" # Fun interpretation of load average load_1min=$(echo $cpu_load | cut -d',' -f1) if (( $(echo "$load_1min < 1.0" | bc -l) )); then echo "Status: 😎 CPU is relaxed and happy!" elif (( $(echo "$load_1min < $cpu_count" | bc -l) )); then echo "Status: 💪 CPU is working but managing well" else echo "Status: CPU is working overtime!" fi
Copied!
Learning Checkpoint
If a system has 4 CPU cores and a 1-minute load average of 6.2, what status message would the script display?
A) 😎 CPU is relaxed and happy!
The load is below 1.0
Incorrect. This status only appears when load average is less than 1.0. With a load of 6.2, the CPU is definitely not relaxed!
B) 💪 CPU is working but managing well
The load is between 1.0 and the CPU count
Incorrect. This status appears when load is between 1.0 and the CPU count (4). A load of 6.2 exceeds the number of cores.
C) CPU is working overtime!
The load exceeds the number of CPU cores
Correct! With 4 cores and a load of 6.2, the CPU is definitely working overtime. This means processes are waiting in queue for CPU time.
D) The script would produce an error
The comparison would fail
Incorrect. The script uses bc for floating-point comparisons, so it would handle 6.2 correctly without errors.

Memory Usage Analysis

# Memory usage analysis echo -e "\n--- 💾 Memory Usage ---" total_mem=$(free -h | grep '^Mem:' | awk '{print $2}') used_mem=$(free -h | grep '^Mem:' | awk '{print $3}') free_mem=$(free -h | grep '^Mem:' | awk '{print $4}') echo "Total Memory: $total_mem" echo "Used Memory: $used_mem" echo "Free Memory: $free_mem" # Calculate percentage mem_percent=$(free | grep Mem | awk '{print int($3/$2 * 100)}') echo "Memory Usage: ${mem_percent}%" # Memory health indicator if [ $mem_percent -lt 60 ]; then echo "Status: ✅ Plenty of memory available" elif [ $mem_percent -lt 80 ]; then echo "Status: ⚠️ Memory usage moderate" else echo "Status: High memory usage - investigation needed!" fi
Copied!

Disk Space Monitoring

# Disk usage for critical partitions echo -e "\n--- Disk Usage ---" echo "Checking critical partitions..." df -h / /home /var 2>/dev/null | grep -v '^Filesystem' | while read line do partition=$(echo $line | awk '{print $6}') usage=$(echo $line | awk '{print $5}') available=$(echo $line | awk '{print $4}') # Remove % sign for comparison usage_num=${usage%\%} # Visual indicator if [ $usage_num -lt 70 ]; then status="✅" elif [ $usage_num -lt 85 ]; then status="⚠️" else status="🚨" fi echo "$status $partition: $usage used, $available available" done
Copied!

Lab Exercise: Enhanced System Reporter

Time to level up! Let's extend the system information script to include a warning system.

#!/bin/bash # Script: enhanced_system_report.sh # Task: Add threshold checking echo "=== 🏥 Enhanced System Health Report 🏥 ===" echo "Date: $(date)" echo "===========================================" # Memory check with threshold echo -e "\n--- 💾 Memory Analysis ---" mem_percent=$(free | grep Mem | awk '{print int($3/$2 * 100)}') echo "Memory Usage: ${mem_percent}%" # YOUR TASK: Add if statement to check if memory usage > 80% if [ $mem_percent -gt 80 ]; then echo "⚠️ WARNING: High memory usage detected!" echo " Recommendation: Check for memory-hungry processes" else echo "✓ Memory usage is within normal range" fi # CPU load check echo -e "\n--- 🧠 CPU Load Analysis ---" cpu_count=$(nproc) load_1min=$(uptime | awk -F'load average:' '{print $2}' | cut -d',' -f1 | xargs) # Remove decimal for comparison load_int=${load_1min%.*} # Warn if load exceeds CPU count if [ ${load_int:-0} -ge $cpu_count ]; then echo "⚠️ WARNING: High CPU load detected!" echo " Current load: $load_1min (CPU cores: $cpu_count)" fi # Disk space check echo -e "\n--- Disk Space Analysis ---" for partition in / /home do df $partition &>/dev/null || continue usage=$(df $partition | tail -1 | awk '{print int($5)}') echo "$partition usage: ${usage}%" if [ $usage -gt 85 ]; then echo "⚠️ WARNING: Low disk space on $partition!" echo " Recommendation: Clean up old logs or temporary files" fi done
Copied!
Learning Checkpoint
In the enhanced system report script, what disk usage percentage triggers a warning?
A) Greater than 70%
The threshold is set to 70%
Incorrect. Looking at the disk space check code, the condition is `if [ $usage -gt 85 ]`, which means greater than 85%.
B) Greater than 80%
The threshold is set to 80%
Incorrect. The disk warning uses 85% as the threshold, not 80%. The 80% threshold is used for memory warnings.
C) Greater than 85%
The threshold is set to 85%
Correct! The script checks `if [ $usage -gt 85 ]`, triggering a warning when disk usage exceeds 85%.
D) Greater than 90%
The threshold is set to 90%
Incorrect. The script uses 85% as the threshold for disk space warnings, giving admins time to act before space runs critically low.
Learning Checkpoint
On a system with 8 CPU cores, which of the following 1-minute load averages would trigger the CPU warning in the enhanced script?
A) 7.5

Incorrect. The script truncates decimals, so 7.5 becomes 7. The condition checks if load >= CPU count (8), and 7 is not >= 8.
B) 8.0
Load average of 8.0
Correct! A load of 8.0 truncates to 8, which equals the CPU count, triggering the warning (load >= cores).
C) 7.9
Load average of 7.9
Incorrect. The script truncates 7.9 to 7, which is less than 8 cores, so no warning is triggered.
D) Both B and C
Both 8.0 and 7.9 would trigger the warning
Incorrect. Only B (8.0) would trigger the warning. C (7.9) truncates to 7, which is less than 8 cores.
