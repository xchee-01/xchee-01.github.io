Check Your Understanding: Medical Data Types
Which R data type would be MOST appropriate for storing patient blood types (A+, B-, O+, etc.)?
A) numeric
Numeric data type for blood types
Not quite. Numeric types are for numbers, not categorical data like blood types.
B) logical
Logical data type for blood types
Incorrect. Logical types only store TRUE/FALSE values, not multiple categories.
C) factor
Factor data type for blood types
Correct! Factors are ideal for categorical data like blood types. They store distinct categories and can have ordered levels if needed.
D) integer
Integer data type for blood types
Not correct. Integers are for whole numbers, not categorical data like blood types.

Factor Levels Question
Given this code:
severity <- factor(c("Mild", "Severe", "Moderate"), levels = c("Mild", "Moderate", "Severe"))
What will levels(severity) return?
A) "Mild" "Severe" "Moderate"
Returns data in original order
Not correct. levels() returns the defined levels, not the data order.
B) "Mild" "Moderate" "Severe"
Returns levels as specified
Correct! The levels parameter defines the order, not the data order. levels() returns these in the order specified.
C) "Moderate" "Mild" "Severe"
Returns alphabetical order
Incorrect. The levels are explicitly defined, not alphabetical.
D) Error: levels don't match data
Produces an error
Wrong. R doesn't require the levels to match the data order.

BMI Categorization Challenge
A patient has a BMI of 29.8. Using the cut() function with breaks at 0, 18.5, 25, 30, and 40, which category will they fall into?
A) Normal
BMI 29.8 is in Normal range
Not correct. Normal range is 18.5-25, and 29.8 is above this range.
B) Overweight
BMI 29.8 is in Overweight range
Correct! The value 29.8 falls between 25 and 30, placing it in the Overweight category.
C) Obese
BMI 29.8 is in Obese range
Incorrect. Obese range starts at 30, and 29.8 is just below this threshold.
D) None - it's on the boundary
Boundary value causes issue
Wrong. cut() handles all values within the breaks properly. 29.8 clearly falls in the 25-30 range.

Adding New Test Results (New Columns)

# Start with basic patient data patient_cohort <- data.frame( patient_id = c("COH001", "COH002", "COH003"), baseline_glucose = c(105, 118, 132) ) # Lab sent follow-up results! patient_cohort$followup_glucose <- c(98, 109, 125) # Calculate improvement patient_cohort$glucose_change <- patient_cohort$followup_glucose - patient_cohort$baseline_glucose print(patient_cohort) # Everyone improved!

Adding Columns Question
Which syntax correctly adds a new column 'treatment' to the data frame 'patient_cohort'?
A) patient_cohort[treatment] <- c("A", "B", "A")
Using bracket notation without quotes
Incorrect. Column names need quotes when using bracket notation: patient_cohort["treatment"]
B) patient_cohort$treatment <- c("A", "B", "A")
Using $ notation
Correct! Use $ notation to add new columns. This is the most common and straightforward approach.
C) patient_cohort <- treatment(c("A", "B", "A"))
Using treatment function
Wrong. This would overwrite the entire data frame, not add a column.
D) add_column(patient_cohort, treatment = c("A", "B", "A"))
Using add_column function
Not quite. add_column is from the tibble package, not base R, and requires assignment.

Row Binding Challenge
What happens if you try to rbind() two data frames with different column names?
A) R automatically matches columns by position
Positional matching occurs
Wrong. rbind requires matching column names, not just positions.
B) R adds the row with NA values for missing columns
Missing columns filled with NA
Incorrect. rbind doesn't automatically handle missing columns.
C) R gives an error about mismatched column names
Error occurs
Correct! rbind requires matching column names. You'll get an error like "names do not match previous names".
D) R creates new columns for the mismatched names
New columns are created
Not correct. rbind doesn't create new columns automatically.

Correcting Data Errors

# Lab correction: Patient 2's follow-up was 112 patient_cohort[2, "followup_glucose"] <- 112 # Recalculate glucose change patient_cohort[2, "glucose_change"] <- patient_cohort[2, "followup_glucose"] - patient_cohort[2, "baseline_glucose"] # Add clinical interpretation patient_cohort$improved <- patient_cohort$glucose_change < 0 print(patient_cohort)

Data Modification Question
After running this code:
df[3, "value"] <- 50
Which statement is TRUE?
A) Only row 3 is modified
All of row 3 changes
Not precise. Only the specific cell is modified, not the entire row.
B) The entire "value" column becomes 50
Whole column is set to 50
Wrong. This notation targets a specific cell, not the entire column.
C) A new column "value" is created if it doesn't exist
New column creation
Partially true, but the main effect is setting a specific cell value.
D) Row 3, column "value" is set to 50
Specific cell is modified
Correct! This notation targets a specific cell at row 3, column "value".

Comprehensive Understanding Check
Which operation would you use to find all diabetic patients over 50 in a data frame called 'patients'?
A) patients$diabetic == TRUE & patients$age > 50
Logical expression only
This creates a logical vector but doesn't select the rows.
B) patients[patients$diabetic == TRUE & patients$age > 50, ]
Row indexing with logical condition
Correct! This uses proper logical indexing to select rows meeting both conditions.
C) filter(patients, diabetic = TRUE, age > 50)
Using filter function
filter() is from dplyr (not base R) and uses == not = for comparison.
D) subset(patients, diabetic & age > 50)
Using subset function
Close, but should use == TRUE for clarity: subset(patients, diabetic == TRUE & age > 50)
