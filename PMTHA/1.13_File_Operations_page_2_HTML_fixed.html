Reads the file content
A
The 'w' mode is for writing, not reading.
Not quite. The 'w' mode is for writing, not reading. To read a file, you would use 'r' mode.
Creates a new file or overwrites existing content
B
Opens file for writing, creating it if it doesn't exist.
Correct! The 'w' mode creates a new file if it doesn't exist, or completely overwrites the existing file content.
Appends to the end of the file
C
Appending requires 'a' mode, not 'w'.

Chapter 6: Appending to Medical Records

Because Patient Histories Grow Over Time!

The append mode ('a') is like adding pages to a patient's chart without removing the old ones. It's perfect for maintaining medical histories!

📚 Building Living Documents

# Creating an evolving patient record from datetime import datetime # Add a new entry to patient history with open('patient_history.txt', 'a') as file: timestamp = datetime.now().strftime("%Y-%m-%d %H:%M") file.write(f"\n--- Entry: {timestamp} ---\n") file.write("Chief Complaint: Persistent cough\n") file.write("Action: Prescribed antibiotics\n")

Learning Checkpoint
📋 When should you use append mode ('a') instead of write mode ('w')?
When creating a new file
A
Both modes can create new files.
Not the best answer. Both 'w' and 'a' modes can create new files if they don't exist. The key difference is what happens to existing content.
When you want to add content without erasing existing data
B
Append mode preserves existing content.
Correct! Append mode ('a') adds new content to the end of an existing file without deleting the current content.
When reading file content
C
Reading requires 'r' mode.
Incorrect. To read file content, you would use 'r' mode. Append mode ('a') is for writing.
When working with binary files
D
Binary files use 'ab' for append.
Not specific to append mode. For binary files, you would use 'ab' for append or 'wb' for write.

Chapter 7: Processing Large Medical Data Files

Big Data, Bigger Impact!

🧬 The Challenge: Genomic Data

Imagine trying to load a 200GB genome file into memory... 💥 Computer says NO!

Instead, we process files line by line - like eating an elephant one bite at a time (please don't eat elephants 🐘).

💪 Power Technique: Line-by-Line Processing

# Analyzing a massive genomic dataset print("🧬 Genome Analyzer 3000") print("="*40) mutation_count = 0 gene_count = 0 # Simulating genome analysis (would be a real file in practice) genome_data = [ ">GENE001 BRCA1\n", "ATCGATCGATCG\n", ">GENE002 TP53 MUTATION\n", "ATCGMUTATIONATCG\n", ">GENE003 EGFR\n" ] # Process without loading entire file for line in genome_data: # In real life: with open('genome.txt') as file: if line.startswith('>'): gene_count += 1 if 'MUTATION' in line: mutation_count += 1 print(f"⚠️ Mutation detected in: {line.strip()}") print(f"\n📊 Analysis Complete:") print(f" Total Genes: {gene_count}") print(f" Mutations Found: {mutation_count}")
Copied!
Learning Checkpoint
🧬 Why is line-by-line processing better for large genomic files?
It's faster than reading the entire file
A
Speed isn't the main advantage.
Not necessarily. The main advantage isn't speed but memory efficiency.
It uses less memory by processing one line at a time
B
Only one line is kept in memory.
Correct! Line-by-line processing only keeps one line in memory at a time, allowing you to process files larger than your available RAM.
It automatically sorts the data
C
No automatic sorting occurs.
Incorrect. Line-by-line processing doesn't sort data; it processes in the order it appears in the file.
It compresses the file while reading
D
No compression happens.
False. Line-by-line processing doesn't compress files; it simply reads them sequentially.

🛡️ Error Handling for Medical Data

# Robust medical file handling def read_patient_data(filename): try: with open(filename, 'r') as file: return file.read() except FileNotFoundError: print(f"⚠️ Patient file '{filename}' not found!") print("Creating new patient record...") with open(filename, 'w') as file: file.write("New Patient Record\n") return "New Patient Record\n" except PermissionError: print("🔒 Access denied! Check your permissions.") return None # Test the robust function data = read_patient_data('patient_999.txt')
Copied!
