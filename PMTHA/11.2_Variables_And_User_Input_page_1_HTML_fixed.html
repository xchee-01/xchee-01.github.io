Shell Scripting: Variables and Command Substitution

Welcome to the exciting world of interactive Linux shell scripting! In this module, you'll master shell variables and command substitution - essential tools for creating dynamic scripts that adapt to different situations. These skills are foundational for automating bioinformatics workflows and managing computational resources in precision medicine research.

Fun Fact: The $ symbol in shell variables comes from early computing when memory was so precious that single-character symbols were preferred. It's been with us since the 1970s!

11.2.1. Variables: Creation, Usage, and Best Practices

Variables are labeled containers that store information your scripts can use. In bioinformatics and healthcare IT, we use them to store file paths, sample IDs, configuration settings, and analysis parameters.

Creating Variables

# No spaces around the equals sign! sample_id="PATIENT_001" data_directory="/home/researcher/genomics_data" threads_count=8 reference_genome="hg38"
Copied!
Learning Checkpoint
Which of the following is the correct way to assign a variable in shell scripting?
name = value
With spaces around the equals sign
Not quite! Spaces around the equals sign will cause an error. Shell interprets this as a command 'name' with arguments '=' and 'value'.
name=value
No spaces around the equals sign
Correct! In shell scripting, variable assignment must have no spaces around the equals sign. This is a fundamental rule!
$name=value
With dollar sign before the name
Incorrect! The $ symbol is used to access variable values, not to assign them. Use $ only when referencing the variable.
set name=value
Using the set command
That's not right. The 'set' command has different purposes in shell scripting. Direct assignment without any command is the correct approach.

Using Variables

echo "Processing sample: $sample_id" echo "Data location: $data_directory" echo "Using $threads_count CPU threads" echo "Reference: $reference_genome"

Variable Naming Best Practices

Good variable names are crucial for maintainable scripts, especially in research environments where code may be shared among team members.

# Good names (descriptive and lowercase) input_fastq="/data/raw/sample_001.fastq" output_directory="/results/aligned" quality_threshold=30 # Avoid these patterns x="data" # Too vague! INPUT_FILE="/data/file" # Uppercase reserved for environment vars output-dir="/results" # Hyphens not allowed 1st_file="data.txt" # Cannot start with number

11.2.2. Command Substitution and System Information

Command substitution allows you to capture the output of commands and use them in your scripts. This is essential for dynamic script behavior and system monitoring in research computing environments.

Basic Command Substitution

# Capture command output using $(...) current_date=$(date +%Y-%m-%d) current_user=$(whoami) system_load=$(uptime | awk '{print $10}') available_memory=$(free -h | grep Mem | awk '{print $7}') echo "Analysis date: $current_date" echo "Running as user: $current_user" echo "System load: $system_load" echo "Available memory: $available_memory"
Copied!
Learning Checkpoint
What does current_date=$(date +%Y-%m-%d) do?
Executes date command and stores output
Runs the date command and assigns its output to current_date
Correct! The $(...) syntax executes the command inside and captures its output into the variable.
Stores the text "date +%Y-%m-%d"
Assigns the literal command text to the variable
Not quite! The $(...) syntax executes the command, it doesn't store it as text.
Creates an alias for the date command
Makes current_date an alias
Incorrect! This creates a variable with the command's output, not an alias.
Schedules the date command to run
Sets up a scheduled task
That's not right. Command substitution executes immediately and captures the output.

11.2.3. Advanced Variable Techniques

Master advanced variable manipulation techniques for sophisticated shell scripting in bioinformatics and data processing workflows.

Default Values and Parameter Expansion

# Use default if variable is unset or empty input_file=${INPUT_FILE:-"/data/default_sample.fastq"} threads=${THREADS:-8} output_format=${FORMAT:-"BAM"} # Assign default and set variable reference=${REFERENCE:="/genomes/hg38.fa"} echo "Processing with $threads threads" echo "Output format: $output_format"
Copied!
Learning Checkpoint
What's the difference between ${var:-default} and ${var:=default}?
:- uses default, := assigns default
:- only substitutes, := also sets the variable
Excellent! :- provides a default value for that use only, while := assigns the default to the variable for future use too.
No difference
They work the same way
Not quite! There's an important difference in whether they modify the variable.
:- is for strings, := for numbers
They handle different data types
Incorrect! Both work with any value type. The difference is in assignment behavior.
:= is faster
Performance optimization
That's not the difference. They have different behaviors regarding variable assignment.

String Operations

# String length sequence="ATCGATCGATCG" echo "Sequence length: ${#sequence}" # Substring extraction sample_name="PATIENT_001_TUMOR_RNA" echo "Patient ID: ${sample_name:0:11}" # PATIENT_001 echo "Sample type: ${sample_name##*_}" # RNA # Path manipulation fastq_file="/data/raw/sample_001_R1.fastq.gz" echo "Directory: ${fastq_file%/*}" # /data/raw echo "Filename: ${fastq_file##*/}" # sample_001_R1.fastq.gz echo "Without extension: ${fastq_file%.fastq.gz}" # /data/raw/sample_001_R1 # Pattern replacement filename="sample_001_raw.bam" echo "Processed file: ${filename/raw/processed}" # sample_001_processed.bam
Copied!

Case Conversion

# Convert case for standardization sample_type="tumor" echo "Uppercase: ${sample_type^^}" # TUMOR echo "Capitalize: ${sample_type^}" # Tumor # Useful for file naming conventions organism="homo_sapiens" echo "Species code: ${organism:0:1}${organism:5:1}" # hs

11.2.4. Environment Variables and System Integration

Environment variables provide system-wide configuration and are essential for managing research computing environments, especially in HPC clusters and containerized workflows.

Accessing Environment Variables

# Common environment variables echo "Current user: $USER" echo "Home directory: $HOME" echo "Current path: $PWD" echo "System PATH: $PATH" echo "Shell: $SHELL" echo "Process ID: $$" echo "Parent PID: $PPID"
Copied!

Exporting Variables

# Export variables for child processes export ANALYSIS_DIR="/projects/genomics/current" export REFERENCE_GENOME="/refs/hg38/genome.fa" export THREADS=16 export SINGULARITY_BINDPATH="/data,/scratch" # Check if variable is exported declare -p ANALYSIS_DIR
Copied!
Learning Checkpoint
What does the special variable $$ represent?
Current process ID
The PID of the running shell script
Correct! $$ gives you the process ID of the current shell or script, useful for creating unique temporary files.
Last command's exit status
The return code of the previous command
Not quite! That would be $?. $$ is for the process ID.
Number of arguments
Count of script parameters
Incorrect! That would be $#. $$ gives the process ID.
Script name
The name of the current script
That's not right. Script name is $0. $$ is the process ID.

Quick Reference Guide

# Variable Assignment var="value" # Basic assignment var=$(command) # Command substitution var=`command` # Backticks (older syntax) # Variable Access echo $var # Simple usage echo ${var} # Safer, prevents ambiguity echo "${var}" # Preserves spaces and special chars # Default Values ${var:-default} # Use default if var is unset/empty ${var:=default} # Use default AND assign to var ${var:?error_message} # Exit with error if unset ${var:+alternate} # Use alternate if var IS set # String Operations ${#var} # Length of string ${var:offset:length} # Substring extraction ${var#pattern} # Remove shortest match from start ${var##pattern} # Remove longest match from start ${var%pattern} # Remove shortest match from end ${var%%pattern} # Remove longest match from end ${var/old/new} # Replace first occurrence ${var//old/new} # Replace all occurrences ${var^} # Capitalize first letter ${var^^} # Convert to uppercase ${var,} # First letter to lowercase ${var,,} # Convert to lowercase # Special Variables $0 # Script name $1, $2, ... $9 # Positional parameters $# # Number of arguments $@ # All arguments (array-like) $* # All arguments (single string) $$ # Current process ID $! # PID of last background process $? # Exit status of last command $- # Current shell options
Copied!
