Mission Briefing: Automated Backup Script

Time for a scary story: "The Day the Database Disappeared!" 👻 (Every sysadmin's nightmare). Data loss prevention is like wearing a seatbelt - you hope you never need it, but you'll be incredibly grateful when you do!

The Art of Digital Insurance

A good backup script does more than just copy files - it's your time machine for data! It verifies the backup succeeded, manages old backups to save space, and logs everything for that inevitable audit.

Learning Checkpoint
Quick Check: What are the key features of a good backup script?
Only copies files
Basic file copying without verification or management.
Not quite. A good backup script must do more than just copy files.
Copies files, verifies success, manages storage, and logs operations
Comprehensive backup with all essential features.
Correct! A comprehensive backup script must handle verification, storage management, and logging in addition to copying files.
Just compresses files
Only handles file compression.
Compression is just one aspect. A complete backup solution needs verification and management features.
Only creates timestamps
Focuses only on timing information.
Timestamps are important, but a backup script needs to actually copy and verify data.
#!/bin/bash # Script: backup_important_dirs.sh # Purpose: Your data's guardian angel # Configuration variables BACKUP_DIR="/backup/daily" SOURCE_DIRS="/etc /home /var/www" TIMESTAMP=$(date +%Y%m%d_%H%M%S) RETENTION_DAYS=7 echo "Automated Backup System Starting..." echo "Backup ID: BACKUP_${TIMESTAMP}"
Copied!
Learning Checkpoint
Understanding Timestamps: What format will the date command date +%Y%m%d_%H%M%S produce?
2024-01-15_14:30:45
Hyphenated date format with colons.
Not quite. This format uses hyphens and colons which aren't in the format string.
20240115_143045
Continuous numeric format with underscore separator.
Correct! %Y=year(4 digits), %m=month(2 digits), %d=day(2 digits), %H=hour(24hr), %M=minute, %S=second.
15/01/2024_14:30:45
European date format with slashes.
Incorrect. The format doesn't include slashes and the order is YYYYMMDD, not DD/MM/YYYY.
Jan-15-2024_14:30:45
Month name format.
Wrong. %m produces numeric month (01-12), not month names.

Learning Checkpoint
Security Check: What does chmod 700 mean for the backup directory?
Everyone can read, write, and execute
Full permissions for all users.
No, that would be chmod 777. 700 is much more restrictive.
Only owner has full access; group and others have no access
Exclusive access for the owner only.
Correct! chmod 700 = rwx------ (owner has read/write/execute, group and others have no permissions).
Owner can read only
Minimal permissions for owner.
That would be chmod 400. 700 gives the owner full permissions.
Group members can write to the directory
Group write access enabled.
No, the middle 0 in 700 means group has no permissions at all.

Smart Backup Logic

# Function to calculate directory size get_dir_size() { du -sh "$1" 2>/dev/null | cut -f1 } # Backup each directory echo -e "\nStarting backup process..." backup_count=0 failed_count=0 for dir in $SOURCE_DIRS do if [ -d "$dir" ]; then dir_name=$(basename "$dir") backup_file="$BACKUP_DIR/${dir_name}_${TIMESTAMP}.tar.gz" echo -e "\n📦 Backing up: $dir" dir_size=$(get_dir_size "$dir") echo " Size: $dir_size" echo " Destination: $backup_file" # Create compressed backup echo -n " Progress: Creating archive" tar -czf "$backup_file" "$dir" 2>/dev/null & tar_pid=$! # Progress indicator while kill -0 $tar_pid 2>/dev/null; do echo -n "." sleep 1 done wait $tar_pid tar_exit=$? if [ $tar_exit -eq 0 ]; then echo " ✅ Done!" backup_size=$(du -h "$backup_file" | cut -f1) echo " Compressed size: $backup_size" echo "[$(date)] SUCCESS: Backed up $dir" >> "$LOG_FILE" ((backup_count++)) else echo " ❌ Failed!" echo "[$(date)] FAILED: Could not backup $dir" >> "$LOG_FILE" ((failed_count++)) fi fi done
Copied!
Learning Checkpoint

Incorrect interpretation of tar flags.
Not correct. These are not the right meanings of the tar flags.
c=create, z=gzip compression, f=filename follows
Standard tar archive creation flags.
Correct! c=create archive, z=compress with gzip, f=specify filename.
c=compress, z=zip, f=force
Common misconception about tar flags.
Incorrect. The c flag means create, not compress.
c=check, z=zone, f=format
Random interpretation of flags.
These meanings are completely incorrect for tar flags.
Learning Checkpoint

The exit status of the last command
Exit code of previous command.
That's $?, not $!. Different special variable.
The PID of the last background process
Process ID of most recent background job.
Correct! $! contains the process ID of the most recently launched background job.
The current shell's PID
Process ID of the running shell.
That's $$, not $!. Different special variable.
The number of background jobs

No, $! gives the PID of the last background job, not a count.

Intelligent Cleanup System

# Clean up old backups echo -e "\n🧹 Performing backup housekeeping..." echo "Policy: Removing backups older than $RETENTION_DAYS days" old_backup_count=0 find "$BACKUP_DIR" -name "*.tar.gz" -mtime +$RETENTION_DAYS -type f | while read old_backup do backup_date=$(stat -c %y "$old_backup" | cut -d' ' -f1) echo "🗑️ Removing old backup from $backup_date" rm "$old_backup" ((old_backup_count++)) done # Final summary echo -e "\n📊 Backup Summary Report" echo "=======================" echo "✅ Successful backups: $backup_count" echo "❌ Failed backups: $failed_count" echo "💾 Current backup storage: $(du -sh $BACKUP_DIR | cut -f1)"
Copied!
Learning Checkpoint
Find Command: What does -mtime +7 in the find command mean?
Files modified exactly 7 days ago
Exact match for 7 days.
That would be -mtime 7 (without the plus sign).
Files modified within the last 7 days
Recent files from the past week.
That would be -mtime -7 (with a minus sign).
Files modified more than 7 days ago
Older files beyond 7 days.
Correct! -mtime +7 finds files modified more than 7 days ago; -7 would be within 7 days.
Files modified 7 minutes ago
Time measured in minutes.
-mtime measures in days, not minutes. For minutes, use -mmin.

Lab Exercise: Backup Verification Script

A backup is only as good as your ability to restore it! Let's create a companion script that verifies backups are valid.

#!/bin/bash # Script: verify_backups.sh BACKUP_DIR="/backup/daily" REQUIRED_DIRS="etc home var" TODAY=$(date +%Y%m%d) echo "=== 🔍 Backup Verification Report 🔍 ===" echo "Checking today's backups..." verified_count=0 missing_count=0 corrupted_count=0 for dir in $REQUIRED_DIRS do echo -e "\n📋 Checking backup for: /$dir" # Find today's backup backup_found=$(find "$BACKUP_DIR" -name "${dir}_${TODAY}*.tar.gz" -type f | head -1) if [ -n "$backup_found" ]; then echo "✓ Backup found: $(basename $backup_found)" # Test archive integrity echo -n " Integrity check: " if tar -tzf "$backup_found" >/dev/null 2>&1; then echo "✅ PASSED" file_count=$(tar -tzf "$backup_found" 2>/dev/null | wc -l) echo " Files in archive: $file_count" ((verified_count++)) else echo "❌ FAILED - Archive is corrupted!" ((corrupted_count++)) fi else echo "❌ No backup found for today!" ((missing_count++)) fi done # Summary echo -e "\n📊 Verification Summary" echo "=====================" echo "✅ Verified backups: $verified_count" echo "❌ Missing backups: $missing_count" echo "Corrupted backups: $corrupted_count"
Copied!
Learning Checkpoint
Archive Testing: What does tar -tzf do?
Creates a new tar file with compression
Archive creation operation.
That would be -czf. The 't' flag is for testing/listing, not creating.
Tests archive integrity and lists contents
Non-destructive archive verification.
Correct! t=test/list contents, z=gzip compressed, f=file; this combination tests and lists without extracting.
Extracts files from archive
File extraction operation.
That would be -xzf. The 't' flag lists without extracting.
Adds files to existing archive
Archive append operation.
That would be -rzf. The 't' flag is for testing, not modifying.

User Account Management Script

Managing user accounts is like being the bouncer at an exclusive Linux nightclub - you need to know who's allowed in, what they can access, and when to revoke their VIP pass! 🚪

Professional User Creation

#!/bin/bash # Script: user_account_manager.sh # Purpose: Automated HR department # Color functions print_success() { echo -e "\033[0;32m✓ $1\033[0m"; } print_error() { echo -e "\033[0;31m✗ $1\033[0m"; } print_info() { echo -e "\033[0;36mℹ️ $1\033[0m"; } # Generate secure password generate_password() { local password=$(cat /dev/urandom | tr -dc 'a-zA-Z0-9!@#$%' | fold -w 12 | head -n 1) echo "$password" } # Create user account function create_user_account() { local username=$1 local fullname=$2 local department=$3 echo -e "\n🧑 Creating account for: $fullname" # Check if user exists if id "$username" &>/dev/null; then print_error "User $username already exists!" return 1 fi # Create user useradd -m -s /bin/bash -c "$fullname - $department" "$username" if [ $? -eq 0 ]; then print_success "User account created" # Set password temp_password=$(generate_password) echo "$username:$temp_password" | chpasswd chage -d 0 "$username" # Create directories for dir in Documents Downloads Projects .ssh; do mkdir -p "/home/$username/$dir" done chown -R "$username:$username" "/home/$username" chmod 700 "/home/$username/.ssh" # Account summary echo "┌─────────────────────────────────────┐" echo "│ 📋 Account Creation Summary │" echo "├─────────────────────────────────────┤" echo "│ Username: $username" echo "│ Temp Password: $temp_password" echo "│ Status: Must change password @ login" echo "└─────────────────────────────────────┘" fi }

Learning Checkpoint
Security: In the password generation, what does /dev/urandom provide?
User random selections
User-provided randomness.
No, /dev/urandom is a system device, not user input.
Pseudo-random data suitable for most purposes
Cryptographically secure randomness.
Correct! /dev/urandom provides cryptographically secure pseudo-random data suitable for password generation.
Previously used passwords
Password history.
/dev/urandom generates new random data, not old passwords.
Dictionary words
Word-based passwords.
/dev/urandom provides raw random bytes, not words.
