Basic Conditional Logic in Linux

Welcome to decision-making in Linux shell scripting! Shell scripts need to evaluate conditions and execute different code paths - the foundation of intelligent automation.

Understanding the if Statement

The if statement is your primary tool for implementing decision points in shell scripts.

Basic Syntax:

if [ condition ]; then echo "Condition is true" fi
Copied!

Pro Tip: The square brackets [ ] are shorthand for the test command. Try which [ in your terminal!

Quick Check
What do the square brackets [ ] represent in a bash if statement?
A) Array notation
Used for defining arrays in bash
Not quite. While brackets are used for arrays in bash, in the context of an if statement, they serve a different purpose.
B) Shorthand for the test command
A convenient way to write test conditions
Correct! The square brackets are actually a command (try which [) that's a synonym for the test command. Both [ -f file ] and test -f file are equivalent.
C) Optional syntax
Can be omitted if desired
Incorrect. The brackets (or an equivalent like test) are required for condition evaluation in bash if statements.
D) String concatenation
Used to join strings together
No, brackets don't perform string concatenation in bash. They're specifically for condition testing.

Real-World File Check:

# Check if critical file exists if [ -f /etc/passwd ]; then echo "Password file exists - system configured" fi
Copied!
Quick Check
What does the -f flag check for in a bash conditional?
A) If the path is a directory
Checks for directory existence
Not correct. To check if a path is a directory, you would use -d instead of -f.
B) If the file is readable
Checks read permissions
That's not right. To check if a file is readable, you would use -r.
C) If the path exists and is a regular file
Verifies it's a file, not a directory or device
Correct! The -f flag returns true if the path exists AND is a regular file (not a directory, device, or other special file type).
D) If the file is empty
Checks if file has zero size
Incorrect. To check if a file is empty (zero size), you would use -s which returns true if the file exists and has size greater than zero.

Lab Exercise 1: System Health Check

Create a script checking if Apache config exists:

#!/bin/bash # Check if Apache config exists if [ -f /etc/apache2/apache2.conf ]; then echo "STATUS: Apache configuration ______" fi
Copied!

🤔 Fill the blank to indicate file found.

#!/bin/bash # Check if Apache config exists if [ -f /etc/apache2/apache2.conf ]; then echo "STATUS: Apache configuration found" fi
Copied!

Adding else Clause

Handle both true AND false conditions:

if [ condition ]; then echo "Primary path" else echo "Alternative path" fi
Copied!

Service Monitoring Example:

if systemctl is-active --quiet nginx; then echo "Nginx running ✅" else echo "WARNING: Nginx not running ⚠️" sudo systemctl start nginx fi
Copied!
Quick Check
In the service monitoring example, when does the sudo systemctl start nginx command execute?
A) When nginx is already running
Executed in the primary condition path
No, when nginx is already running, the script only prints "Nginx running ✅" and doesn't attempt to start it.
B) When nginx is not running
Executed in the else block
Correct! The command executes in the else block, which runs when nginx is NOT active. This is a common pattern for auto-recovery scripts.
C) Always, regardless of nginx status
Runs every time the script executes
Incorrect. The command is inside the else block, so it only runs when the condition is false (nginx not running).
D) Never, it's just an example
The code is not functional
Wrong. This is functional code that would execute when nginx is not running, attempting to start the service.

Numeric Comparisons

Bash needs special operators for numbers:

Operator Meaning
-eq equal to
-ne not equal
-gt greater than
-lt less than
-ge greater or equal
-le less or equal
Quick Check
Which operator would you use to check if a variable is less than 10?
A) -eq
Equal to comparison
No, -eq checks for equality, not less than.
B) -lt
Less than comparison
Correct! -lt stands for "less than" and is the proper operator for checking if a number is less than another.
C) -le
Less than or equal to
Close, but -le means "less than or equal to", which would also match when the value equals 10.
D) -gt
Greater than comparison
Incorrect. -gt means "greater than", which is the opposite of what you want.

Disk Usage Check:

disk_usage=$(df -h / | awk 'NR==2 {print $5}' | sed 's/%//') if [ $disk_usage -gt 80 ]; then echo "ALERT: Disk usage critical at ${disk_usage}%" else echo "✅ Disk usage healthy at ${disk_usage}%" fi
Copied!
Quick Check
In the disk usage check, what threshold triggers the critical alert?
A) When disk usage is exactly 80%
Only at the exact threshold
Not quite. The -gt operator means "greater than", so 80% exactly would not trigger the alert.
B) When disk usage is less than 80%
Below the threshold
Incorrect. Less than 80% would be the healthy state, not the critical state.
C) When disk usage is greater than 80%
Above the threshold
Correct! The condition [ $disk_usage -gt 80 ] is true when disk usage is greater than 80%, triggering the critical alert.
D) When disk usage is 80% or more
At or above the threshold
Close, but not correct. To include 80%, you would need -ge (greater than or equal to), not -gt.

Lab Exercise 2: Process Monitor

Monitor Apache process count:

#!/bin/bash process_count=$(ps aux | grep -c '[a]pache2') threshold=50 if [ $process_count ____ $threshold ]; then echo "⚠️ WARNING: High process count: $process_count" ____ echo "✅ Processes normal: $process_count" fi
Copied!

Answer:

#!/bin/bash process_count=$(ps aux | grep -c '[a]pache2') threshold=50 if [ $process_count -gt $threshold ]; then echo "⚠️ WARNING: High process count: $process_count" else echo "✅ Processes normal: $process_count" fi
Copied!

String Comparisons

Text comparison operators:

Operator Meaning
= or == strings equal
!= not equal
-z string empty
-n string not empty

⚠️ Always quote variables!

Quick Check
Which operator checks if a string variable is empty?
A) -n
Not empty check
Incorrect. -n checks if a string is NOT empty (has length greater than zero).
B) -z
Zero length check
Correct! -z checks if a string has zero length (is empty). Think of "z" for "zero length".
C) !=
Not equal comparison
No, != compares two strings for inequality, it doesn't check if a string is empty.
D) ==
Equal comparison
Not right. While you could use == "" to check for empty, -z is the dedicated operator for this purpose.

Hostname Verification:

current_host=$(hostname) if [ "$current_host" = "webserver01" ]; then echo "✅ Correct server" else echo "❌ Wrong server!" exit 1 fi
Copied!
Quick Check
Why are quotes important around "$current_host" in the comparison?
A) They make the code more readable
Just a style preference
No, quotes aren't just for readability. They serve a crucial functional purpose in bash.
B) They prevent word splitting and handle empty values correctly
Essential for proper comparison
Correct! Quotes prevent word splitting (if the variable contains spaces) and avoid syntax errors if the variable is empty. Without quotes, an empty variable would cause a syntax error.
C) They are optional in this case
Could work without them
Incorrect. While it might work in some cases, omitting quotes can lead to unexpected errors, especially with empty or space-containing values.
D) They convert the variable to uppercase
Perform case conversion
Wrong. Quotes don't change the case of variables. They preserve the variable's value exactly as it is.

Environment Check:

if [ -z "$DATABASE_URL" ]; then echo "❌ ERROR: DATABASE_URL not set" exit 1 fi
Copied!
Quick Check
What does the environment check script do when DATABASE_URL is not set?
A) Sets a default value for DATABASE_URL
Provides a fallback value
No, the script doesn't set any default value. It only checks and exits with an error.
B) Continues execution normally
Ignores the missing variable
Incorrect. The exit 1 command stops the script execution entirely.
C) Prints an error and exits with status code 1
Terminates with error status
Correct! The script prints an error message and exits with status code 1 (indicating failure). This is a common pattern for ensuring required environment variables are set.
D) Waits for user input
Prompts for the value
Wrong. The script doesn't wait for input; it immediately exits with an error status.
