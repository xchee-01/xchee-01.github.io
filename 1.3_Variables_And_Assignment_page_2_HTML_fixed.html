Part 5: Multiple Assignment – Batch Processing Lab Results

Process Multiple Values at Once

When the lab sends back a panel of results, you can store them all in one line:

# Complete Blood Count (CBC) results arrive together white_cells, red_cells, platelets = 7.5, 4.8, 250 # Vital signs taken simultaneously temp, pulse, bp_systolic, bp_diastolic = 98.6, 72, 120, 80 # Liver function panel alt, ast, bilirubin = 25, 30, 1.2

🏥 Real-World Scenario: Modern lab equipment returns dozens of values at once. Multiple assignment helps you capture them efficiently without writing repetitive code.

  • The number of variables must match the number of values
  • Values are assigned in order from left to right
  • This is particularly useful for processing batch results from lab equipment

Part 6: Variable Naming Conventions – Building Professional Code

Snake_case: Python's Preferred Style

In Python medical applications, we use snake_case (words separated by underscores):

Learning Checkpoint
Which naming style follows Python conventions for medical applications?
patient_date_of_birth
snake_case
Words separated by underscores, all lowercase
Correct! Snake_case is the Python standard. It's readable, consistent, and follows PEP 8 style guidelines used in professional medical software.
patientDateOfBirth
camelCase
First word lowercase, subsequent words capitalized
Not quite. While camelCase is common in JavaScript, Python prefers snake_case for variable names. Using consistent style helps maintain readable medical codebases.
PatientDateOfBirth
PascalCase
All words capitalized, no separators
Not for variables. PascalCase is reserved for class names in Python. Using it for variables would confuse other developers working on medical systems.
patient-date-of-birth
kebab-case
Words separated by hyphens
This won't work! Python interprets hyphens as subtraction operators. This would cause a syntax error in your medical application.

Final Challenge: Emergency Department Tracker

Create a mini emergency department tracking system:

Emergency Department Tracker Implementation
Which implementation correctly creates and updates the ED tracking variables?
Complete Implementation
ed_patient_count = 12
next_available_bed = 305
average_wait_minutes = 45.5
trauma_bay_occupied = False
on_call_physician = "Dr. Sarah Chen"

ed_patient_count = ed_patient_count + 1
current_bed_assignment = next_available_bed
next_available_bed = 306
excessive_wait = average_wait_minutes > 60
Perfect! You've correctly created all variables with appropriate types and values, properly updated counts, and implemented the wait time check.
Missing Updates
ed_patient_count = 12
next_available_bed = 305
average_wait_minutes = 45.5
trauma_bay_occupied = False
on_call_physician = "Dr. Sarah Chen"

# Forgot to update variables when new patient arrives
This creates the initial variables but doesn't update them when a new patient arrives. ED systems must track changes in real-time.
Wrong Data Types
ed_patient_count = "12"  # String instead of int
next_available_bed = 305.0  # Float instead of int
average_wait_minutes = 45  # Int instead of float
trauma_bay_occupied = "False"  # String instead of bool
Incorrect data types! Patient counts and bed numbers should be integers, wait times can have decimals (float), and occupancy status should be boolean.

Complete Solution

Emergency Department Tracker Solution:

# Emergency Department Tracker # ============================ # Initial state # ============= ed_patient_count = 12 next_available_bed = 305 average_wait_minutes = 45.5 trauma_bay_occupied = False on_call_physician = "Dr. Sarah Chen" # New patient arrives # =================== ed_patient_count = ed_patient_count + 1 current_bed_assignment = next_available_bed next_available_bed = 306 # Check wait time # =============== excessive_wait = average_wait_minutes > 60 print(f"Excessive wait warning: {excessive_wait}")
