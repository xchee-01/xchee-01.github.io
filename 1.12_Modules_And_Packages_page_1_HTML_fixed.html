Mission Briefing: Understanding Modules and Packages

What Are Modules? Your Code's Medicine Cabinet! 💊

A module is simply a Python file containing code you can reuse. Think of it as a specialized medical instrument - like a stethoscope that you can use across different patient examinations. Instead of rewriting the same diagnostic functions for every patient, you store them in a module and import them whenever needed.

# Simple module concept # File: vital_signs.py (this is a module!) def calculate_bmi(weight_kg, height_m): """Calculate Body Mass Index""" return weight_kg / (height_m ** 2) def blood_pressure_category(systolic, diastolic): """Categorize blood pressure readings""" if systolic < 120 and diastolic < 80: return "Normal" elif systolic < 130 and diastolic < 80: return "Elevated" else: return "High Blood Pressure"

What Are Packages? Your Hospital Department! 🏥

If modules are individual medical instruments, packages are entire hospital departments! A package is a collection of related modules organized in a directory structure. Just as a cardiology department contains various specialized units (ECG lab, catheterization lab, imaging), a Python package contains multiple modules working together.

# Package structure example precision_health/ __init__.py # Makes this directory a package diagnostics/ __init__.py blood_tests.py # Module for blood analysis imaging.py # Module for medical imaging genetics/ __init__.py dna_analysis.py # Module for genetic sequencing mutations.py # Module for variant detection

Lab Section 1: Creating Your First Medical Module

Let's build a practical module for calculating common medical metrics. This hands-on approach will solidify your understanding!

Step 1: Create the Module

# File: medical_calculator.py """ Medical Calculator Module A collection of functions for common medical calculations Used in precision health applications """ def calculate_bmi(weight_kg, height_m): """ Calculate Body Mass Index Args: weight_kg (float): Patient weight in kilograms height_m (float): Patient height in meters Returns: float: BMI value rounded to 1 decimal place """ bmi = weight_kg / (height_m ** 2) return round(bmi, 1) def calculate_bsa(weight_kg, height_cm): """ Calculate Body Surface Area using Mosteller formula Used for drug dosage calculations """ bsa = ((height_cm * weight_kg) / 3600) ** 0.5 return round(bsa, 2) # Module-level variables NORMAL_BODY_TEMP_C = 37.0 NORMAL_BODY_TEMP_F = 98.6
Copied!

Step 2: Import and Use the Module

# Different ways to import your module # Method 1: Import entire module import medical_calculator patient_bmi = medical_calculator.calculate_bmi(70, 1.75) print(f"Patient BMI: {patient_bmi}") # Method 2: Import specific functions from medical_calculator import calculate_bmi, calculate_bsa patient_bmi = calculate_bmi(70, 1.75) # No module prefix needed! patient_bsa = calculate_bsa(70, 175) print(f"BMI: {patient_bmi}, BSA: {patient_bsa} m²") # Method 3: Import with alias (nickname) import medical_calculator as medcalc result = medcalc.calculate_bmi(70, 1.75)
Copied!
Learning Checkpoint
Which import method would you use if you want to use the calculate_bmi function without typing the module name each time?
import medical_calculator
Import the entire module with its original name.
Not quite. With this method, you'd still need to use medical_calculator.calculate_bmi() to call the function.
from medical_calculator import calculate_bmi
Import the specific function directly.
Correct! This imports the function directly into your namespace, so you can call calculate_bmi() without the module prefix.
import medical_calculator as mc
Import the module with an alias.
With this method, you'd use mc.calculate_bmi(), which still requires a prefix (though shorter).
import calculate_bmi
Import the function directly without specifying the module.
This won't work. Python needs to know which module the function comes from. You need to use 'from medical_calculator import calculate_bmi'.

Advanced Import Techniques: Your Swiss Army Knife

The Power of `from ... import *` (Use Carefully! ⚠️)

# Imports EVERYTHING from a module from medical_calculator import * # Now you can use all functions without prefix bmi = calculate_bmi(70, 1.75) # Works! temp = NORMAL_BODY_TEMP_C # Works too!
Copied!

⚡ Warning: While convenient, import * can lead to namespace pollution - like mixing medications without labels! Use it sparingly and only with well-documented modules.

Selective Imports with Aliases

# Import specific items with custom names from medical_calculator import ( calculate_bmi as bmi_calc, calculate_bsa as body_surface_area, NORMAL_BODY_TEMP_C as NORMAL_TEMP ) # Use your custom names patient_index = bmi_calc(80, 1.80) surface = body_surface_area(80, 180)

The Magic of `__init__.py` Files 🎩

The __init__.py file transforms a directory into a Python package. It can be empty or contain initialization code:

# precision_health_toolkit/__init__.py """ Precision Health Toolkit A comprehensive package for medical data analysis """ # Package metadata __version__ = "1.0.0" __author__ = "Dr. Python" # Convenient imports from .patient_metrics.vitals import check_vital_signs from .lab_analysis.blood_work import analyze_cbc # Package-level constants CRITICAL_VALUES = { 'glucose_low': 70, 'glucose_high': 140, 'systolic_high': 140, 'diastolic_high': 90 } print("Precision Health Toolkit loaded successfully! 🏥")

Understanding Python's Module Search Path

When you import a module, Python searches for it in specific locations. Understanding this helps troubleshoot import errors!

import sys # View Python's module search path print("Python searches for modules in these locations:") for path in sys.path: print(f" - {path}") # Add custom path (useful for development) sys.path.append('/path/to/my/medical/modules') # Now you can import from the new location import custom_medical_module

You've mastered accessing and modifying Python's module search path. Remember: sys.path[0] is the first location, append() adds new paths, and sys.path contains all search locations.
Key points to remember:
  • sys.path is a list containing all directories Python searches for modules
  • The first element (index 0) is usually the current directory
  • Use append() to add new directories to the search path
  • Changes to sys.path are temporary and only last for the current session

🧠 Mental Model: Think of sys.path as Python's GPS system for finding modules - it checks each location in order until it finds what you're looking for!

Common Pitfalls and Solutions

Circular Import Problem

# file: diagnosis.py from treatment import recommend_treatment def make_diagnosis(symptoms): # diagnosis logic return diagnosis # file: treatment.py from diagnosis import make_diagnosis # Circular import! 🔄 def recommend_treatment(diagnosis): # treatment logic return treatment
Copied!

Solution: Restructure your code or use import inside functions:

# file: treatment.py def recommend_treatment(diagnosis): # Import only when needed from diagnosis import validate_diagnosis if validate_diagnosis(diagnosis): return treatment_plan
Copied!
Learning Checkpoint
What's the best way to resolve a circular import between two modules that depend on each other?
Use import * in both modules
Import everything from each module to ensure all functions are available.
This would still cause a circular import error and wouldn't solve the problem. The modules would still try to import each other infinitely.
Move imports inside functions
Import the required module inside the function where it's needed, not at the top of the file.
Correct! By moving imports inside functions, they're only executed when the function is called, breaking the circular dependency at module load time.
Rename one of the modules
Give one module a different name to avoid the conflict.
Renaming doesn't solve the circular dependency. The modules would still try to import each other regardless of their names.
Restructure into a third module
Create a third module containing shared functionality that both modules can import.
Also correct! This is often the cleanest solution - extracting common functionality into a separate module that both can depend on.

Name Conflicts

# Problematic: Two modules with same function name from patient_stats import calculate_average from lab_stats import calculate_average # Overwrites the first! # Solution 1: Use aliases from patient_stats import calculate_average as patient_avg from lab_stats import calculate_average as lab_avg # Solution 2: Import modules, not functions import patient_stats import lab_stats patient_result = patient_stats.calculate_average(data) lab_result = lab_stats.calculate_average(data)

Now it's time to put everything together! Create a simple medical analysis package with the following structure:

medical_toolkit/ __init__.py patient/ __init__.py vitals.py # Create calculate_bmi() and check_blood_pressure() lab/ __init__.py glucose.py # Create convert_glucose_units() function

Requirements:

  • The vitals.py module should contain functions for BMI calculation and blood pressure categorization
  • The glucose.py module should convert between mg/dL and mmol/L
  • Make key functions available directly from the package level

Solution:

# medical_toolkit/__init__.py """Medical Toolkit - A precision health analysis package""" __version__ = "1.0.0" # Convenient imports from .patient.vitals import calculate_bmi, check_blood_pressure from .lab.glucose import convert_glucose_units # medical_toolkit/patient/__init__.py # Empty file to make this a package # medical_toolkit/patient/vitals.py def calculate_bmi(weight_kg, height_m): """Calculate Body Mass Index""" return round(weight_kg / (height_m ** 2), 1) def check_blood_pressure(systolic, diastolic): """Categorize blood pressure""" if systolic < 120 and diastolic < 80: return "Normal" elif systolic < 130 and diastolic < 80: return "Elevated" else: return "High" # medical_toolkit/lab/__init__.py # Empty file to make this a package # medical_toolkit/lab/glucose.py def convert_glucose_units(value, from_unit="mg/dL"): """Convert glucose between mg/dL and mmol/L""" if from_unit == "mg/dL": return round(value * 0.0555, 1) # to mmol/L else: return round(value / 0.0555, 1) # to mg/dL # Usage example: import medical_toolkit bmi = medical_toolkit.calculate_bmi(70, 1.75) glucose_mmol = medical_toolkit.convert_glucose_units(126, "mg/dL")
