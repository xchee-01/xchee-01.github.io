📊 Understanding map() - Transform All Data

Exercise: Map with Lambda Functions
Complete the code to transform temperature data:
# Step 1: Simple example - Square all numbers numbers = [1, 2, 3, 4, 5] squared = list(map(lambda x: x**2, numbers)) print(f"Squared: {squared}") # Step 2: Medical application - Temperature conversion temperatures_c = [36.5, 37.2, 38.1, 37.8, 36.9] temperatures_f = list(map(lambda c: (c * 9/5) + 32, temperatures_c)) # Pretty print with labels for c, f in zip(temperatures_c, temperatures_f): print(f"{c}°C = {f:.1f}°F")

🔍 Understanding filter() - Select Specific Data

# Filter patients with fever (temperature >= 38°C) fever_patients = list(filter(lambda temp: temp >= 38, temperatures_c)) print(f"Patients with fever: {fever_patients}") # Count fever cases fever_count = len(fever_patients) total_patients = len(temperatures_c) print(f"Fever rate: {fever_count}/{total_patients} ({fever_count/total_patients*100:.0f}%)")

📈 Understanding sorted() - Order Your Data

# Patient glucose data (name, glucose_mg/dL) patient_glucose = [ ("Alice", 95), # Normal ("Bob", 125), # Pre-diabetic ("Carol", 108), # Normal ("David", 87), # Normal ("Eve", 145) # Pre-diabetic ] # Sort by glucose level (ascending) sorted_by_glucose = sorted(patient_glucose, key=lambda x: x[1]) print("Patients by glucose level:") for name, glucose in sorted_by_glucose: status = "Normal" if glucose < 100 else "Pre-diabetic" if glucose < 126 else "Diabetic" print(f" {name}: {glucose} mg/dL ({status})")

🧪 Lab Exercise 3: Genetic Variant Filtering

🎓 Learning Objective

Use lambda functions with filter() to identify pathogenic genetic variants from a list of variant data.

Medical Context: In genetics, variants with very low frequency in the population (< 1%) are often associated with rare diseases. These are prime candidates for further investigation!

📝 Scaffolded Exercise

• APOE (0.15) - Alzheimer's risk gene
• TP53 (0.0005) - Tumor suppressor gene
• LDLR (0.08) - Cholesterol gene

Which pattern do you notice about the frequencies and disease associations?
Cancer and rare disease genes have very low frequencies
BRCA1, TP53, and CFTR all have frequencies < 0.001
Excellent observation! Genes associated with severe conditions like cancer (BRCA1, TP53) and cystic fibrosis (CFTR) have very low population frequencies because natural selection removes harmful variants.
All disease genes have similar frequencies

Not quite. Notice how APOE and LDLR (associated with common conditions) have much higher frequencies than the cancer genes.

🎯 Complete Solution

# Lab scenario: Filter genetic variants by allele frequency # Allele frequency = how common a variant is in the population # Variants with frequency < 0.01 (1%) are considered rare genetic_variants = [ ("BRCA1_v1", 0.0001), # BRCA1: Breast cancer gene ("APOE_v2", 0.15), # APOE: Alzheimer's risk gene ("TP53_v3", 0.0005), # TP53: Tumor suppressor gene ("LDLR_v4", 0.08), # LDLR: Cholesterol gene ("CFTR_v5", 0.0002) # CFTR: Cystic fibrosis gene ] # Complete solution rare_variants = list(filter(lambda variant: variant[1] < 0.01, genetic_variants)) print(f"Rare variants: {rare_variants}") # Bonus: Extract just the variant names rare_variant_names = list(map(lambda v: v[0], rare_variants)) print(f"Rare variant names: {rare_variant_names}") # Extra bonus: Create a summary report print("\n📊 Variant Analysis Report:") print(f"Total variants analyzed: {len(genetic_variants)}") print(f"Rare variants found: {len(rare_variants)}") print(f"Percentage rare: {len(rare_variants)/len(genetic_variants)*100:.0f}%") # Super bonus: Find ultra-rare variants (< 0.0001) ultra_rare = list(filter(lambda v: v[1] < 0.0001, genetic_variants)) print(f"Ultra-rare variants: {[v[0] for v in ultra_rare]}")
Copied!

🧬 Brilliant work! You've just implemented a fundamental bioinformatics operation used to identify potentially disease-causing genetic variants. This is how researchers discover new genetic causes of disease!

🎯 Common Pitfalls and Debugging

⚠️ Watch Out For These Common Mistakes:

1. Forgetting the colon
Which of these lambda function definitions is correct?
square = lambda x x**2
Missing colon syntax
This will cause a SyntaxError! Lambda functions need a colon (:) between parameters and the expression.
square = lambda x: x**2
Correct syntax with colon
Perfect! The colon separates the parameter(s) from the expression in a lambda function.
2. Trying to use statements
Why doesn't this lambda work: bad_lambda = lambda x: print(x)?
print() is a statement, not an expression
Lambda can only contain expressions that return values
Correct! Lambda functions can only contain expressions (things that evaluate to a value), not statements like print(). Use a regular function if you need statements.
print() requires parentheses
The syntax is incorrect
The parentheses are there. The issue is that print() doesn't return a value - it performs an action.
Lambda functions can't take parameters
x is not allowed
Lambda functions can definitely take parameters. The issue is with using print() inside the lambda.
3. Making lambdas too complex
When should you use a regular function instead of a lambda?
When you need parameters
Lambda can't handle multiple inputs
Lambda functions can take multiple parameters: lambda x, y: x + y
When the logic is complex or multi-line
Lambda should be simple, one-line expressions
Exactly! If your lambda is getting complex with multiple conditions or would be clearer as multiple lines, use a regular function for better readability.
When working with numbers
Lambda is only for text processing
Lambda functions work great with numbers! Example: lambda x: x**2 for squaring.

💡 Debugging Tip: If your lambda is longer than one line when written out, it's probably too complex!
