Part 6: Variable Naming Conventions – Building Professional Code

Snake_case: Python's Preferred Style

In Python medical applications, we use snake_case (words separated by underscores):

Professional Python Style
Which naming style follows Python conventions for medical applications?
✅ Professional Python style patient_date_of_birth = "1978-03-15" last_medication_time = "08:00" systolic_blood_pressure = 120 ❌ Other styles (avoid in Python) patientDateOfBirth = "1978-03-15" # camelCase PatientDateOfBirth = "1978-03-15" # PascalCase patient-date-of-birth = "1978-03-15" # kebab-case (won't work!)
snake_case
patient_date_of_birth
Words separated by underscores, all lowercase
Correct! Snake_case is the Python standard. It's readable, clear, and follows PEP 8 style guidelines used in professional medical software.
camelCase
patientDateOfBirth
First word lowercase, subsequent words capitalized
Not quite. While camelCase is popular in JavaScript, Python conventions strongly prefer snake_case for variable names.
PascalCase
PatientDateOfBirth
Every word starts with a capital letter
Not correct. PascalCase is reserved for class names in Python, not variables. Using it for variables would confuse other developers.
kebab-case
patient-date-of-birth
Words separated by hyphens
This won't even work in Python! The hyphen is interpreted as a minus sign, causing a syntax error. Stick with snake_case.

Include Units in Variable Names

A game-changing practice in medical programming:

Units in Variable Names
Which variable naming approach is safer for medical applications?
⚠️ Ambiguous - mg? g? mcg? drug_dose = 500 ✅ Crystal clear drug_dose_mg = 500 patient_weight_kg = 68.5 glucose_mmol_per_l = 7.2 waiting_time_minutes = 45
Without units
drug_dose = 500
Shorter names, units documented elsewhere
Dangerous! Without units, 500 could mean 500mg, 500mcg, or 500g. This ambiguity has caused real medical errors.
With units
drug_dose_mg = 500
Units included in the variable name
Excellent! Including units prevents dangerous confusion. Anyone reading your code instantly knows this is 500 milligrams, not micrograms or grams.
Comments only
drug_dose = 500 # mg
Units specified in comments
Better than nothing, but comments can be separated from code or overlooked. Units in the variable name are always visible.

💡 True Story: A Mars spacecraft crashed because engineers mixed up metric and imperial units. In medicine, such confusion could be fatal!

Final Challenge: Emergency Department Tracker

Create a mini emergency department tracking system:

Emergency Department Tracker Challenge
Create an ED tracking system with these requirements:
  • ED patient count (start with 12)
  • Next available bed number (305)
  • Average wait time in minutes (45.5)
  • Trauma bay occupied (True/False)
  • On-call physician name
Which code correctly implements the initial ED state?
Complete Implementation
ed_patient_count = 12 next_available_bed = 305 average_wait_minutes = 45.5 trauma_bay_occupied = False on_call_physician = "Dr. Sarah Chen"
Perfect! You've correctly used appropriate data types: integers for counts, float for wait time, boolean for occupancy status, and string for the physician name.
Incorrect Types
ed_patient_count = "12" next_available_bed = 305.0 average_wait_minutes = 45 trauma_bay_occupied = "False" on_call_physician = Dr. Sarah Chen
Several issues: patient count should be int not string, bed number should be int not float, wait time needs decimal precision, boolean should be True/False not string, and physician name needs quotes.
Poor Naming
patients = 12 bed = 305 wait = 45.5 trauma = False doc = "Dr. Sarah Chen"
While technically correct, these variable names are too vague. In medical systems, clear naming prevents confusion and errors.

Complete ED Tracker Solution

Here's the full emergency department tracking system:

# Emergency Department Tracker # =========================== # Initial state ed_patient_count = 12 next_available_bed = 305 average_wait_minutes = 45.5 trauma_bay_occupied = False on_call_physician = "Dr. Sarah Chen" # New patient arrives ed_patient_count = ed_patient_count + 1 current_bed_assignment = next_available_bed next_available_bed = 306 # Check wait time excessive_wait = average_wait_minutes > 60 print(f"Excessive wait warning: {excessive_wait}") # Display current status print(f"Current ED Status:") print(f"- Patients: {ed_patient_count}") print(f"- Next bed: {next_available_bed}") print(f"- Average wait: {average_wait_minutes} minutes") print(f"- Trauma bay in use: {trauma_bay_occupied}") print(f"- On-call physician: {on_call_physician}")
