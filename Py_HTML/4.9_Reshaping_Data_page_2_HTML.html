🧪 Lab Exercise 2: Reshaping Genomic Expression Data

🧬 Welcome to Precision Oncology Data Lab!

You're working with gene expression data from tumor samples. The oncology team needs this data in two formats:

  1. Wide format for heatmap visualization (genes as columns)
  2. Wide format with clinical data for correlation analysis

🔬 Fun Fact: The human genome has ~20,000 genes. Modern sequencing can measure all of them at once. That's a LOT of reshaping!

# Lab scenario: Gene expression data from tumor samples # Each row represents one gene measurement from one sample 🧬 gene_expression_long = pd.DataFrame({ 'sample_id': ['S001', 'S001', 'S001', 'S002', 'S002', 'S002', 'S003', 'S003', 'S003'], 'gene': ['BRCA1', 'TP53', 'EGFR', 'BRCA1', 'TP53', 'EGFR', 'BRCA1', 'TP53', 'EGFR'], 'expression_level': [2.5, 0.8, 4.2, 1.2, 3.5, 1.8, 0.5, 4.8, 2.1], 'tumor_stage': ['II', 'II', 'II', 'III', 'III', 'III', 'I', 'I', 'I'] }) # TODO: Create two transformations: # 1. Pivot to wide format for heatmap (samples as rows, genes as columns) # 2. Add tumor_stage to the wide format while maintaining gene expression values # 🎯 Challenge: Can you create a heatmap-ready matrix AND preserve clinical data? # Expected output: 3 rows × 4 columns (sample_id + 3 genes) for basic pivot
Copied!

🎯 Complete Solution

# 1. Basic pivot for heatmap visualization # Creating the expression matrix - the foundation of precision medicine! 🎨 expression_matrix = gene_expression_long.pivot( index='sample_id', # Each sample gets a row columns='gene', # Each gene gets a column values='expression_level' # Expression values fill the matrix ) print("🧬 Gene Expression Matrix (Ready for Heatmap):") print("=" * 50) print(expression_matrix) print("\n🎨 Perfect for creating those beautiful expression heatmaps!") print("Notice: BRCA1 is lowest in S003 - might indicate treatment response!") # 2. Include tumor stage information for clinical correlation # First, extract unique tumor stage for each sample tumor_stages = gene_expression_long[['sample_id', 'tumor_stage']].drop_duplicates() # Merge clinical data with expression matrix - the power of pandas! 💪 expression_with_stage = expression_matrix.merge( tumor_stages, left_index=True, right_on='sample_id' ).set_index('sample_id') # Reorder columns for clarity (clinical data first!) expression_with_stage = expression_with_stage[['tumor_stage', 'BRCA1', 'EGFR', 'TP53']] print("\n🏥 Gene Expression with Clinical Annotation:") print("=" * 50) print(expression_with_stage) print("\n🔬 Now we can correlate expression patterns with disease stage!") print("Look: Higher TP53 in earlier stages - potential biomarker? 🎯")
Copied!

🔬 Mission Briefing: Advanced Reshaping with Multiple Operations

🎪 The Grand Finale: Reshaping Gymnastics!

In real research, you rarely do just one reshape. You combine operations like a chef combines ingredients - melt here, pivot there, aggregate somewhere else. Let's tackle a complex scenario that mirrors actual clinical research workflows!

🏥 Scenario: You're analyzing a pain management study comparing physical therapy vs. medication across multiple outcome measures.

# Create complex treatment response dataset # This mimics real clinical trial data with multiple measurements! 📊 treatment_data = pd.DataFrame({ 'patient_id': ['P001', 'P001', 'P002', 'P002', 'P003', 'P003'] * 2, 'visit': ['Baseline', 'Week4', 'Baseline', 'Week4', 'Baseline', 'Week4'] * 2, 'measurement': ['Pain_Score', 'Pain_Score', 'Pain_Score', 'Pain_Score', 'Pain_Score', 'Pain_Score', 'Mobility', 'Mobility', 'Mobility', 'Mobility', 'Mobility', 'Mobility'], 'value': [8, 5, 9, 6, 7, 4, 3, 6, 2, 5, 4, 7], 'treatment': ['Physical_Therapy', 'Physical_Therapy', 'Medication', 'Medication', 'Physical_Therapy', 'Physical_Therapy'] * 2 }) print("📋 Raw Treatment Data (Long Format):") print(treatment_data.head(8)) print("\n🤯 This is realistic - messy and complex!")
Copied!
Data Format Identification
What format is the treatment_data DataFrame currently in?
Wide format
Data spread horizontally across columns.
The data has individual observations as separate rows, not spread across columns.
Long format
Each observation is a separate row.
Correct! Each measurement for each patient at each visit is a separate row, which is the characteristic of long format data.
Matrix format
Organized as a mathematical matrix.
This isn't a specialized matrix format - it's standard tabular data in long format.
Normalized format
Data in normalized database form.
While this data is normalized, the question is about wide vs. long format, not database normalization.

🎯 Complex Reshape: Creating a Treatment Comparison Matrix

# Complex reshape: Create matrix with visits as columns and measurements as rows # This is the kind of transformation that makes analysts cry tears of joy! 😂 treatment_matrix = treatment_data.pivot_table( index=['patient_id', 'treatment', 'measurement'], columns='visit', values='value', aggfunc='first' # Using 'first' because we know there are no duplicates ).reset_index() print("\n📊 Treatment Response Matrix:") print("=" * 50) print(treatment_matrix) print("\n✨ Now we can see before/after for each measure!")
Copied!
Pivot Table vs Pivot
Why do we use pivot_table() instead of pivot() for this operation?
pivot_table() is faster
Performance reasons for choosing pivot_table.
Performance isn't the main reason - both functions have similar performance characteristics.
pivot_table() allows multiple index columns
Can handle complex index structures and aggregation.
Correct! pivot_table() is more flexible and allows multiple index columns, aggregation functions, and handles duplicates, making it ideal for complex reshaping operations.
pivot() doesn't exist in pandas
Only pivot_table is available.
Both pivot() and pivot_table() exist in pandas - they serve different purposes.
pivot_table() creates prettier output
Better formatting and appearance.
The choice is based on functionality, not aesthetics.

📈 Calculate Treatment Effectiveness

# Calculate improvement scores - the moment of truth! 🎯 treatment_matrix['improvement'] = treatment_matrix['Baseline'] - treatment_matrix['Week4'] treatment_matrix['percent_improvement'] = ( treatment_matrix['improvement'] / treatment_matrix['Baseline'] * 100 ).round(1) print("\n🏆 Treatment Effectiveness Analysis:") print("=" * 50) effectiveness = treatment_matrix[['patient_id', 'treatment', 'measurement', 'percent_improvement']] print(effectiveness) print("\n💊 Medication vs 💪 Physical Therapy - Fight!") print("Spoiler: Both work, but check out P003's mobility improvement with PT!")
Copied!
Calculation Understanding
If a patient's pain score went from 8 (Baseline) to 5 (Week4), what is their percent improvement?
37.5%
(8-5)/8 * 100 = 37.5%
Correct! Improvement = (8-5)/8 * 100 = 3/8 * 100 = 37.5%. This represents a significant reduction in pain score.
62.5%
5/8 * 100 = 62.5%
This calculates the remaining pain as a percentage, not the improvement.
60%
3/5 * 100 = 60%
This uses the final value as the denominator, not the baseline value.
3%
Just the difference: 8-5 = 3
This is the absolute improvement, not the percentage improvement.

🏥 Real-World Connection: The FDA requires exactly this type of analysis for drug approval. Researchers must show improvement across multiple outcome measures, calculated from complex longitudinal data. One misplaced reshape, and your billion-dollar drug might not get approved!

🧪 Lab Exercise 3: Complex Reshaping for Clinical Dashboard

🏥 The Ultimate Challenge: Multi-Clinic Diabetes Dashboard

You're the lead data scientist for a healthcare network. The CEO wants a dashboard showing diabetes management performance across all clinics. The catch? The data is a mess, and the board meeting is tomorrow!

🎯 Your Mission: Create an executive-ready dashboard showing:

  1. Average HbA1c trends by clinic
  2. Patient volume by clinic
  3. Performance indicators (improving vs. worsening)
# Lab scenario: Multi-clinic diabetes monitoring data # This is as real as it gets - welcome to healthcare analytics! 🏥 diabetes_monitoring = pd.DataFrame({ 'clinic': ['North', 'North', 'North', 'South', 'South', 'South'] * 3, 'patient_id': ['DN001', 'DN002', 'DN003', 'DS001', 'DS002', 'DS003'] * 3, 'month': ['Jan', 'Jan', 'Jan', 'Jan', 'Jan', 'Jan', 'Feb', 'Feb', 'Feb', 'Feb', 'Feb', 'Feb', 'Mar', 'Mar', 'Mar', 'Mar', 'Mar', 'Mar'], 'hba1c': [7.2, 8.1, 6.9, 7.8, 9.2, 7.1, # January 7.0, 7.8, 6.7, 7.5, 8.9, 6.9, # February 6.8, 7.5, 6.5, 7.2, 8.5, 6.7], # March 'weight_kg': [82, 95, 78, 88, 102, 73, 81, 93, 77, 87, 100, 72, 80, 91, 76, 86, 98, 71] }) # TODO: Create a dashboard view that shows: # 1. Average HbA1c by clinic and month (clinics as rows, months as columns) # 2. Patient count per clinic per month # 3. Identify clinics with improving vs worsening average HbA1c trends # 🏆 Bonus: Create a single comprehensive dashboard DataFrame # 💡 Remember: Lower HbA1c = Better diabetes control!
Copied!

🤔 Strategic Thinking:

Clinical Metrics
Why track HbA1c by month in diabetes management?
To fill up more spreadsheet cells
Create more comprehensive-looking reports.
The purpose is clinical, not aesthetic - tracking trends is essential for diabetes management.
To identify seasonal patterns that affect diabetes control
Monitor trends and patterns in patient health over time.
Correct! Monthly tracking helps identify seasonal patterns, medication adherence issues, and treatment effectiveness over time.
Because months are easier to spell than weeks
Convenience in data entry and reporting.
The choice of timeframe is based on clinical relevance, not convenience.
To make the data look more complex
Increase the apparent sophistication of the analysis.
Healthcare analytics should be driven by clinical needs, not complexity for its own sake.

🎯 Complete Solution

# 1. Calculate average HbA1c by clinic and month # Creating the primary quality metric - HbA1c is the gold standard! 🥇 hba1c_summary = diabetes_monitoring.pivot_table( index='clinic', columns='month', values='hba1c', aggfunc='mean' ) # Reorder months correctly (because 'Feb' < 'Jan' alphabetically - oops!) month_order = ['Jan', 'Feb', 'Mar'] hba1c_summary = hba1c_summary[month_order] print("📊 Average HbA1c by Clinic and Month:") print("=" * 50) print(hba1c_summary.round(2)) print("\n💡 Target HbA1c < 7.0 for good control") print("North Clinic is crushing it! 🏆") # 2. Count patients per clinic per month # Volume matters - are we comparing apples to apples? 🍎 patient_counts = diabetes_monitoring.pivot_table( index='clinic', columns='month', values='patient_id', aggfunc='count' )[month_order] print("\n👥 Patient Count by Clinic and Month:") print("=" * 50) print(patient_counts) print("\n✅ Good news: Equal patient counts = fair comparison!") # 3. Calculate trends - the moment of truth! # Are we getting better or worse? 📈📉 hba1c_summary['trend'] = hba1c_summary['Mar'] - hba1c_summary['Jan'] hba1c_summary['trend_direction'] = hba1c_summary['trend'].apply( lambda x: '✅ Improving' if x < 0 else '⚠️ Worsening' ) print("\n🎯 Clinic Performance Trends:") print("=" * 50) trend_display = hba1c_summary[['Jan', 'Mar', 'trend', 'trend_direction']] print(trend_display) # Bonus: Create comprehensive executive dashboard # This is what the CEO actually wants to see! 💼 dashboard = pd.DataFrame({ 'clinic': hba1c_summary.index, 'avg_hba1c_jan': hba1c_summary['Jan'].round(2), 'avg_hba1c_mar': hba1c_summary['Mar'].round(2), 'hba1c_change': hba1c_summary['trend'].round(2), 'performance': hba1c_summary['trend_direction'], 'total_patients': patient_counts.sum(axis=1), 'quality_score': ['⭐⭐⭐⭐⭐' if t < -0.2 else '⭐⭐⭐' for t in hba1c_summary['trend']] }) print("\n🏥 Executive Dashboard - Board Ready!") print("=" * 50) print(dashboard) print("\n📢 Key Insights:") print("• North Clinic: Best performer with consistent improvement") print("• South Clinic: Needs intervention - consider sharing North's best practices") print("• Overall: 50% of clinics improving - glass half full! 🥤")
Copied!

🎉 Exceptional work! You've just created a dashboard that could:

  • Drive quality improvement initiatives
  • Justify resource allocation
  • Identify clinics for best practice sharing
  • Support grant applications for diabetes programs
