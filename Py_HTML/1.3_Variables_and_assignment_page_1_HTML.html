Welcome, future medical data scientist! 🎯 You're about to embark on an exciting journey where programming meets precision health. In this module, we'll master variables and assignment – the fundamental building blocks that power everything from electronic health records to genomic analysis tools.

Part 1: Variables – Your Medical Data Containers

Understanding the Basics First

Let's start with a simple truth: variables are just named boxes where we store information. Nothing more, nothing less! 📦

# Your first variable - it's that simple! patient_name = "Alex Rivera"
Copied!

That's it! You've just created a variable called patient_name that holds the text "Alex Rivera". The = sign doesn't mean "equals" in math terms – it means "put this value into this box."

The Medical Connection

Now let's see why this matters in healthcare:

# Storing a blood glucose reading glucose_level = 126 # Recording a patient's temperature body_temp = 98.6 # Tracking medication status medication_taken = True
Copied!
🎯 Quick Practice
Before moving on, try creating a variable for a patient's heart rate. Which of these is correct?
heart_rate = 72
Creates a variable named heart_rate with the value 72
Perfect! You've created a variable that stores a patient's heart rate. The variable name is descriptive and follows Python naming conventions.
heart rate = 72
Uses a space to make it more readable
Variable names can't contain spaces. Use underscores instead: heart_rate
72 = heart_rate
Puts the value first for clarity
The variable name must come first, followed by =, then the value. The correct order is: heart_rate = 72
heart-rate = 72
Uses a hyphen for compound words
Hyphens aren't allowed in variable names. Use underscores: heart_rate

Part 2: Naming Your Variables Like a Pro

Python's Simple Rules

Think of variable names like patient ID bands – they need to be clear and follow certain rules:

  1. Start with a letter or underscore (not a number)
  2. Use only letters, numbers, and underscores
  3. Case matters (Patient ≠ patient)
# ✅ Good variable names patient_age = 45 blood_type = "O+" is_allergic_to_penicillin = True # ❌ Won't work - starts with number 2nd_dose = 500 # Error! # ❌ Won't work - has spaces patient name = "John" # Error!
Copied!

💡 Pro Tip: In healthcare, clarity saves lives! Always choose descriptive names:

  • temp ❌ (Temperature? Temporary?)
  • body_temperature_celsius ✅ (Crystal clear!)
🧪 Mini Lab: Fix the Variable Names
Which of the following fixes the variable naming errors correctly?
# Can you spot and fix the naming errors? patient-id = "12345" # Problem: dash not allowed 1st_visit = "2024-01-15" # Problem: starts with number bp reading = 120 # Problem: space not allowed
Correct Fix
patient_id = "12345"
first_visit = "2024-01-15"
bp_reading = 120
Excellent! You've fixed all the naming issues: replaced dashes and spaces with underscores, and avoided starting with a number.
Partial Fix
patientId = "12345"
visit1 = "2024-01-15"
bpReading = 120
While these are valid, Python convention prefers snake_case (with underscores) over camelCase for variable names.
Still Has Errors
patient.id = "12345"
_1st_visit = "2024-01-15"
bp-reading = 120
Dots and dashes aren't allowed in variable names. Also, starting with underscore and number (_1) is not conventional.

Part 3: Data Types in Clinical Context

The Fantastic Four of Medical Data

Python automatically figures out what type of data you're storing (smart, right?). Here are the four types you'll use constantly:

1. Strings (text) - For names, IDs, and descriptions

patient_mrn = "MRN2024-001" diagnosis = "Type 2 Diabetes" medication_name = "Metformin"
Copied!

2. Integers (whole numbers) - For counts and discrete values

patient_age = 67 pills_per_day = 3 hospital_room = 204
Copied!

3. Floats (decimals) - For precise measurements

weight_kg = 72.5 hemoglobin_a1c = 6.8 drug_dose_mg = 12.5
Copied!

4. Booleans (True/False) - For yes/no conditions

is_pregnant = False has_insurance = True needs_interpreter = False
Copied!
🤔 Think About It
Why might storing weight as an integer (72 instead of 72.5) be dangerous in pediatric medicine?
Medication Dosing Accuracy
Even 0.5 kg difference can significantly affect pediatric medication dosing calculations
Exactly right! In pediatrics, medication dosing is often calculated per kilogram of body weight. A 0.5 kg difference could mean under- or over-dosing a child, which could be dangerous.
Storage Space
Integers take up less computer memory than floats
While this is technically true, the tiny memory savings aren't worth the risk of inaccurate medical calculations.
Easier Calculations
Whole numbers are easier to work with in calculations
Python handles decimal calculations just as easily as whole numbers. Medical accuracy is far more important than computational simplicity.

Part 4: Variable Reassignment – Tracking Patient Changes

The Power of Updates

In healthcare, nothing stays constant. Variables can be updated to reflect changes:

# Morning vital signs oxygen_saturation = 95 print(f"Morning O2: {oxygen_saturation}%") # After oxygen therapy oxygen_saturation = 98 print(f"After treatment: {oxygen_saturation}%")
Copied!

💭 Medical Metaphor: Think of reassignment like updating a patient's chart. The chart (variable name) stays the same, but the information (value) gets updated.

Progressive Monitoring Example

# ICU patient monitoring over time patient_status = "critical" print(f"Admission: {patient_status}") # After 2 hours of treatment patient_status = "serious" print(f"2 hours later: {patient_status}") # After successful intervention patient_status = "stable" print(f"Current status: {patient_status}")
Copied!
🎯 Self-Check
What will this code output?
pain_level = 8 pain_level = pain_level - 3 print(pain_level) # What number appears?
5
The pain level is reduced from 8 to 5
Correct! The code takes the current pain_level (8), subtracts 3, and stores the result (5) back in pain_level. This is how we track patient improvement over time.
8
The original value remains unchanged
The second line updates pain_level with a new value (8 - 3 = 5). Variables can be reassigned.
3
It shows the amount reduced
The code prints the new pain_level value after subtraction, not the amount subtracted. 8 - 3 = 5.
Error
You can't use a variable on both sides of =
It's perfectly valid to use a variable in its own reassignment. Python evaluates the right side first, then assigns the result.
