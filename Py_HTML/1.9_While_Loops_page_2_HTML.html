Section 4: Infinite Loops - Continuous Monitoring Systems

Real medical devices often run forever (well, until someone turns them off). Let's learn how to do this safely!

Creating Safe Infinite Loops

# ECG Monitor Simulation import random print("🫀 ECG Monitor Starting...") reading_count = 0 while True: # This runs forever! # Simulate heart rhythm rhythm = random.choice(["Normal", "Normal", "Normal", "Irregular"]) if rhythm == "Irregular": print("⚠️ ALERT: Irregular heartbeat detected!") print("Notifying medical staff...") break # Exit the infinite loop print(f"Reading {reading_count}: {rhythm} rhythm") reading_count += 1 # Demo limit (remove in real system) if reading_count >= 10: print("Demo complete - shutting down") break

Learning Checkpoint
💡 Pro Tip: Real medical devices have multiple exit conditions. Which of the following would NOT be a good exit condition for a medical monitoring system?
Critical patient events
The system should alert medical staff when critical events occur.
Actually, this IS a good exit condition. Medical devices should definitely stop and alert when critical patient events occur.
Low battery
The device should safely shut down before battery failure.
This IS a good exit condition. Medical devices must shut down safely before battery failure to prevent data loss or unsafe conditions.
Random time intervals
The device should stop monitoring at random times.
Correct! Random stopping would be terrible for medical monitoring. Medical devices should only stop for specific, predictable reasons like manual override, critical events, or maintenance needs.
System errors
The device should stop safely when errors are detected.
This IS a good exit condition. Medical devices should fail safely when system errors occur, alerting staff to the malfunction.

Challenge: Build a ventilator monitoring system that:

  1. Runs continuously
  2. Monitors oxygen saturation (O2 sat)
  3. Alerts if O2 sat drops below 90%
  4. Has a maximum of 15 checks for this demo
Coding Challenge
Which loop structure would be best for creating a ventilator monitor that runs continuously but has multiple exit conditions?
# Normal O2 saturation is 95-100% import random o2_saturation = 97 check_count = 0 print("🫁 Ventilator Monitor Active") # TODO: Create an infinite loop that: # - Adds random variation to o2_saturation (-2 to +1) # - Prints current O2 saturation # - Breaks with alert if < 90% # - Breaks after 15 checks (demo limit) # Your code here:
for loop with range(15)
Use a for loop that runs exactly 15 times.
A for loop would run exactly 15 times, but wouldn't exit early if O2 drops below 90%. We need a loop that can exit based on conditions.
while True with break statements
Use an infinite while loop with multiple break conditions.
Perfect! An infinite while loop with break statements allows us to exit for different reasons: low O2 saturation OR reaching the demo limit.
while o2_saturation >= 90
Use a while loop that continues while O2 is normal.
This would exit when O2 drops, but wouldn't handle the 15-check demo limit. We need multiple exit conditions.
Recursive function calls
Create a function that calls itself repeatedly.
Recursion would be unnecessarily complex and could cause stack overflow. A simple while loop is the best approach for continuous monitoring.

💡 Hint: Random variation

Use random.uniform(-2, 1) to get a random float between -2 and +1

Solution: ICU Ventilator Monitor

import random o2_saturation = 97 check_count = 0 print("🫁 Ventilator Monitor Active") while True: # Add realistic variation variation = random.uniform(-2, 1) o2_saturation += variation # Ensure realistic bounds o2_saturation = max(85, min(100, o2_saturation)) print(f"Check {check_count + 1}: O2 Sat = {o2_saturation:.1f}%") # Critical alert if o2_saturation < 90: print("🚨 CRITICAL: Low oxygen saturation!") print("Increasing oxygen flow...") break check_count += 1 # Demo limit if check_count >= 15: print("✅ Monitoring session complete - all readings normal") break

Section 5: Putting It All Together

Let's build a complete patient monitoring system!

# Comprehensive Patient Monitor import random import time class PatientMonitor: def __init__(self, patient_name): self.patient_name = patient_name self.vital_signs = { 'heart_rate': 75, 'blood_pressure': 120, 'temperature': 98.6, 'oxygen': 98 } def monitor_patient(self): print(f"📊 Monitoring {self.patient_name}") checks = 0 alerts = 0 while True: # Update vitals with random variations self.vital_signs['heart_rate'] += random.randint(-5, 5) self.vital_signs['oxygen'] += random.uniform(-1, 0.5) # Check for critical conditions if self.vital_signs['heart_rate'] > 100: print(f"⚠️ Tachycardia alert! HR: {self.vital_signs['heart_rate']}") alerts += 1 if self.vital_signs['oxygen'] < 92: print(f"🚨 Low O2 saturation: {self.vital_signs['oxygen']:.1f}%") alerts += 1 # Emergency break if alerts >= 3: print("🚨 Multiple alerts - Calling medical team!") break # Normal reading if alerts == 0: print(f"✅ Vitals normal at check {checks + 1}") checks += 1 # Demo limit if checks >= 10: print("Monitoring session complete") break # Reset alerts for next check alerts = 0 # Test the monitor monitor = PatientMonitor("John Doe") monitor.monitor_patient()

Key Takeaways

While Loop Essentials
Which of the following is NOT an essential practice when using while loops?
Always change the condition variable
Prevent infinite loops by updating the loop condition.
This IS essential! Failing to update the condition variable is the most common cause of infinite loops.
Use break for emergency exits
Immediate exit when critical conditions occur.
This IS essential! Break statements provide emergency exits for critical conditions in medical monitoring.
Always use nested while loops
Put while loops inside other while loops for complexity.
Correct! This is NOT essential. In fact, nested while loops can make code harder to understand and debug. Use them only when necessary.
Have exit strategies for infinite loops
Always have multiple ways to exit an infinite loop.
This IS essential! Every infinite loop must have clear exit conditions to prevent system lockup.
Medical Programming Best Practices
In medical programming, what should be your TOP priority when designing monitoring loops?
Safety First
Always include emergency breaks for critical values.
Absolutely correct! Patient safety is paramount. Always design your loops to detect and respond to critical conditions immediately.
Speed optimization
Make the loop run as fast as possible.
While efficiency is important, safety always comes first in medical programming. A fast but unsafe monitor is dangerous.
Memory usage
Minimize memory consumption above all else.
Memory efficiency is good, but patient safety is the top priority. Never compromise safety for memory optimization.
Code simplicity
Keep the code as simple as possible.
Simplicity is valuable, but safety is paramount. Sometimes safety features require additional complexity.

Pattern 1 for continuous ECG monitoring
Use the first pattern for heart rhythm monitoring.
Pattern 1 stops when safe, but ECG needs continuous monitoring. Pattern 3 would be better for continuous monitoring.
Pattern 2 for emergency response
Use the index pattern for critical alerts.
Pattern 2 is for processing lists, not emergency response. Pattern 1 or 3 would be better for emergencies.
