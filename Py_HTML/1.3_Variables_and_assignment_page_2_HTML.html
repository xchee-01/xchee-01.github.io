Part 5: Multiple Assignment – Batch Processing Lab Results

Process Multiple Values at Once

When the lab sends back a panel of results, you can store them all in one line:

# Complete Blood Count (CBC) results arrive together white_cells, red_cells, platelets = 7.5, 4.8, 250 # Vital signs taken simultaneously temp, pulse, bp_systolic, bp_diastolic = 98.6, 72, 120, 80 # Liver function panel alt, ast, bilirubin = 25, 30, 1.2

🏥 Real-World Scenario: Modern lab equipment returns dozens of values at once. Multiple assignment helps you capture them efficiently without writing repetitive code.

What should replace the blanks to correctly assign the triage data?
45, 2, 7, True
Numeric values and boolean for insurance status
Correct! Use the appropriate data types: integers for age, priority, and pain scale; boolean for insurance status.

All values as strings
Not quite. While this would work, it's better to use numeric types for numbers and boolean for True/False values to enable proper calculations and comparisons.

This creates a list, not multiple assignments. The values should be separated by commas, not enclosed in brackets.

Part 6: Variable Naming Conventions – Building Professional Code

Snake_case: Python's Preferred Style

In Python medical applications, we use snake_case (words separated by underscores):

# ✅ Professional Python style patient_date_of_birth = "1978-03-15" last_medication_time = "08:00" systolic_blood_pressure = 120 # ❌ Other styles (avoid in Python) patientDateOfBirth = "1978-03-15" # camelCase PatientDateOfBirth = "1978-03-15" # PascalCase patient-date-of-birth = "1978-03-15" # kebab-case (won't work!)
Copied!
Learning Checkpoint
Which variable name follows Python's preferred naming convention for storing a patient's heart rate?
heartRate
camelCase style
This is camelCase, commonly used in JavaScript but not Python's preferred style.
HeartRate
PascalCase style
This is PascalCase, typically reserved for class names in Python, not variables.
heart_rate
snake_case style
Correct! Python uses snake_case convention, where words are separated by underscores and all letters are lowercase.
heart-rate
kebab-case style
This is kebab-case. Python would interpret the hyphen as subtraction, causing a syntax error!

Include Units in Variable Names

A game-changing practice in medical programming:

# ⚠️ Ambiguous - mg? g? mcg? drug_dose = 500 # ✅ Crystal clear drug_dose_mg = 500 patient_weight_kg = 68.5 glucose_mmol_per_l = 7.2 waiting_time_minutes = 45
Copied!

💡 True Story: A Mars spacecraft crashed because engineers mixed up metric and imperial units. In medicine, such confusion could be fatal!

Learning Checkpoint
Which variable name is BEST for storing a patient's temperature to avoid confusion?
temperature = 37.5
Generic name without units
This is ambiguous - is it Celsius or Fahrenheit? Including units prevents dangerous misunderstandings.
temp = 37.5
Abbreviated name without units
Even more ambiguous - abbreviated and no units specified. This could lead to critical errors.
body_temp_celsius = 37.5
Descriptive name with units
Correct! Including the unit (celsius) in the variable name prevents dangerous misunderstandings between Celsius and Fahrenheit scales.
patient_temperature_c = 37.5
Abbreviated unit designation
While better than no unit, 'c' could be confused. Full unit names like 'celsius' are clearer.

Putting It All Together: Build a Patient Intake System

Let's combine everything we've learned into a real-world example:

# Patient Intake System # ==================== # Basic Information patient_id = "PID-2024-1847" patient_first_name = "Maria" patient_last_name = "González" patient_age_years = 52 # Vital Signs (taken together) temp_celsius, pulse_bpm, resp_rate = 37.2, 78, 16 bp_systolic_mmhg, bp_diastolic_mmhg = 128, 82 # Medical History has_diabetes = True has_hypertension = True current_medications_count = 3 # Lab Results fasting_glucose_mg_dl = 142 hba1c_percentage = 7.2 # Calculate risk score (preview of next lesson!) diabetes_controlled = fasting_glucose_mg_dl < 130 print(f"Diabetes controlled: {diabetes_controlled}") # Update after intervention fasting_glucose_mg_dl = 118 diabetes_controlled = fasting_glucose_mg_dl < 130 print(f"After treatment - Diabetes controlled: {diabetes_controlled}")
Copied!

After a new patient arrives and is assigned a bed, what should next_available_bed equal?
305
Remains unchanged
No, the patient was assigned to bed 305, so the next available bed needs to be updated.
306
Incremented by one
Correct! The patient gets bed 305, so the next available bed should be incremented to 306.
304
Decremented by one
Incorrect. Bed numbers increase as patients are assigned, not decrease.
"306"
String value "306"
The bed number should remain an integer for calculations, not be converted to a string.

# Emergency Department Tracker # ============================ # Initial state ed_patient_count = 12 next_available_bed = 305 average_wait_minutes = 45.5 trauma_bay_occupied = False on_call_physician = "Dr. Sarah Chen" # New patient arrives ed_patient_count = ed_patient_count + 1 current_bed_assignment = next_available_bed next_available_bed = 306 # Check wait time excessive_wait = average_wait_minutes > 60 print(f"Excessive wait warning: {excessive_wait}")
