🔬 Part 4: Multi-dimensional Arrays - The Matrix Has You!

🏥 2D Arrays: Patient × Measurement Tables

Real medical data often comes in tables. Let's work with a patient monitoring matrix:

# ICU vital signs: 5 patients × 4 measurements # Columns: [Temperature(°C), Heart Rate, BP Systolic, O2 Sat(%)] vital_signs = np.array([ [37.2, 78, 120, 98], # Patient 1 [38.1, 92, 135, 96], # Patient 2 [36.8, 71, 118, 99], # Patient 3 [37.5, 85, 128, 97], # Patient 4 [38.9, 101, 142, 94] # Patient 5 (fever + tachycardia!) ]) # Access specific values patient2_hr = vital_signs[1, 1] # Row 1, Column 1 print(f"❤️ Patient 2 HR: {patient2_hr} bpm") # Get all temperatures (column 0) all_temps = vital_signs[:, 0] print(f"🌡️ All temperatures: {all_temps}") # Get all vitals for Patient 5 patient5_vitals = vital_signs[4, :] # or just vital_signs[4] print(f"🚨 Patient 5 vitals: {patient5_vitals}")
Copied!
Learning Checkpoint
To access Patient 3's oxygen saturation level from the vital_signs array, which indexing would you use?
vital_signs[3, 3]
Access row 3, column 3
Remember that Python uses 0-based indexing! Patient 3 is at index 2, not 3.
vital_signs[2, 3]
Access row 2, column 3
Correct! Patient 3 is at index 2 (0-based), and O2 Sat is column 3 (index 3).
vital_signs[3, 2]
Access row 3, column 2
This would access Patient 4's BP Systolic, not Patient 3's O2 Sat.
vital_signs[2, 4]
Access row 2, column 4
Column 4 doesn't exist - we only have columns 0-3!
Learning Checkpoint
Which syntax correctly extracts all heart rate values (column 1) from all patients?
vital_signs[1, :]
Get row 1, all columns
This gets all vitals for Patient 2 (row 1), not heart rates for all patients.
vital_signs[:, 1]
Get all rows, column 1
Perfect! The colon (:) selects all rows, and 1 selects column 1 (heart rate).
vital_signs[1]
Get index 1
This gets the entire row 1 (Patient 2's data), not column 1.
vital_signs[:][1]
Get all rows, then index 1
This returns row 1, not column 1. Use comma notation for 2D indexing.

[5, 88, 130, 37.0, 97], # Patient D [8, 118, 90, 36.5, 92], # Patient E - Low BP + O2! [2, 78, 125, 37.1, 98], # Patient F [6, 95, 135, 38.2, 96], # Patient G [10, 130, 170, 37.8, 93] # Patient H - Severe pain! ]) # TODO: Find patients needing immediate attention # Criteria: Pain >= 8 OR O2 < 95 OR BP_Sys > 160 OR BP_Sys < 100 # TODO: Calculate triage priority score # Score = Pain + (10 if HR>120) + (10 if O2<95) + (5 if fever) # TODO: Sort patients by priority score (highest first)

Learning Checkpoint
Which boolean expression correctly identifies critical patients based on the given criteria?
(ed_data[:,0] >= 8) & (ed_data[:,4] < 95) & (ed_data[:,2] > 160) & (ed_data[:,2] < 100)
Using AND operators
This requires ALL conditions to be true. We need ANY condition (OR).
(ed_data[:,0] >= 8) | (ed_data[:,4] < 95) | (ed_data[:,2] > 160) | (ed_data[:,2] < 100)
Using OR operators
Perfect! The | (OR) operator means a patient is critical if ANY condition is met.
(ed_data[0,:] >= 8) | (ed_data[4,:] < 95) | (ed_data[2,:] > 160) | (ed_data[2,:] < 100)
Selecting wrong dimension
This checks specific patients instead of specific measurements for all patients.
(ed_data[:,0] >= 8) + (ed_data[:,4] < 95) + (ed_data[:,2] > 160) + (ed_data[:,2] < 100)
Using addition
This counts conditions but doesn't create a boolean mask. Use | for OR.

🚑 Emergency Triage Solution

# Extract relevant columns pain = ed_data[:, 0] hr = ed_data[:, 1] bp_sys = ed_data[:, 2] temp = ed_data[:, 3] o2_sat = ed_data[:, 4] # Find critical patients critical_mask = (pain >= 8) | (o2_sat < 95) | (bp_sys > 160) | (bp_sys < 100) critical_patients = np.where(critical_mask)[0] print(f"🚨 Critical patients: {['ABCDEFGH'[i] for i in critical_patients]}") # Calculate priority scores priority_scores = pain.copy() priority_scores += 10 * (hr > 120) priority_scores += 10 * (o2_sat < 95) priority_scores += 5 * (temp > 37.5) # Sort by priority sorted_indices = np.argsort(priority_scores)[::-1] # Descending order patient_letters = ['A', 'B', 'C', 'D', 'E', 'F', 'G', 'H'] print("\n🏥 Triage Order:") for rank, idx in enumerate(sorted_indices): print(f"{rank+1}. Patient {patient_letters[idx]}: " f"Priority Score = {priority_scores[idx]}") # Show critical values for top 3 print("\n📋 Top 3 Critical Details:") for idx in sorted_indices[:3]: print(f"Patient {patient_letters[idx]}: " f"Pain={pain[idx]}, HR={hr[idx]}, " f"BP={bp_sys[idx]}, O2={o2_sat[idx]}%")

✏️ Direct Element Updates

In real clinical settings, data gets updated constantly. NumPy lets you modify arrays in-place:

# Medication doses that need adjustment (mg) med_doses = np.array([100.0, 150.0, 200.0, 175.0, 125.0]) print(f"💊 Original doses: {med_doses}") # Doctor orders dose reduction for Patient 3 med_doses[2] = 180.0 print(f"✏️ After adjustment: {med_doses}") # Reduce all doses by 10% for kidney function med_doses *= 0.9 print(f"🏥 After renal adjustment: {med_doses}")

🎯 Conditional Updates

Update multiple values based on conditions:

# Lab values with some errors lab_values = np.array([5.2, -1.0, 8.7, 999.0, 6.3, 0.0, 7.1]) # Fix obvious errors lab_values[lab_values < 0] = np.nan # Mark as missing lab_values[lab_values > 100] = np.nan # Outliers print(f"🔧 Cleaned values: {lab_values}") # Impute missing values with median valid_mask = ~np.isnan(lab_values) median_value = np.median(lab_values[valid_mask]) lab_values[np.isnan(lab_values)] = median_value print(f"📊 After imputation: {lab_values}")
Copied!

🔬 Part 6: Performance & Best Practices

⚡ Views vs Copies: Memory Matters

Understanding when NumPy creates views vs copies is crucial for both performance and data integrity:

# Original patient data original = np.array([120, 125, 130, 128, 135]) # Creating a view (shares memory) view = original[1:4] view[0] = 999 # This changes the original! print(f"⚠️ Original after view change: {original}") # Creating a copy (independent) original = np.array([120, 125, 130, 128, 135]) # Reset copy = original[1:4].copy() copy[0] = 999 # Original is safe print(f"✅ Original after copy change: {original}")
Copied!
Learning Checkpoint
Which operation creates a view (not a copy) of the original array?
arr[2:5]
Basic slicing
Correct! Basic slicing creates a view that shares memory with the original.
arr[[2, 3, 4]]
Fancy indexing
Fancy indexing with a list always creates a copy.
arr[arr > 100]
Boolean indexing
Boolean indexing creates a copy, not a view.
arr.reshape(5, 1)
Reshaping
Also correct! reshape() usually returns a view when possible.

🏃 Vectorization: Speed Matters

# Slow way (avoid this!) import time data = np.random.rand(1000000) start = time.time() result_slow = [] for x in data: if x > 0.5: result_slow.append(x * 2) slow_time = time.time() - start # Fast way (use this!) start = time.time() result_fast = data[data > 0.5] * 2 fast_time = time.time() - start print(f"🐌 Loop time: {slow_time:.4f}s") print(f"🚀 Vectorized time: {fast_time:.4f}s") print(f"⚡ Speedup: {slow_time/fast_time:.0f}x faster!")
Copied!
