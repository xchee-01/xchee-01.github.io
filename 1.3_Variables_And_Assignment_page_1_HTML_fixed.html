Why Variables Matter in Medicine
Which of the following is NOT a good use of variables in medical programming?
Real-time monitoring
Update patient vitals every second
Actually, this is a GREAT use of variables! Real-time monitoring systems constantly update variables with new patient data to track vital signs and alert medical staff to changes.
Dosage calculations
Store weight for medication math
This is also an excellent use! Variables storing patient weight, age, and other factors are essential for calculating safe medication dosages.
Permanent storage
Replace hospital databases entirely
Correct! Variables are temporary storage in a program's memory. They're perfect for processing and calculations, but permanent patient records need to be saved to databases or files. Variables work WITH databases, not instead of them.
Research databases
Track thousands of patient outcomes
Variables are perfect for this! Research programs use variables to process and analyze large datasets, calculating statistics and identifying patterns in patient outcomes.

🌍 Real-World Connection: When a nurse checks your blood pressure and enters it into the computer, it becomes a variable in the hospital's Electronic Health Record (EHR) system. That single variable might trigger alerts, update charts, and inform treatment decisions - all automatically!

Mission Briefing: Variable Naming for Medical Applications

🏷️ The Life-Saving Importance of Good Names

Here's a scary thought: In 2018, a hospital's medication system had a variable named just d for dosage. A programmer thought it meant "default dose" when it actually meant "double dose." The confusion nearly led to serious overdoses before being caught!

Lesson learned: In medical programming, variable names can literally save lives. Let's make yours crystal clear!

Python's Variable Naming Rules
Which of these is a valid Python variable name for storing a patient's heart rate?
2nd_heart_rate
Starts with a number
Variable names cannot start with a number! Python would see "2" and expect a number, not a variable name. Use "second_heart_rate" instead.
heart-rate-bpm
Uses hyphens to separate words
Python interprets hyphens as subtraction! It would try to calculate "heart minus rate minus bpm". Use underscores instead: heart_rate_bpm
heart_rate_bpm
Uses underscores between words
Perfect! This follows all Python naming rules: starts with a letter, uses underscores for spaces, and is descriptive. The "bpm" suffix even clarifies the units!
heart rate bpm
Contains spaces
Variable names cannot contain spaces! Python would see three separate things. Replace spaces with underscores: heart_rate_bpm

Lab Exercise 2: Laboratory Results Management
A busy clinical lab sent these blood test results. Which variable naming approach follows best practices?

Results to store:
  • White blood cell count: 8200 cells/μL
  • Platelet count: 250000 per μL
  • Fasting glucose: 95 mg/dL
  • Creatinine level: 1.1 mg/dL
Option A
wbc = 8200
plt = 250000
glu = 95
cr = 1.1
These abbreviations are too short and unclear. In medical software, clarity is crucial for patient safety. Not everyone will know what "plt" or "cr" means!
Option B
lab_wbc_count = 8200
lab_platelet_count = 250000
lab_fasting_glucose_mg_dl = 95
lab_creatinine_level = 1.1
Outstanding! These names are clear, use the lab_ prefix for organization, and include units where helpful. Any healthcare provider could understand this code without documentation!
Option C
WhiteBloodCellCount = 8200
PlateletCount = 250000
FastingGlucose = 95
CreatinineLevel = 1.1
While descriptive, this uses CamelCase which isn't Python's convention. Python prefers snake_case (words_with_underscores). Also missing the helpful lab_ prefix!
Option D
test1 = 8200
test2 = 250000
test3 = 95
test4 = 1.1
Never use generic names like test1, test2! In a medical emergency, which test is which? This naming could literally endanger patients.

Complete Lab Results Display

# Laboratory results with clear naming lab_wbc_count = 8200 lab_platelet_count = 250000 lab_fasting_glucose_mg_dl = 95 lab_creatinine_level = 1.1 # Display lab report print("=== Laboratory Results ===") print(f"WBC: {lab_wbc_count} cells/μL") print(f"Platelets: {lab_platelet_count} per μL") print(f"Glucose: {lab_fasting_glucose_mg_dl} mg/dL") print(f"Creatinine: {lab_creatinine_level} mg/dL")
